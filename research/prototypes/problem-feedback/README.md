# Worket 问题反馈 UI 原型

这是可丢弃的 UI 设计，回答“如何让截图、问题描述与本次日志授权在紧凑面板内完成，以及中途补截图如何继续原草稿”。不调用生产服务；报告、回执与待发队列使用示例数据和内存状态，刷新会重置这些演示记录。当前编辑草稿单独存入本浏览器 IndexedDB，保留最近编辑后的 7 天，文字、所选图片文件与未提交日志选择可以跨刷新恢复。顶部“重置”会清除本地草稿。“截取 Worket 窗口”使用静态示例图，确认后才加入草稿；导出按钮只导出演示报告元数据。

运行 `npm run prototype:feedback`，打开 `http://127.0.0.1:4327/?variant=A`。

## 布局候选

| 布局 | 地址 | 取舍 |
| --- | --- | --- |
| A 单页反馈 | `/?variant=A` | 描述、截图和日志授权同屏，推荐作为首版；用户无需额外确认步骤 |
| B 情境抽屉 | `/?variant=B` | 工作详情保留在背景，反馈更贴近出错操作；可用空间更紧 |
| C 分步确认 | `/?variant=C` | 先描述，再检查发送内容；确认更集中，增加一次切换 |

底部切换器或左右方向键切换候选，输入时方向键不被拦截。顶部可切换管理员以及正常发送、网络不可用、日志不可用场景。管理员直接入口为 `/?surface=admin&variant=A`。

共用真实 `src/renderer/theme.css` 与 `panel.css`。原型包括反馈入口、截图选择/拖入/粘贴/预览/移除、本次日志勾选及预览、发送结果、离线待发、我的反馈、删除确认和管理员收件箱。

补截图路径：填写描述 → “返回工作补截图” → 原工作页面 → “继续填写反馈” → 原文字与截图保留。也可以点击“截取 Worket 窗口”，收起反馈后预览原问题页面，使用截图或取消都会回到原草稿。返回和关闭默认保存；“放弃草稿”在应用菜单中单独确认。日志勾选只保存为未提交选项，不会因恢复而发送。

## 当前结论与验证

助手推荐 A，尚未获得用户对视觉方案的确认。在 410×660 面板中，填写描述、添加截图和展开日志授权说明后没有内部滚动；窄窗允许内容滚动，底部发送动作保留。日志默认未勾选，缺失日志不阻止提交反馈。

2026-10-08 浏览器检查通过：截图添加/预览/移除、日志返回后保留授权、成功回执、断网重试、缺失日志、反馈删除、三种布局、管理员状态与备注，以及 360 像素宽的页面。未捕获脚本错误或数据写入请求。截图位于 `output/playwright/problem-feedback/`，运行产物不纳入提交。

同日补充检查通过：填写后返回工作、刷新后继续原草稿、确认截图再加入、取消截图保留草稿，以及真实 PNG 文件与日志选项跨刷新恢复。浏览器没有脚本错误。草稿保存为未提交数据，不会发送；原工作位置与日志范围在正式应用中仍需真实接入。

原型分支：`codex/prototype-problem-feedback`。尚未接入 Electron、诊断采集或后台上传；用户选定后再按正式实现要求重写，并更新产品与架构现状。
