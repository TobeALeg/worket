# Worket 问题反馈 UI 原型

这是可丢弃的 UI 设计，回答“如何让截图、问题描述与本次日志授权在紧凑面板内完成，以及中途补截图如何继续原草稿”。不调用生产服务；报告、回执与待发队列使用示例数据和内存状态，刷新会重置这些演示记录。当前编辑草稿单独存入本浏览器 IndexedDB，保留最近编辑后的 7 天，文字、所选图片文件与未提交日志选择可以跨刷新恢复。顶部“重置”会清除本地草稿。“收起反馈并截取工作页面”使用静态示例图，点击“加入反馈”后才加入草稿；导出按钮只导出演示报告元数据。

运行 `npm run prototype:feedback`，打开 `http://127.0.0.1:4327/?variant=A`。

## 布局候选

| 布局 | 地址 | 取舍 |
| --- | --- | --- |
| A 单页反馈 | `/?variant=A` | 描述、截图和日志授权同屏，推荐作为首版；用户无需额外确认步骤 |
| B 情境抽屉 | `/?variant=B` | 工作详情保留在背景，反馈更贴近出错操作；可用空间更紧 |
| C 分步确认 | `/?variant=C` | 先描述，再检查发送内容；确认更集中，增加一次切换 |

底部切换器或左右方向键切换候选，输入时方向键不被拦截。顶部可切换管理员以及正常发送、网络不可用、日志不可用场景。管理员直接入口为 `/?surface=admin&variant=A`。

共用真实 `src/renderer/theme.css` 与 `panel.css`。原型包括反馈入口、截图选择/拖入/粘贴/预览/移除、本次日志勾选及预览、发送结果、离线待发、我的反馈、删除确认和管理员收件箱。

正常操作时仅右上角反馈图标作为入口。默认先显示工作页面，点击图标才展开；顶部返回、关闭、Escape 或“返回工作补截图”均收起。工作列表、详情、交接和沉淀的演示流程独立于反馈，不会把正常操作导向反馈，菜单不增加第二入口；正常工作页面不显示草稿或反馈提醒。

补截图路径：填写描述 → “返回工作补截图” → 正常工作页面 → 系统截图 → 再点右上角图标 → 粘贴或添加，原文字与截图保留。也可以点击“收起反馈并截取工作页面”，预览示例原问题页面；“加入反馈”或取消后都留在工作页面，只有再点图标才展开。刷新默认关闭反馈，再点图标恢复草稿。缓存静默进行，仅保存失败在反馈内部提示；日志主表单保留勾选和“查看内容”，详细范围移至日志页。“放弃草稿”在展开反馈后的应用菜单中确认。日志勾选只保存为未提交选项，不会因恢复而发送。

## 当前结论与验证

助手推荐 A，尚未获得用户对视觉方案的确认。在 410×660 面板中，单页主表单移除缓存提示和日志说明，内容更紧凑；窄窗允许内容滚动，底部发送动作保留。日志默认未勾选，缺失日志不阻止提交反馈。
