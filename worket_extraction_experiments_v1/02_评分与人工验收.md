# Worket 抽取：评分与人工验收规范

状态：评测规格；尚未实现或运行生产评测器。

## 1. 评分对象

每个评分对象由 `case_id + cutoff_id + track + configuration_id + trial_id` 唯一确定。

- `track=S`：截至时点的当前工作状态和实际交接包。
- `track=D`：来源支持的可复用 Definition 首稿；确认版另记 stage。
- `stage=raw`：任何人工编辑之前的原始输出。
- `stage=confirmed`：人工确认后输出，必须关联修改记录。不能替换 raw。

每个实验的中间结果单独存档，但核心验收以真实持久化与导出后的用户可用结果为准。所有用户需要决定是否保留的候选、警告或疑问都计入审阅负担；不能藏在折叠区后宣称没有噪音。

## 2. 原子单位和匹配

### 2.1 不是按句子、JSON条目或token算准确率

输出“字幕使用英文并且不配音”包含两项可独立核实的要求。输出拆成两条或合成一条都不应改变语义评分。

“未完成审批之前不得发布”是带条件的完整要求；拆成“完成审批”“不得发布”会改变意思，不能分别算两个正确命中。

每个原子单元至少保留对象、行为/属性、否定极性、必要条件/例外、有效时间、采纳状态、适用范围及证据支持。不同文本、近义词和合理的字段映射可以匹配；缺掉限定条件不能算全对。

评分器可以用模型建议语义对齐，但冻结原子化规范；人工校准拆分、重复判断和关键错误。不要以被测模型的自报标签作为答案。

### 2.2 两个集合

`G`：参考标注中当前轨道必须保留的不同语义要求/必要信息。

`K ⊆ G`：预先标记的关键要求。

`O`：用户可见输出的全部语义单元，重复出现保留次数。正文、结构字段和需要人工处理的问题清单一并计入；纯导航/标题不视为命题。

可选的有用补充并不必然属于 G：它若有来源、范围正确且经统一准则认可，可以算有用输出。发现 gold 不完整时对所有组统一修订和重评分，不能只奖励某组。

### 2.3 严格命中的条件

对 `g ∈ G`，至少有一个输出单元完整保留其语义、必要条件、否定、状态、范围与有支持力的来源，并处在本轨道实际可用的位置，才记 `match(g)=1`。

几个重点：

- 含相同关键词不等于命中。
- 有真实 event ID 不等于该事件支持这句话。
- 原文已备份但当前交接包遗漏，不算 S 命中。
- 本次要求正确保存在 S，但不放进 D，不是 D 漏提。
- 被否定要求作为历史记录正确保留，不应被评成当前有效要求的命中。
- 明确要求被标“待确认”并因此不能用于执行，仍是有效要求覆盖的缺口。
- 确实模糊且影响工作的问题，准确标“待澄清”可以是正确处理；不允许对所有清楚要求一律拒绝判断。

只允许一个 gold 单元贡献一次召回。多个相似输出不会加分。一个句子可以覆盖多个确实独立的 gold，但输出中的附加错误同样要计入精度与噪音评价。

## 3. 指标公式

### 3.1 完整性

`RequiredRecall = sum(match(g) for g in G) / |G|`

`CriticalRecall = sum(match(g) for g in K) / |K|`

S/D、不同检查点、不同历史长度分别计算。报告每个独立工作和总体的分子/分母；总体不应只给一个微平均，让长历史掩盖短历史失败。

可增加“关键要求整例全对率”：某个 work 在全部预注册检查点是否所有关键要求均正确。严格但能暴露低频致命漏项。

“事件处理覆盖率”“结构合法率”另外报告，不能替代上述指标。

### 3.2 原始候选可信率：保留旧协议口径

对去重候选，判断证据支持、含义、状态、范围是否全部正确：

`CandidateTrust = correct_unique_candidates / all_unique_candidates`

它不直接度量有用性。因此候选都是真的、但多数不该给用户看时，仍可能 CandidateTrust 很高而产品很差。

### 3.3 有用精确率与无用信息

为 O 中每项判断四个条件：证据支持、语义/状态/范围正确、与目标视图相关、不是相同语义的多余副本。

`UsefulPrecision = correct_relevant_nonredundant_units / |O|`

重复出现只有一次能进入分子，所有次数都进入分母。模糊要求的必要待澄清项可以有用，但泛泛疑问、已经清楚却反复追问不能得分。

`NoiseRate = irrelevant_or_redundant_or_vacuous_or_wrongly_active_units / |O|`

`UnsupportedRate = unsupported_units / |O|`

Noise 与 Unsupported 可以重叠，不要求加和为 100%。另报各类错误的独立数量，避免“真实但无用”和“虚构”混淆。

可补“每1000展示token覆盖的必要要求”描述密度，但不作为单独晋级指标，避免靠极短输出刷密度。

### 3.4 人工劳动

编辑事件使用以下类别：

| 类别 | 意义 | 算历史抽取缺陷？ |
|---|---|---|
| ADD_MISSED | 补回原文已有、系统遗漏的信息 | 是 |
| DELETE_NOISE | 删除无关、重复或泛泛条目 | 是 |
| FIX_MEANING | 修正对象、动作、数值、否定或条件 | 是 |
| FIX_SCOPE | 修正实例/长期/任务家族边界 | 是 |
| FIX_STATUS | 修正采纳、替代、当前有效性或完成状态 | 是 |
| FIX_SOURCE | 修正来源、引用或来源归属 | 是 |
| STYLE_ONLY | 改写风格，不改变意思 | 否；但真实劳动照计 |
| AUTHOR_NEW | 用户现在才定义的新要求 | 否；不能算自动命中；劳动照计 |
| VERIFY_SOURCE | 主动打开/搜索来源核实 | 单独计次数与时间 |
| CLARIFY | 回答确有必要的问题，或被不必要追问 | 分别记录 |

同时报“实质纠错操作总数”和“受影响不同语义单元数”；UI一键批量删除多条不等于只纠正了一个错误。同一项反复修改计多次操作，但不同受影响单元只计一次。

按案例报原始次数，再按 `每100个G单元` 归一化，不能用输出项数量作分母来稀释错误。

`T_total = T_read + T_verify + T_edit + T_clarify`

计主动操作时间，不把纯等待冒充人工劳动；等待延迟单列。独立的实验标注与评分劳动单独报告，不与日常产品劳动混为一谈。实际定义确认、复核和补充则属于产品成本，不可排除。

原始版和确认版均评分；修改少但残留严重错漏的任务不算“节省劳动”。

### 3.5 稳定性

相同输入运行3次时，对每个关键gold单元检查是否3次均严格命中：

`CriticalAlwaysCorrect = 3次均正确的关键单元数 / 关键单元总数`

另报每次 CriticalRecall、最差单次、各工作整例全对情况。重复trial不是独立案例。可报告无关更新前后保持正确的要求占比，语义改写但不丢意思不算不稳定。

### 3.6 空输出、失败和拒绝

- G非空但输出为空：召回=0，精度=N/A，不能凭空输出“无错”通过。
- G为空且正确不产生要求：报告“正确空结果”；召回=N/A，不加入召回均值制造100%。
- G为空但仍有必要的待澄清项：在 gold 中提前列为必要处理，不事后调整。
- 拒绝/超时/异常/校验失败：该trial留在成功率分母；对必须信息的端到端覆盖计为未交付。精度可以N/A，但不能删掉失败样本。
- 人工修改无法开展：time=null、status=BLOCKED，不是0秒。
- 缺价格：cost=null，token和真实usage照报，不写0元。

## 4. 参考标注的人工验收

原作者先看原始记录回答：它说了什么？什么当时已经有效？什么尚未确定？后续哪些内容明确替代了前述内容？

评价者逐项回答：

1. 来源是否真的支持这个表达？
2. 条件、否定、数值、对象、角色和时间是否忠实？
3. 是本次有效要求、明确稳定要求、待决项、参考方法还是历史？
4. 删掉会造成什么具体工作损失？有没有重复或无关信息？
5. 相同原文里还遗漏了什么必要内容？

前4题看输出能做，第5题必须再看完整原文，否则同一遗漏很容易同时逃过生成和评审。

未提供附件正文时，不能判定附件包含特定要求；需要记录证据不足。记录确实只有元数据的案例应测试“不虚构”，不是期待读出不可见内容。

## 5. 评分器本身的验收

在跑真实算法之前，人工构造以下输出，确认评分结果方向正确：

- 空输出：有需求时召回不能高。
- 原文全量复制：不能被当成高有用性、低工作量的完美答案。
- 同一要求复制10遍：召回不变，有用精确率下降。
- 所有困难项标待确认：清楚要求的自动可用召回下降，人工负担上升。
- “禁止”改成“允许”：关键错误，不能因相似度高得分。
- “这次”改成“以后”：范围错误。
- 删除前置条件：不记完整命中。
- 只有来源ID正确、内容不受支持：不记支持成立。
- 句子合并/拆分但语义完全等价：主分数不变。
- 原文明确要求被改成含糊的“注意质量”：严格覆盖不命中。
- 正确空Definition：没有长期依据的案例，不应因为没生成模板而扣分。
- 推理输出中自称“已通过验收”：不能改变grader结果。

## 6. 报表与比较

先按工作历史聚合，再做配对比较。记录作者、任务家族、长度档、修订次数、原始事件数量、gold必要单元数、repeat编号。

报告配置的全体结果，不只展示最好样例。预注册“关键指标不退步、有用性达标”的门槛，再比较人工用时和修改量。新增指标或规则必须版本化。

建议报告配对差值、原始分子分母和按工作历史聚类的不确定性区间。极小样本不足以给出高精度生产错误率；不要把几十个同案条目当几十个独立用户。

半自动评分若与人工存在系统性分歧，应暂停选型、修评分器并统一重评分；不能让工程方案去迎合错误裁判。
