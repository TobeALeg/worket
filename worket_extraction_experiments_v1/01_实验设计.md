# Worket 信息抽取实验设计 v1.0

日期：2026-09-21
状态：**实验方案，未进行真实模型抽取实验，未修改仓库。**
范围：提高 Worket 抽取的完整性、准确性、有用性与稳定性；不涉及 Jev 选型，不预设“拆多阶段一定优于当前实现”。

## 0. 要回答的问题

在明确的任务家族、授权输入、模型和预算内，哪种处理方式能让 Worket **保留应保留的信息、不改变原意、不制造无用内容，并减少用户把首稿改到可用的实际劳动**？

“最好”指本轮预注册候选配置中，在测试范围内达到质量约束后的较优选择，不是对所有模型、行业和未来任务的普遍最优证明。

本方案给出的是建议阈值和实验设计；不把目标写成已实现结果。

## 2. 先定义“有价值”，而不是先选模型

### 2.1 工作相关的有效信息

满足以下至少一种作用，并有可定位的来源，才有理由进入可执行工作视图：

- 改变执行者要做什么、不做什么、采用什么输入或交付什么结果。
- 改变选择、边界、条件、审批、判断依据或验收方式。
- 说明当前有效状态、已知阻塞、待办、已经确认的产物或需要核实的未决问题。
- 避免下一位执行者重复犯错、重复询问或把已否定方案重新执行。

可以用一个判断帮助人工标注：**删掉这条，合格接手者可能做错什么、遗漏什么或不得不追问什么？**这只是判断辅助，不允许模型自行编造删除后果来证明任意内容有价值。

“通用”是共同的信息结构与适用范围，不是把所有工作都写成“保证质量、保持专业”。“只属于本次”并不等于“无价值”。

### 2.2 两条独立评分轨道

**S：WorkState / 交接轨道。** 保存本次目标、具体约束、输入事实、决定、已完成与待办事项、产物和不确定性。完整性分母是截至评估时点已经表达、对本次工作有效的要求。必须评价真实写入后的状态及导出的交接包，不能只评价中间 JSON。

**D：Work Definition / 复用轨道。** 保存有依据且适用范围明确的稳定规则、输入角色、输出要求和验收要求。分母是来源支持的可复用要求，不是原文的全部内容。不能因 D 不应保留实例值，就把它在 S 中的漏提判为合理。

历史上已否定或被替代的信息应留在可追溯记录中；不是当前有效要求。未采纳提案可以作为确有必要的待决项，但不应作为已经成立的规则。

### 2.3 三个需要保留的边界

1. 用户只说“高级一点”，系统应保留这是一个真实但未充分定义的要求，必要时列待澄清；不能自行扩写成“黑金配色、衬线字体”。不要将一切模糊要求都当成垃圾删除。
2. 历史中多次使用同一工具，只能支持“观察到一种做法”。除非用户明确要求，否则不能升级成永久必须使用的工具。方法可以保留为有依据的参考。
3. 未表达、未提供给模型的隐含偏好不能计为模型应提取的内容；用户评审时新增的要求标 `AUTHOR_NEW`，与“补回原文已有的遗漏”分开。

## 3. 数据与参考答案

### 3.1 第一轮先聚焦一个任务家族

建议沿用旧协议的“从素材制作视频 brief / 内容方案”，因为适合观察风格参考、约束、修改和交接。正式材料必须来自真实授权记录；本文样例不是用户真实历史。

第二个任务家族，例如编码或研究，单独增加、单独报告，不能用合并平均数宣称跨领域通用。

### 3.2 分阶段样本规模

起步：6 份独立真实工作历史，2 份校准、4 份封存。只能用于跑通标注和初步比较，不适合做大量选型后仍声称 4 份是独立测试。

多轮选型的目标规模：20 份独立工作历史，按 **10 开发 / 6 验证 / 4 最终封存** 分组。之前仍未使用的 2 调试 / 4 封存可纳入对应组；已经看过或用于优化的封存材料必须降级，不能重复当新测试。

开发集用于提示词、架构、阈值迭代；验证集只比较冻结候选、选择最终配置；最后 4 份只运行一次冻结的正式比较。样本不足时停止在试点结论，不把合成样本补成真实工作数量。

同一工作历史的不同片段、检查点、改写、重试及来自同一模板的近重复不能跨集合。共享相同客户项目/定义模板的案例按家族分组，避免泄漏。至少争取 2 位原作者；只有用户本人时如实标注单作者。

每段历史按有效时间选最多 3 个真实检查点：形成初始要求、明确修改之后、交接之前。只提供该时点之前可见的信息，不用未来消息评早期状态。

合成挑战集作为诊断与回归，至少覆盖：否定、双重条件、短回应、部分采纳、临时例外、跨分块纠正、重复、工具结果与人工确认区别、附件只有元数据、无有效要求、相互冲突、无复用价值、跨工作串线、旧实例值泄漏。与真实数据分开报告。

### 3.3 参考答案不是一篇“理想总结”

为每个案例建立原子语义单元，允许不同措辞与合理组织方式。一个条件性要求必须连同条件保存，不因原子化而拆散约束关系。

每个单元记录：

`gold_id, work_id, cutoff_event_id, semantic_content, evidence_refs, source_origin, adoption_status, validity, scope, destination, criticality, utility_reason, acceptable_variants, forbidden_inferences`。

`destination` 可为当前状态、复用候选、明确的待澄清项、历史追溯或不进入结构化视图。这里只是评测规范，不强迫生产库立即迁移全部字段。

原作者先确认真实意图和来源，评价者从完整原文检查遗漏及错误。不得只拿某个抽取器的候选让人打勾来建立金标准，那会共同漏掉同样的内容。LLM 可以预标注，但不能自己生成答案再自己确认。

重要要求双人复核，其他项可在试点后按预注册比例抽查；最初 2 份校准记录全部双评。争议项保留分歧并裁定。新发现确实有依据的有效信息，修改 gold 后须对所有组统一重评分；不能因为不在初稿参考里就一律算错误，也不能为了某组过关改答案。

## 4. 指标：完整、准确、有用和省修改必须同时成立

完整公式见 `02_评分与人工验收.md`。主看板至少有以下指标：

| 指标 | 核心问题 | 防作弊规则 |
|---|---|---|
| 关键要求严格覆盖率 | 关键要求是否在最终正确位置、以正确含义/状态/范围被保留？ | 在原文备份、隐藏候选或错误字段下出现同样词语不算命中 |
| 全部必要信息覆盖率 | 不仅最重要项，普通必要信息是否也保留？ | 分母由冻结的 gold 决定，不由模型输出数量决定 |
| 原始候选可信率（旧口径） | 有证据且语义、状态、范围正确吗？ | 独立报告，不用“引用存在”代替“引用支持” |
| 有用精确率 | 用户看到的条目中，有多少正确、相关且不重复？ | 真但无关、泛泛常识、重复及错误升格都不能得分 |
| 无用信息率 | 用户要读/删除多少无关、冗余或错误激活的内容？ | 候选列表、问题列表、折叠区的阅读负担也要入账 |
| 人工修改量与主动用时 | 把首稿改成可用版本需要多少增删改与查证？ | 不仅数点击；减少修改但留下严重错误不算改善 |
| 重复运行可靠性 | 同一输入每次都能正确保留关键内容吗？ | 所有重复保留；不能 best-of-N |
| 运行失败率与资源 | 是否稳定返回、真正写入，消耗多少 token/调用？ | 超时、空结果、校验失败不得从分母消失 |

不把所有指标压成一个总分。先满足硬约束，再在质量相当的候选里比较人工劳动、噪音、延迟和费用。

## 5. 实验 E0：诊断基线——信息到底在哪里丢失？

E0 是测量准备，不是待上线算法。

冻结当前代码和实际模型配置。对原文、候选、协调后条目、最终 WorkState/Definition 和导出工作包逐层追踪 gold。

错误定位为：

- **CAPTURE_MISSING**：合法来源没采集/没送到处理器。抽取专项分数与产品端到端分数分别报，不能隐藏采集问题。
- **DISCOVERY_MISSING**：来源已输入，但没形成候选。
- **INTERPRETATION_ERROR**：候选存在，但否定、条件、来源、采纳、范围或替代关系错误。
- **PROJECTION_LOSS**：正确候选在归纳/去重/压缩中消失、变弱、被误升格。
- **PERSISTENCE_OR_HANDOFF_LOSS**：模型结果正确，实际应用 patch 或导出时丢失。
- **NOISE**：新增无用、重复、无依据或错误生效的信息。

在开发集可做两种 oracle 诊断：给下游提供人工正确候选，测下游上限；给同一流程补上完整原文，测证据丢失影响。它们必须标 `ORACLE_DIAGNOSTIC`，不能作为产品成绩或送入正式测试。

当前路径没有显式候选层时记 `NOT_OBSERVABLE`，不能把后来另一次模型解释当成原始调用内部过程；可通过隔离实验进一步定位。

## 6. 六组核心实验

所有实验先固定模型版本、schema、合法输入范围、权限和评测规则。每个候选不覆盖基线。所有新增阶段都计入调用、token 与人工成本。

### E1｜提示词与上下文组织：简单修改是否已经足够？

**假设：** 提炼目标不清楚或语义上下文被切断，是部分漏提与误提的原因。

先比较 `P0 当前提示词` 与 `P1 明确有用性、实例/复用边界、原子要求及正反例的提示词`，保留原调用拓扑不变。正反例只能来自开发集。

再对胜出的提示词比较 `C0 当前切块/输入组织` 与 `C1 保持原始时间顺序、将指代/更正与必要相邻上下文组织在一起的窗口`。只调整一个因素；来源不能静默删除。

长历史采用同档输入上限，记录 overlap 和去重。不能为了让新方案读全而截断基线，或让新方案看见额外真实来源却不记录这种差异。正文超过任何配置的能力范围都保留失败账目。

**看什么：** 严格覆盖率、否定/更正错误、不同长度和位置表现、成本。如果 P1 或 C1 已达到目标，保留它作为有竞争力的简单基线，后续复杂方案必须证明增量。

### E2｜证据保真 × 职责拆分：究竟是原文有用，还是多阶段有用？

采用 2×2 对照：

| 组 | 相关原文证据贯穿关键下游阶段 | 抽取后独立协调，再生成最终视图 |
|---|---|---|
| E0D0 | 沿用 E1 最佳简单路径 | 否 |
| E1D0 | 是 | 否 |
| E0D1 | 沿用原路径证据策略 | 是 |
| E1D1 | 是 | 是 |

这里的“否”是不增加相应机制，不是删除当前代码已经提供的原文或已有 Definition 阶段。Definition 本来已分块提取和聚合；D1 是进一步将原子候选、状态/范围协调、最终表达变成可观测的独立职责。WorkState 则是从一次联合输出改为可观测阶段。

Definition 的 E1 是让协调/泛化阶段能核对候选所指向的原句及必要的更正/采纳上下文。WorkState 已经接收 newEvents 原文；它的 E1 是补齐跨轮指代和相关旧条目的来源，不是重复塞入相同文本。无差异案例不能被算作证据策略实验的有效比较。

证据选择由预先固定的程序规则与合法输入完成：候选引用、相邻回应、已知被替代条目等。禁止用 gold 挑出“正确证据”。程序验证事件/摘录真实性，模型负责含义判断；所有组最终仍输出兼容现有产品的结果。

**看什么：** E1D0 对 E0D0 测证据收益；E0D1 对 E0D0 测拆分收益；E1D1 检查协同或抵消。既比较效果，也比较实际总资源，必要时补固定成本上限比较。不预设最复杂组胜出。

### E3｜复查是否有效：不复查、普通复查、双向复查

固定 E2 入围流程，比较：

- R0：无新增复查。
- R1：通用“检查并改正”复查。
- R2：来源→结果的缺项核查，以及结果→来源的支持/状态/范围核查。

R1 与 R2 的总新增调用次数及 token 上限相同。R2 不是一句“再检查一下”，必须产出带证据的遗漏/错误清单和有限 patch。每次添加必须有来源，每次删改必须保留理由。

单次运行最多一轮审核修正；审核后保留复查前后快照。禁止无限自我改写、直到评分器满意。

**看什么：** 找回多少正确缺项、引入多少新错误、误删多少正确项、净提升是否值得新增成本。若只提高可信率却让覆盖率下降，不自动晋级。

### E4｜有用性与压缩：不是写得越多越好，也不是越短越好

固定同一份候选及证据，比较三种投影：

- V0：较完整地显示候选，状态/来源照常标注。它是噪音与覆盖的诊断参照，不是刻意让错误提案冒充事实的稻草人。
- V1：认真制作的普通整理/压缩，同样要求忠实、去重且方便接手。
- V2：按“是否影响执行/判断/验收/交接”筛选，并明确区分当前状态、复用候选、待澄清和历史。

V1 与 V2 在输入长度档位内使用相同展示 token 预算；另做不过度压缩的完整输出检查。预算事先由开发集确定，不根据测试 gold 临时放宽。低复用价值案例允许 Definition 为空或仅有待确认问题。

评价删除前后的原子要求覆盖、无用率、查找和修改时间。必要信息被移入原文备份不算“仍然完整”；用户真正要审阅的候选、警告和折叠区都计入工作量。

**看什么：** V2 是否比 V1 更少无用信息，而非仅仅更短；是否为了压缩而删掉困难要求；是否能避免把实例参数升格为默认规则。

### E5｜稳定性、增量更新和边界

对当前基线、简单强基线、最终入围方案做重复运行及语义保持变形。

旧协议每条件 2 次为最低重复要求；本轮建议对入围方案做 3 次，用于观察波动，必须全部报告。这是重复 trial，不是新增独立案例。

语义保持变形：插入不相关工具日志、等义表达、适度重复、改变不涉及时间关系的信息位置、改变分块边界。不得随意打乱更正发生顺序；改变先后可能已经改变真值。

语义敏感变形：只改一个“这次/以后”、只改一个否定、从“建议”改为“同意执行”、从“已导出”改为“已验收”。期望相应结果发生变化，其余无关要求保持。

增量测试比较：同一历史在真实调用节奏下持续追加，与每个检查点对截至当时的合法历史重算。只比较归一化语义，不要求 id/措辞完全一致。分别做“给正确 previousState”的隔离诊断和“延续自身输出”的真实累积测试，避免错误被金标准状态遮盖。最后必须通过实际 apply patch 和导出路径检查。

**看什么：** 关键内容全重复正确率、最差单次覆盖率、跨检查点要求保留率、过期要求复活、重复追加、跨工作串线和失败率。小样本零错误不是零风险证明。

### E6｜人工劳动与下一次工作：输出确实有用吗？

只对入围 1–2 个方案、原流程、认真普通总结做最终验证，避免把大量评测成本压到用户身上。

**A. 首稿纠正实验。** 冻结原始输出，用同一界面、相同证据入口，隐藏组名，记录增/删/改/查证/澄清的主动时间。尽量不同评价者交叉安排；同一人必须看相同案例的多个版本时，随机顺序、间隔展示并披露熟悉效应。先修哪一组会影响另一组，不能假装独立双盲。

修完后做独立残留错误审查。修改少但关键错漏还在，不算劳动节省。源中未曾出现、用户新创设的要求独立标注；它的劳动计入真实产品使用成本，但不能算自动抽取的命中或历史遗漏。

**B. 交接/复用探针。** 使用同一执行模型、harness、工具、权限、新材料与任务上限，比较原流程输出、入围方案输出和认真普通总结。先测试未经人工纠正的输出，之后可用确认版另测，不能混报。

S 轨道是在历史检查点接手同一工作；D 轨道是在相同任务家族里换客户/日期/语言/素材等本次参数。生成 Definition 时不能看到未来新任务的答案或事后新增要求。来源未规定的取舍，所有组获得相同授权信息，或同样允许提问。

执行者只获得分组允许的工作包和新材料；不挂载 gold，不读其他组输出。真实工作原文若属于某组允许基线材料，要明确记录，不能暗中附加给全部组而掩盖提炼缺陷。

重点评价预先指定的硬约束通过率、旧值污染、需要追问或人工救场次数和首稿验收。人工金标准工作包可作为开发诊断上限，不能当待部署算法。

**结论边界：** 只通过格式与语义评分，不等于已证明执行收益；只在原案例有效，不等于提炼出了可复用标准。

## 7. 可选的最后一轮：模型比较

架构选型时先不同时换模型。冻结候选流程后，可用当前模型与另一个经授权的模型做对照，或测试小模型/大模型组合。模型名单与实际接口版本现场核验，不在方案里假定某个型号一定存在或更优。

先固定流程测模型效应；再允许两模型分别在同样开发预算下小幅调优，统一在新验证集评估。若只换模型就胜过复杂重构，应接受这个结果。

微调不列入首轮必做：先得到稳定标注与错误分布，再决定是否值得增加训练工程。

## 8. 晋级规则：先质量约束，再谈省事

以下是建议决策线，必须在正式测试前冻结。旧 V1 指标与新指标分别保留，不能改了分母后与旧数字直接横比。

| 项目 | 旧协议最低参考 | 本轮候选晋级建议 |
|---|---|---|
| 原始候选可信率 | ≥95% | 继续报告，不由其他分数替代 |
| 关键稳定要求覆盖率（D） | ≥90% | 建议严格口径 ≥95%；S 的关键要求单独要求 ≥95% |
| 全部必要信息覆盖率 | 旧协议未设统一线 | 建议 ≥90%，各轨道/长度档分别展示 |
| 有用精确率 | 新指标 | 建议 ≥95%，无用信息率 ≤5% |
| 首稿人工实质修改量 | 全量记录 | 对当前流程建议下降 ≥30%；基线很低时用绝对差，不强算百分比 |
| 首稿主动审阅与纠正时间 | 全量记录 | 建议下降 ≥20%，不得以残留严重错误为代价 |
| 严重错误 | 确认版为零 | 冻结高风险挑战集与确认版均零；未确认首稿风险另报 |

严重错误包括明确禁止变允许、临时授权变永久、未采纳建议变规范、旧客户/日期/账号值污染新实例、错误跨工作替代、伪造已完成/已验收及关键错引。它们不能用几十条容易信息的高分抵消。

每份结果报告分子/分母、独立工作数、作者数、轨道和最差案例。置信区间或重采样以独立工作历史为聚类单位；多个原子要求和重复调用不是独立样本。仅 4 份封存案例的结论是试点观察，不能据此精确声称生产错误率小于 1%。

按质量门槛筛选后，比较人工负担、噪音、稳定性、延迟和费用的 Pareto 前沿。两个方法差异小于测量不确定性且没有明确质量优势时，优先维护成本较低者；保留“无明确胜者”的合法结论。

## 9. 执行顺序与停止条件

先 E0/E1，再 E2，之后按错误分布决定是否做 E3/E4；候选冻结后再做 E5/E6。不要第一天就运行所有组合。

开发闭环：冻结输入与基线 → 错误定位 → 单因素最小改动 → 全部旧回归 + 新反例 → 独立评测 → 人工裁定 → 晋级或回退。

沿用之前优化 loop 的边界：单轮最多 3 次开发迭代；连续 2 次无实质净改善就停止扩展、检查数据或任务定义。已用于查看错误的验证集降级，不继续称封存。正式测试不能边看分数边修改提示词。

## 10. 谁做什么

工程 Agent：接实际产品路径、做对照开关、保存 trace 和测试，不改 gold。

评测 Agent：独立处理证据匹配、错误归类、统计和泄漏审计；自动语义评分只作为辅助，需用人工样本校准。

用户/原作者：授权真实材料与费用，确认真实要求、适用范围和有用性，完成入围首稿纠正与最终业务验收。

需要时增加独立审计 Agent 检查数据隔离、评分器和实验账目；Agent 彼此不能代签人工确认。具体交付与停止条件见 `03_CODEX_执行任务.md`。

## 11. 推荐优先检验的方向，而非预定结论

当前代码值得优先检验的组合是：原文证据保真 + 可追踪的原子要求记录 + 当前状态/可复用定义分开投影 + 有限双向核查。

它的意图是“内部保留依据，外部只呈现相关有效内容”。最终是否采用、拆成几次调用，由实验结果决定。若一个清楚的提示词加简单上下文组织就达到同等质量，应优先保留简单实现。
