# 这次优化循环中，你需要做什么

你不需要编写测试，也不需要在多个Agent之间协调。你负责“真实业务要求是什么、哪些数据可用、是否真有改善”，总控负责代码、实验与证据。

## 开始给什么

先给1份完整且可授权的历史工作，逐步补至2份开发样本。不要求你先整理成Work Definition，否则会把待验证的提炼工作提前人工做完。保留用户/Agent角色、顺序、纠正/拒绝/临时例外、关键附件与最后成果。

再给你现在会用的最好办法：现有Skill、模板、原生项目规则或旧会话；没有文档就口头说明。对照不能被故意弱化。

原计划4份封存历史和6个未来新输入保留给final，不提前给算法开发者看。只有2份材料时可以先做开发方向，不让Agent从中改写出4份“独立验证数据”。

密钥不发聊天，不打印配置；只说明已配置服务/安全凭据使用位置。公司/客户资料先确认权限，脱敏不自动等于已授权外发。

## 你确认什么

| 时点 | 你收到什么 | 你做什么 |
|---|---|---|
| 启动H0 | 资料、服务、用途、预算、修改范围 | 批准具体范围，或删减；未批准live预算默认为0 |
| gold/门槛H1 | 原文标注与公平基线 | 修正稳定要求/本次事实/被否定/未确认类别和关键程度 |
| 每个被选定义H2 | 原文、原始候选、变更对照 | 保留、修订、删除；新想到的要求标USER_ADDED |
| 迭代争议H4 | 盲编号输出、冲突句子、差异 | 说明是否真的更正确/更能交付；无法判断就保持unknown |
| 候选就绪H1/H4 | 新旧对照、回归、成本与剩余风险 | 决定是否停止优化，允许解封final，或缩小范围 |
| 真实交接H3/公开H5 | 目标账号、材料/动作，或脱敏案例 | 分别批准，不用一般权限覆盖所有发送和宣传 |

不要求每轮逐条重复审已经稳定且未变的内容；总控先显示变更与高风险项。正式批次按原协议完整覆盖，未审查的份数不能被Agent自动签字。

## 手动审核用这6个问题

1. 这句话原文真的有依据吗？不是只有一个能点开的引用。
2. 意思是否相同？“不要做X”没有变成“做X”，“本次”没有变成“以后”。
3. 旧要求是否已被明确修订？不同工作的差异有没有被错误合并？
4. Agent建议是否真的被我采纳？一句“OK”不能代替每项确认。
5. 旧客户、日期、账号、答案有没有跑进新工作的默认值或固定约束？
6. 修改/确认之后，下一次用起来是否更省事？还是把重新说明变成更费力的改说明？

本次真实修订与主动用时要记录；等待模型单列。自动提炼和你补写的价值分开。没有真实计时就不宣称人工提效。

## 收到什么才值得放行

一页报告应包含：当前版本、适配任务、哪些缺口已修、哪些仍存在；本轮原始可信率和关键覆盖的分子分母；全部失败；你花了多少确认时间；下一步到底是“进入final”还是“已经有价值证据”。

不要接受只有“测试全绿、建议上线”。也不需要等到任意任务都能完美完成才推进；把没验证的路径从宣传范围中明确拿掉。
