# Codex执行：Worket提取优化循环

版本 v3，2026-09-18。目标是在最终价值验证之前，用证据定位最小修改，确保提取质量、来源可信和复用边界可测试。**不是“不断修改直到所有数字变绿”。**

## 0. 任务授权与边界

本协议是执行方案。用户将本包交给Codex并要求执行后，可在隔离工作分支编写测试、做本协议范围内的最小算法修复。真实数据读取/外发、收费调用、全局集成、schema迁移、生产部署、公开发布仍需具体授权；执行本协议不等于同意这些额外动作。

先读根AGENTS.md、CONTEXT.md、审计报告，再核验实际代码。不要切掉/覆盖本地未提交更改，不默认合并实验分支，不登录仓库记载的VPS。不得修改 `audit-snapshot/` 让历史诊断“看起来修好了”：产品修改应发生在实际Worket分支。

既有v2的人类关卡、数据隔离、证据分类仍有效；v3只增加前置优化，不降低v2标准。存在产品契约歧义时给用户可选解释及影响，不按模型喜好改变领域。

## 1. 4个角色，保持开发与裁判分离

| 角色 | 责任 | 修改权与边界 |
|---|---|---|
| A0总控 | 核验版本、拆单、审批/预算、锁、选候选、整合 | 唯一写任务板与状态；不代人签字，不改结果 |
| A1算法与工程 | 复现根因、提出最小修复，修改获准产品路径 | 不能修改gold、隐藏试题、评测阈值、失败分母 |
| A2测试与评估 | 把诊断转成回归；维护dev集、基线、runner、指标 | 不向A1提前开放final；不自己替用户做业务确认 |
| A3独立审计 | 检查来源/隔离/差异/全量运行，审查晋级条件 | 默认只读；不改产品、gold或原始记录 |

开发可按独立worktree并行；共享schema接口先由A0锁定，一个写者；正式批次并发1，桌面桥接独占。worktree不隔离HOME/模型会话/隐藏答案，执行者需独立受控目录与上下文。

没有可用子Agent工具时，按四份角色契约串行并标明模式，不虚构CLI参数。真正执行被测任务的短会话不能继承A0/A1/A2的参考答案。A3是内部审计角色，不应宣称第三方独立认证。

## 2. 一个循环，两个终点

```text
核验代码/数据权限/测试标准
        ↓
建立当前版本基线（不修改）
        ↓
已有防线与真实开发集是否满足候选门槛？
   是 → 可零修改进入候选冻结
   否
        ↓
选一个已复现失败族 → 先写会失败的测试 → 定位根因
        ↓
最小修复（一次只改变一个主要因素）
        ↓
确定性回归 + 开发集语义评估 + 小规模开发复用
        ↓
审计 + 必要人工裁定
   退步/无增益 → 保留失败记录，丢弃本候选或重新定位
   改善且无阻断回归 → 晋级为新的best candidate
        ↓
满足候选门槛 / 到上限 / 无增益 / 缺授权或数据 → 停止循环
        ↓ 满足时
冻结代码、提示词、模型、schema、任务与评分
        ↓ 人允许开启未见过的final
一次正式验收批次（固定重复次数，不是只跑1个样本）
        ↓
提取已验证后接回v2完整复用、接力、真人及采用验证
```

`FINAL_VALIDATION_READY` = 有资格开启未见过的数据；不是 `VALUE_VALIDATED`。最终通过也仅支持本任务范围和样本，不能推导“任意工作/任意Agent都可用”。

如果提取已经准确而实际总人工成本没有降低，转查交互/确认/维护/任务频率或定位，不继续无目的加复杂提取逻辑。

## 3. 数据必须在循环开始前分区

| 分区 | 内容 | 谁可看、何时可用 |
|---|---|---|
| regression | 本包反例、仓库合成样本、已公开的旧失败 | A1/A2可见，反复跑，证明不再复发 |
| dev | 至少先2份授权真实历史＋开发用的新输入 | A1可针对失败学习；明确不是最后证据 |
| final-extraction | 原计划4份封存历史 | 候选与评分冻结后才解封，不能提前调参 |
| final-reuse | 原计划6个未见过的新任务输入 | 最终V2阶段使用；绝不作为开发“冒烟题” |
| human-observation | 真实作者确认、主动时间、再次使用事实 | 按H0–H5授权；不能模型模拟填补 |

同一来源的分段、改写或近重复必须同分区，不能把拆出来的一半当独立holdout。仅文件名隐藏不是访问隔离。A0可保存哈希/分区清单；A1和被测执行者环境不挂载final原文或gold。

开发阶段只能用dev及合成变体调优。如果final失败后查看了内容以定位问题，整批内容记为已暴露，转入回归/开发；**不能再作为fresh final重跑并宣称验证成功**。没有新的未见过材料时写 `BLOCKED_FRESH_FINAL_DATA`。

材料总量不足时，可以先做低样本试点，不能借用final增加dev后仍沿用原final的宣传口径。

## 4. L0：盘点、基线与候选规则（先不改代码）

A0/A1核验main、当前本地分支、dirty状态、模型/服务版本、Node、测试发现列表。联网fetch需遵守当前权限；不自动pull。复用本地实际package scripts，在隔离目录中跑 typecheck/build:server/test，记录真正测试文件数和失败，不靠glob漏测制造绿色。

读取以下真实路径并生成 `adapter-map.md`：

- A链：AppService选择哪个WorkStateExtractor，什么时候调用，patch如何写入core和交接包。
- B链：prepare/wire → provider/extractDefinition → validateResult → receive/draft → update/publish → create → START/CONTINUE。
- `server/evaluate.mjs`可以复用的调用、usage、错误与人审机制。
- 工作目录与远程服务的代码/提示词版本如何对应。不知道生产版本时不得声称“已经测了生产算法”。

A2把本包G01–G08/L01做成针对**当前工作树**的复现，不直接运行历史snapshot冒充当前。原样保留第一次失败。

同时在H0批准的dev上跑当前版本真实模型结果，留未经修订候选。没有凭据只做mock和结构回归，live部分BLOCKED；不得让Codex自己生成候选再填回产品。

输出：`environment.json`、`baseline/`、`gap-matrix.md`、`HUMAN_INBOX.md`、人确认的`rules.freeze.json`。基线模型与每次候选比较须固定；要换模型应作为单独因素和独立对照，不同时改prompt/schema/model。

## 5. L1：把已复现问题写成“期望行为”测试

**本包诊断的GAP_REPRODUCED是“复现成功”，不是正确行为。不要把它直接复用为产品合格断言。**

| 测试族 | 应补到的实际边界 | 期望行为与对照 |
|---|---|---|
| T01中间schema | chunk响应收到后、reduce之前 | 非法scope/引用/空字段/重复ID中止或转明确失败；合法候选正常通过 |
| T02替代链 | 同work协调后 | 拒绝自环/环/未知目标；合法修订链通过；跨work不能默默覆盖 |
| T03范围到条目 | generalize结果与发布之前 | final来源条目必须映射有效要求；INSTANCE/REJECTED/SUPERSEDED不能静默升级通用硬要求 |
| T04实例默认值 | 模型输出接收＋发布/实例化边界 | 历史客户/账号等不自动做新实例默认；有依据的稳定默认保留明确确认路径 |
| T05语义支持 | dev评估/疑难项人审 | 合法ID但相反含义标contradicted；证据不足标uncertain，不依靠简单关键词当最终真值 |
| T06事件覆盖与要求召回 | runner统计 | 分开event coverage和gold语义recall；本案例空提取不能得高召回；确实无可复用要求可安全返回不足/不相关 |
| T07状态条目保留 | LocalRuleExtractor/core/UI | >8条关键约束不因显示限制丢失；原文、状态、来源仍可核验 |
| T08否定完成 | LocalRuleExtractor → package | 否定/未完成不呈现为已完成事实；肯定陈述依旧是AGENT_PROPOSED，不能自动变成用户验收 |
| T09长事件（按需要） | chunking/evidence span | 超额明确拒绝或无遗漏分段；父事件/区间/哈希可还原，跨界纠正可识别 |
| T10既有控制 | 全链现有回归 | 假引用/角色冒充仍拒绝，合法变体通过；版本、实例、授权、取消仍正确 |

安全失败、歧义待确认可以是正确结果，但不能把全部拒绝当成高质量；对适配任务同时考查覆盖率、完成度和确认负担。

A3核对测试是否调用实际模块/公共入口。精确原文包含不能替代自然语言蕴含；按本测试句子特判、删掉失败用例或改gold均为无效修复。

## 6. L2：最小升级路径（按失败决定，不要求一次全做）

### U1 中间结果结构化验证

优先在 `src/contracts/definition.ts` 增加可复用的中间结果validator，在 `server/workflow.mjs` 每次chunk调用后立即运行。规则与来源集合由程序传入，不由模型自己声明“合法”。

替代目标可能在后续chunk，不能在单chunk把尚未看见的合法引用直接判死。分两层：chunk仅接受允许的局部信息/外部待解析指向；同work全量协调后再检查目标存在与无环。无法可靠对齐则保留待确认，不靠字符串相似度强制合并。

### U2 原文锚点、来源角色和有效性贯通

引入内部 `ExtractionTrace` / 相当类型，先不改变用户可见对象体系。建议包含：

```text
AtomicRequirement
  id, text
  origin                 # 模型分类；必须与实际事件角色交叉核验
  scope                  # INSTANCE / REUSABLE / UNCERTAIN
  status                 # ACTIVE / SUPERSEDED / REJECTED / UNCONFIRMED
  applicability          # 有依据的适用条件；未知不能造
  evidence[]             # sourceKey,eventKey,可定位片段
  supersedes[]           # 有依据的修订关系

DefinitionItemTrace
  itemPath               # collection + key，避免跨集合重名
  requirementIds[]
  supportStatus          # supported / contradicted / uncertain
```

原文片段/角色/顺序/哈希由程序从冻结request回填并核验。若模型提供start/end/excerpt，验证它们与同一原事件匹配；别把模型写下的kind/hash当可信源。聚合拿到精简原文依据与必要上下文，而不只是上一步改写。

内部字段是候选设计，不要求照抄名字。任何wire schema/存储迁移先给出兼容方案并由H1补充确认。已发布定义不得偷偷重写；新版本可以使用新trace，旧版本声明缺少哪些证据。

### U3 只把可复用的有效要求编入定义

区分“本次允许不加CTA”和“以后不要加CTA”；区别“用户拒绝了Agent提案”与“用户要求不要采用该手法”。不要把含否定词的句子全部删除，因为禁止要求本身是重要知识。

最终来源型条目必须能沿 requirement → evidence → 原文追溯。已替代或仅本次内容可以留在历史/解释中，不直接作为下一实例硬约束；有冲突时写issue且阻断/待确认。若同一材料含有效稳定要求与实例事实，不能仅凭事件相同就全收或全删。

机器产生的实例参数默认值采用保守策略。可把候选stable default显示为待确认，H2后按人确认的范围发布；人工新增与模型提取分账。不要求禁止所有可推导/可建议内容，只禁止假装它们已经是用户长期标准。

### U4 语义核对与开发复用

先对原文增强版本做dev比较，再评估是否需要额外语义审核调用。关键负向、范围扩大和冲突项可用独立无工具模型辅助核对；所有调用计预算，超限失败有状态。缺少足够上下文应uncertain，不强行supported。

A2给人显示“原文→中间要求→最终定义→变化”。开发人评用于识别真改善；模型评审需用人标样本校准并记录分歧，不能把多Agent一致当人工确认。

用开发专用的新输入，做小规模A/B/C复用方向检查（例如2输入×3组×2次=12次，须预算批准）。最终6个输入不在此使用。保留现行好Skill/文档对照，不把只提升提炼评分却使交付变差的候选晋级。

### U5 状态路径与容量

需要宣传接力时修T07/T08，单独检查本地与云端WorkState接入、core合并和人编辑保护。单批修好不自动表示跨批合并正确。若只宣传定义复用且不依赖此状态路径，可留为已知未覆盖，不据此宣布全产品就绪。

长事件按实际材料决定是否分段。分段必须可还原事件区间，交叠去重有定义，最后一段缺失不能显示覆盖100%。先把支持范围说清楚，比仓促支持所有文件更好。

## 7. L3：每次候选的对照与晋级

每轮只选一个失败族，写清假设、预期影响、涉及路径。A1提交diff，A2同规则同dev评估best与candidate；历史baseline也保留。默认同条件2次，不只重跑候选输掉的任务。

所有实际启动trial先入账；崩溃、超时、取消、错误、人工救场都保留。修改/重试新runId，记录retryOf和新版本，禁止覆盖。usage、费用与主动人工时间缺失填null，不写0。

晋级条件同时满足：

- 该失败族的期望行为回归通过，合法正对照也通过；现有阻断类回归无新增失败。
- dev可信率/关键覆盖/硬约束没有退步；新严重来源或实例污染为0；不靠大幅拒绝/漏提规避。
- 至少一个事先冻结的目标指标实际改善，或旧版本本就达到门槛而无需修改。不同人/题/版本混算不能算改善。
- 小规模dev复用不出现新增严重失败；没有真实人工计时就不发布省时结论。
- 费用与延迟在事先批准的范围，A3确认证据有效；涉及语义争议由用户裁定。

若引入不可比schema或模型变化，用新的可比批次，而不是拼接旧/新最优数字。新旧功能均保留可重跑版本，回退只操作该候选工作分支，不覆盖用户其他工作。

## 8. 停止规则（默认建议，开始前可调整）

- 自动开发候选最多3轮，不计第一次baseline；连续2轮没有预先定义的实质改善即停止，输出NO_GAIN和根因。
- live费用上限未被人填入并批准时为0：不调用真实服务。并发默认1；每trial超时/重试上限、每批调用数在H0确定。
- 达到预算/迭代上限或新资料/新收件方/新schema需求时暂停相关分支，交付已完成证据。
- 出现未授权外发、来源伪造、破坏原件等严重问题，立即阻断相关live路径并保留安全的诊断信息。
- 已达候选门槛即可停止优化，不能为了多跑一轮消耗final或制造更多改进项。

状态：`BASELINED / ITERATING / DEV_READY / FINAL_VALIDATION_READY / FINAL_EXTRACTION_PASSED / VALUE_VALIDATED`；并列异常 `FAIL / BLOCKED / NEEDS_HUMAN / NO_GAIN`。日志写下一步，不使用一个总passed掩盖各证据层。

## 9. 何时允许开启最终验收

A0给用户一页候选就绪卡，包含：固定版本/提示词/模型/schema、支持任务范围、目标缺口处置、全部回归及控制、开发语义分子分母、人工修改负担、费用、已知限制、未读final的哈希清单。

提取候选门槛沿用v1建议：dev未经人工改写的可信率≥95%、关键稳定要求覆盖≥90%、确认后严重错误0。小样本只作内部方向信号，不是总体置信声明。unknown/争议必须单列且不能静默剔除，缺gold或空分母不能得100%。

H2对用于C/D的每个定义版本真实确认；H1允许解封final。封存输入跑固定次数，再由合格的人评分。此时才判断最终V1，随后接回v2的V2完整机器与真人、V3生命周期、宣传所需V4/V5及V6观察/V7信任。

最终检查失败不能被修改开发门槛掩盖。失败说明范围；需要继续修复则遵循final退役和新样本规则。

## 10. 每轮程序与人工分别验什么

| 内容 | 程序负责 | 人负责 |
|---|---|---|
| 版本/输入 | SHA、schema、snapshot与gold哈希、环境 | 选择拟推广的实际版本和任务范围 |
| 引用 | ID、角色、区间、哈希、映射、无环 | 引用是否支持该句话，是否扩大范围 |
| 要求 | 状态/范围闸门、模型不能伪造人工review | 稳定/本次/废弃/建议的真实含义 |
| 结果 | 产物存在、状态/权限、全量账本 | 能否交付，事实和品味是否符合冻结规则 |
| 成本 | 采集调用、计时工具、算术和缺失 | 真正主动投入、估算/实测、支持时间 |
| 晋级 | 明确阈值计算和不完整证据阻断 | 业务取舍、争议裁定、范围与公开授权 |

## 11. 最小实现形态与输出

不要新建评测SaaS/数据库/企业ontology。优先扩展现有 `server/evaluate.mjs` 或v2建议的最小Node/JSONL runner，提取共享调用模块，UI/runner走同一生产提炼逻辑。

建议的phase是语义契约，不是当前已存在CLI：`baseline / regress / evaluate-dev / compare / freeze / final`。A2实现后才提供可运行命令，记录入口提交。任何自动控制器必须实际处理非零退出、预算、哈希变化、人工批准缺失和不可重入，不能用shell while无限调用Codex。

退出码可沿用v2：0该程序阶段执行成功；10实际失败；20环境/授权阻断；30等人工；64参数错。report生成成功不代表质量通过；审计probe的0也不代表修复成功。

私有输出：

```text
experiment/
  environment.json  rules.freeze.json  TASK_BOARD.json  HUMAN_INBOX.md
  data-manifest.json  approvals/  gold-private/
  baseline/          # 原始版本全部结果
```
