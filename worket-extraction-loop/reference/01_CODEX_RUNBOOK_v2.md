## 1. 成功产出：分别交付四种结论

| 结论层 | 要回答什么 | 不能替代什么 |
|---|---|---|
| 工程正确性 | 保存、版本、实例、来源、授权、失败路径是否按约定工作 | 不代表真实提炼准确或用户省时 |
| 模型/信息质量 | 真实模型提炼是否准确，新输入交付是否更符合要求 | 不代表确认与维护成本已经回收 |
| 人的使用价值 | 算上安装、整理、确认、返工、维护后是否净省投入 | 不代表别人会自然再用 |
| 采用事实 | 外部用户下一次真实任务出现时是否主动再次选择 | 不代表长期留存、PMF、付费或壁垒 |

结果使用 `PASS / FAIL / BLOCKED / NEEDS_HUMAN / NOT_RUN`。负向用例可 PASS，但其任务结果另写 `blocked_expected`，不能记作交付完成。`SKIP` 不能折算 PASS。每项报告必须说明证据类别：`static / mock / live_model / live_executor / human_observed`，并单列 `synthetic / real` 材料。真实模型处理合成材料仍不是用户样本。

## 2. 调几个 Agent，怎样协调

**4 个长期角色：总控 A0 + 工程 A1 + 实验 A2 + 审计 A3。** 开发准备阶段可并行，正式实验和桌面操作收敛为串行。

| Agent | 负责 | 可写范围 | 明确禁止 |
|---|---|---|---|
| A0 总控 | 版本冻结、排期、任务分配、审批核对、整合与最终报告 | 实验文档、任务板、汇总报告；唯一整合者 | 代用户授权、事后降低门槛、私删失败、未经许可部署 |
| A1 工程测试 | 现有回归、安全边界、测试数据隔离、桌面 UI、必要测试接入点 | 独立分支的测试文件和经分配的测试适配器 | 顺手重构产品、按错误现状改预期、把 mock 算真人 |
| A2 价值实验 | A/B/C/D/H/W 对照准备、任务 runner、随机顺序、计时表、数据计算 | `scripts/value-validation/` 中分配文件、试验原始输出 | 读取隐藏评分后作为正式执行者答题、伪造人工时间 |
| A3 独立审计 | 审查评分、隔离、全样本账本；复核产物、错误、宣称范围 | 默认只读产品和结果，返回审计意见，由总控落盘 | 改业务代码/门槛/原始结果；代人确认“符合品味” |

### 2.1 启动与并发

A0 向原生子 Agent 下发 `agents/01_ENGINEERING.md`、`02_EXPERIMENTS.md`、`03_AUDITOR.md`。先分配互不冲突的目录，等待规定产物，再进入下一阶段。

原生子 Agent 不可用时：保留 4 份角色契约，串行执行；也可由用户开独立本地会话，但默认不要求用户手工调度多个窗口。总控记录实际模式。不要虚构 `codex spawn` 一类未核验命令；先查本机帮助与可用工具。

**正式任务执行者不是这 4 个管理/开发角色。** A2 使用干净会话启动短生命周期执行任务；一次只接收一组授权输入，不继承总控、测试开发或评分者的历史。36 次 trial 不等于调 36 个常驻 Agent，也不等于 36 个用户。运行 trial 时可暂停其他角色，避免无谓并发与费用。

### 2.2 分支、工作目录与设备锁

先检查 `git status --short`，不 stash、reset 或删除用户未提交更改。只有确有必要才创建命名明确的新测试分支/worktree；名称加日期/唯一后缀，存在则停止复用并核查。多个写入者各自 worktree，各自依赖与构建目录；A0 串行整合。

worktree 只减少代码文件冲突，**不隔离 HOME、会话历史、系统桥接、钥匙串或参考答案**。正式执行者采用只挂载本 trial 输入的沙箱/独立受控环境，评分答案与其他组产物不挂载。做不到时标 `ISOLATION_NOT_ENFORCED`，该运行只作为调试证据，不宣传为无泄漏正式评测。

同一台机器同时只能一个进程占用桌面桥接。A0 使用原子 lock 目录/文件记录 PID 与 test_run_id；不要仅凭文件存在删除锁，要确认进程已结束并由总控处理。不能多人并行执行 `package:mac`、`qa:desktop-roundtrip` 或改写同一个输出目录。

### 2.3 用文件交接，不用“应该已经好了”

每个任务单包含 task_id、owner、depends_on、base_sha、allowed_paths、expected_outputs、验收条件。子 Agent 返回：状态、实际命令/退出码、输出路径/哈希、缺陷复现、需要人的具体决定。采用 `templates/agent_handoff.json`。

A0 独占写 `TASK_BOARD.json` 与 `HUMAN_INBOX.md`；其他 Agent 不能互改结果。A3 看不到已经过人为美化的唯一摘要，必须能查原始日志。证据包只追加新运行，不能覆写旧 run。

## 3. 安全默认值与真实权限

默认允许：读仓库代码；在隔离工作目录新增测试、模板、合成数据；运行已审查、无外发的本地测试。依赖下载若环境尚未授权，列出来源与用途后请求授权，不关闭沙箱绕过。

默认不允许：读取或导出全部个人会话；读取密钥正文；修改全局 Agent 配置；安装 hook 到日常账号；发送真实资料给外部服务；收费模型调用；访问或部署 VPS；发布 Release；向客户/投资人发送消息；删除日常数据库。

仓库 AGENTS.md 中的 VPS 操作说明是操作知识，不等于这次测试授权。不要用其中的地址、账号或密钥路径擅自登录。BP 记录要求由 A0 按项目约定维护，但只能追加“待验证/本次实测”的真实状态；不得把脚本生成的 PASS 当作用户收益。

真实材料放在仓库外的私有实验根目录，权限尽量限制到本人。不要放进公开 fixtures、git diff 或完整日志上传。新增代码可提交，真实数据/身份/来源正文不能默认提交。数据清理仅限明确实验目录；保留期与是否清除由人决定。

## 4. 用户要提供什么：渐进收集，不阻塞离线准备

A0 把以下信息整理成模板让用户确认，不要求用户自己整理复杂 JSON。

| 材料 | 最低启动量 | 正式目标 | 用途 |
|---|---|---|---|
| 当前本地环境 | 仓库可访问；Codex 自查 OS、架构与 Node | 桌面阶段需匹配当前打包目标的 Mac、可用测试账号 | 工程与真实 UI |
| 历史工作 | 先 1 份可授权真实记录，仅用于调试 | 6 份：2 调试、4 封存；尽量两位作者 | V1；形成候选定义 |
| 原始材料与成果 | 完整用户/Agent 对话、附件或可读取副本、最终稿 | 保留角色、顺序、关键纠正、拒绝与例外 | 来源核验，不仅是摘要 |
| 现行最佳做法 | 现有 Skill/模板/项目规则/重开旧会话流程 | 先于查看 Worket 输出冻结 | 公平 A 组 |
| 新任务输入 | 调试可用合成内容 | 同类 6 个未用于调参的新输入，其中 1 个不适用边界 | V2 机器 36 次 |

真实样本暂缺，A1/A2 继续代码回归、合成边界、runner 自测，V1 真实质量/V2 真实收益标 BLOCKED。不能编造客户、聊天、付费或人工时间。参考答案由任务拥有者确认，不由生成模型独自充当事实标准。

## 7. 阶段 P1｜工程回归与合成链路（A1主跑，A3复核）

### 7.1 当前仓库的真实入口

下面是固定 SHA 中已经存在的入口，不是新发明的命令。安装依赖前检查 lockfile 与 lifecycle scripts，清理模型密钥环境；允许下载后按锁安装，不自动升级版本。

```sh
npm ci
npm run typecheck
npm run build:server
npm test
git diff --check
```

`npm test` 自带 build；保留 build 失败与测试失败的区别。Node 版本以本机验证为准；不要把环境不兼容当产品逻辑失败，也不要通过改掉全部依赖来“绿化”。服务测试可能需要本机环回端口权限。

匹配当前 Mac ARM64 打包路径、已隔离且获准运行后：

```sh
npm run package:mac
node scripts/qa-distillation.mjs
node scripts/qa-distillation.mjs --improvement
npm run qa:package
```

`qa-distillation.mjs` 的 provider 明确为 fixture，交付物是代码写入的合成文本，且脚本自动选择验收 PASS。因此只验证 Electron/IPC/SQLite/服务/页面串联，**不是 live_model、live_executor 或 human_observed 证据**。

每次脚本可能复用 `output/distillation/` 或 `output/improvement-desktop/`，A1 串行运行，每次立刻复制到唯一 run 目录并计算哈希；不得用后一次覆盖前一次记录。打包命令带 overwrite，只能针对已隔离测试 worktree 的构建产物。

其他现有入口 `qa:current-context`、`qa:workbuddy-context`、`qa:desktop-roundtrip:list` 会接触当前桌面/本地会话；即使是 list 也不自动等于无需授权。`setup:integrations` 会安装集成，必须另外获准后才用。不要默认运行 `qa-vps*`、release、deploy 脚本。

### 7.2 必须覆盖的程序断言

复用现有测试，缺项再补；对每条记录现有文件与 test 名称、是否 mock、断言、日志路径。

| ID | 场景 | 程序必须检查 |

| E01 | 记录指定会话，其他会话有事件 | 只有指定绑定写入；事件来源与工作关联正确 |
| E02 | 重复导入/Hook重发/乱序重放 | 不重复计数或重复绑定；顺序/去重遵循当前领域规则 |

| E04 | 未确认提炼/改进不同开关 | 未授权用途请求数0；分别观察采集、提炼、改进的数据流 |

| E10 | START 与 CONTINUE 包 | purpose 正确，输入/状态边界明确，出口对应实际产品对象 |
| E11 | 附件失效、无权限、版本改变 | 明确缺失/阻塞；不能假读；不靠静默换文件通过 |

## 8. 阶段 P2｜搭建最小价值实验器（A2，A1提供接入点）

### 8.1 worket-adapter 接口契约

至少暴露以下测试职责，函数命名可依本地代码调整；在 `adapter_map.md` 中列真实模块/符号、输入输出与验证证据。

- 导入/读取**授权**工作来源：必须经过真实核心或现有应用API，不直接插入一份伪造“成功库”。用于初始化fixture时的直接造数单列 mock。
- 用实际提炼路径产生原始候选；provider从实际已批准配置取得，不由Codex自己回答后塞回产品。
- 保存候选和用户确认差异；正式发布依赖H2，不让runner自动签字。
- 用已发布definition_id/version和新输入创建实例；记录输出instance_id并核查旧实例快照未变。
- 导出产品真实 START / CONTINUE 工作包及产物引用。已见代码有 `window.workpet.distillation("package", {workId})` 和 `createWorkCore` 的接入示例，可复用，但最终依据本地完整代码。
- 记录实际交付、验收结果和失败；通过产品路径回写，不直接修改数据库完成状态。

若没有可自动调用的接入点，先补一个最小测试适配层并证明与UI同一核心路径，或把该步骤标为人工辅助。不能另写“理想版Worket”代替实际产品。

### 8.2 runner 必须通过的自测

未授权live调用被阻断；预算为空或0时live阻断；dry-run不调用provider；任意子进程失败不被转换成功；mock不能提升为真人结果；产物缺失不能完成；人工计时/确认缺失为null或NEEDS_HUMAN；旧run禁止覆盖；重试保留旧run与retry_of；版本/任务/评分哈希变化使旧审批失效；参考答案未挂载；环境重置失败阻断；计划36次必须逐项入账，缺失不能从分母消失。

所有启动的trial保存：原始输入、组别/顺序、版本/环境、命令、stdout/stderr或工具事件、首稿与最终稿、真实返回usage、状态、错误、证据哈希。价格未知就只报token/额度和费用null，不编造“免费”或0元。

批次并发默认1；每条件正式重复2次；不无限重试。预先设定每trial超时与最大纠正轮数，三组一致。超时保留为失败/受阻，不能重新命名run遮盖。任何新收费调用前原子预留预算；无法估价/硬限额时只做已获准的小批次并由人补充额度规则。

### 8.3 正式执行者和模型固定

核心归因是第三层Worket，先固定第一层模型、第二层Agent/harness及工具/权限；不要C用更强模型、A用较弱模型。

每trial全新工作目录/会话。只给公开任务、该组允许材料、统一工具与固定上限；不给隐藏金标准、组名优劣、参考答案、其他组输出。历史资料中的有效要求是合法输入，未来试题的标准答案不是。

可使用本机可用且已核验的 `codex exec` 执行干净任务，并记录 `--json` 事件与最终产物；具体参数先核对本机help。不得使用 resume 延续上一组；不得使用 `--yolo` 等关闭安全边界。原生历史基线若依赖原会话，应保留其实际合法历史，但确保没有本轮新答案。

订阅登录与API计费分开记录。测试控制Agent耗时不能冒充用户人工耗时，实验专用评分成本也不直接算用户日常成本。

## 9. 阶段 P3｜V1 与 V2（正式核心）

### 9.1 V1 可信提炼

1. A0给历史材料分配 D01—D02 调试、T01—T04 封存，保存快照哈希。源真实/合成、作者数量单列。
2. 人先标记稳定要求、实例参数、当前状态、临时例外、已否定/替代意见、未确认推测；A2可做候选标注，**人修正签字后才是金标准**。
3. H1通过后对4份封存来源运行真实提炼；保存原始候选，按冻结标准逐项比对。
4. H2人确认候选，保存改动和真实主动时间；用户新增标user_added，不作为提炼命中。
5. 未经修改的候选可信率≥95%、关键覆盖≥90%；确认版严重错误0。空输出/分母0为不可计算，不得按100%。未知/争议项须单列，未裁定不能签全量通过。
6. 确认与维护成本进入V2；原始质量差、经人重写后通过不能被汇总成“系统准确”。

### 9.2 V2 新任务复用：A/B/C

A：用户现行最佳办法；B：认真制作、允许人工核对的普通总结；C：Worket实际发布定义。都能访问同样授权历史与新资料，允许各自正常组织，不刻意限制基线。

A先于展示C冻结。A已有历史成本是沉没成本，不重新收取；本轮额外制作成本记录。B模板参考上一版基线提示词，不能退化成“随便概括”。

6个新输入 × 3组 × 2次 = **36个计划trial**。建议其中5个适用任务、1个明确不适用边界。边界正确拒绝/澄清单列，不计为完成交付；总账仍保留36条。每个任务的三组运行顺序由A2随机并记录seed；重复trial不是独立用户。

模型阶段：先评首稿，再按统一停止规则记录纠正后成果。比较硬约束、旧实例污染、遗漏、软质量、实际token与等待，**不得由机器阶段输出人工省时结论**。

真人阶段：3位非创始人，各一对相似难度的新任务，用A/C交换顺序，共6次实际工作。不是让同一个人重复同一道题。作者/同事/外部用户身份分别记录。每人自己的定义与工作匹配，不默认跨人通用。

人H4盲评：隐藏A/B/C与生成工具，保留影响业务判断的合法任务信息。所有严重告警必审；正式36份输出原则上逐份评定，可分配另一位有能力的评审。未评份不能由模型自动签字。模型可辅助列差异，但最终主张依人确认。

### 9.3 V2 通过门槛与计算

质量：C最终硬约束通过率不低于A；100分软评分配对差中位数不低于-5；没有新增严重污染/授权问题。第一轮与纠正后分开，不把全部拒绝当作高质量。

成本：

`T_p(n) = 本轮新增安装/学习/整理/确认成本 + Σ(选择准备 + 说明 + 人工执行 + 返工 + 结果复核 + 维护)`

同一人的重叠主动计时不能重复加；不同人的投入相加；等待单列。实验研究访谈/盲评分与原本交付的业务复核分开；模型费用与创始人支持时间单列。缺失用null，不填0。未完成任务不能因提前结束被算省时。

在真实观察周期内C总主动投入相对A下降≥20%，至少2/3参与者净收益同向，才按本协议给出方向性通过。报告逐人值、完成数、范围和配对限制；不是统计非劣性或总体显著性检验。若只观察了一次，不能把初次投入除以未来假设6次制造回本。质量/完成度不可比时，净省时结论为未成立。

如果B与C已相当或更好，如实披露，进入V3验证产品流程增量，不隐藏B。

## 10. 阶段 P4｜V3/V4/V5：差异化与可移交性

### V3 同等内容导出的消融

C完整Worket；D同一确认定义的完整Skill/Markdown导出。保留来源、版本、约束等同等内容，允许正常文件管理。

做完整序列：第一次使用 → 收到同一标准更新 → 下一位使用者找到正确版本并开始新工作。先1组，目标3组。时间比较覆盖查找、核对、更新、复制、实例化、交付、归档；不要求首份输出必须C优于D。

质量不劣、无新增版本错误，完整生命周期主动投入下降≥20%，才产生产品操作增量证据。没有导出功能时标人工复制方法测试，不说已验证产品导出。

### V4 桌面真实接力：复用已有脚本但不混同价值实验

现有 `qa:desktop-roundtrip` 使用打包Mac应用、当前Codex会话、WorkBuddy账号、真实MCP/Hook证据；会临时改写默认bridge配置并在finally恢复。它不是全自动离线脚本。必须先取得H0/H3、确认应用退出和桥接锁、备份并核对原始配置恢复；不依赖finally处理所有进程强杀情形。

**H0批准会话枚举后**才运行：

```sh
npm run qa:desktop-roundtrip:list
```

然后人指定一个允许外发的thread。**H3明确批准该thread与目标账号后**由A0设置真实参数：

```sh
WORKPET_QA_THREAD_ID="已批准的实际thread_id" \
WORKPET_QA_CONFIRM=SEND_TO_CURRENT_WORKBUDDY_ACCOUNT \
npm run qa:desktop-roundtrip
```

环境变量名和值是现有脚本真实契约；这段示例不是外发授权。脚本会要求人在所选Codex工作中新增一轮对话、完成后回终端继续。A0提示用户具体操作，不能代按回车然后伪造新增内容。环境无交互stdin时不要无限等待，转人工辅助。

该脚本验证记录/接力往返的工程证据；V4收益还需对照：3检查点（未执行、部分成果、阻塞）×2组（H人工交接、W Worket）×2次=12试验。每组相同目标执行环境、工具、文件快照与权限，不能A→B对A→C。基础往返也不能代替三种状态完整覆盖。

关键状态100%正确、非关键≥90%、无旧决定复活/覆盖已确认产物；交接准备+恢复+返工主动投入相对H下降≥30%才称明显收益。没有真人计时，只能报告信息/工程结果。

### V5 非原作者执行

3位未参与原始工作的合格执行者；你不在旁边补课。匹配新输入，普通交接/Worket交换顺序；先复述目标/边界/验收，再交付。必要的新业务决策不是失败，作者救场补旧知识单独计时。至少2/3不需内容性救场而完成合格交付，且双方合计投入下降。

机器人模拟“新人”只能调试材料，不能算3位真人。V3/V5可共用一次观察，但不能重复计独立样本。

## 11. 阶段 P5｜V6 真实使用观察（必须有人参与）

目标5次问题访谈、3—5人试用。A0/A2准备邀请文案、记录卡和数据分析，不未经允许联系任何人。

用户先真实激活：把确认资料用于新任务并达到交付节点；安装/生成定义不是激活。下一次任务出现时分类：未出现机会、失访、实验安排、创始人提醒、应用提醒、无提醒主动使用。

至少3位已激活者出现适配任务机会，其中至少2人不同日期主动再次使用并产生成果，才记初步行为信号。无机会/失访单列，不静默删分母。实验安排的第二次任务不计自然再次使用。H5由人核验，程序只按事实计算。

这阶段可以早于P4并行招募，但不能提前编造未来留存。

## 12. 程序验收与人工验收：不得互相代签

### 12.1 程序验收（A1/A2跑，A3审）

- 工程：真实测试退出码、覆盖清单、数据库/版本/事件/权限断言；实际UI截图与网络/桥接日志。
- 机制：候选与引用可定位、新旧实例隔离、固定版本、输出文件存在且内容哈希一致。
- 实验：计划与实跑逐项核对，失败/重试/缺失全部在账；同一版本、同一模型/预算、环境重置、参考隔离。
- 数据：时间不丢初次成本，未知不是0，分母为任务/人而非requirement数，边界安全通过不冒充交付成功。
- 报告：每个数字可复算，每条关键结论能定位到具体run、原始产物与人评。

### 12.2 人工验收（用户/任务拥有者/合格评价者）

- 要求是否真实表达过、是否属于这一类工作、是否已经过时；作者脑中的未表达品味不追溯惩罚模型。
- 哪些候选可以发布；人工新增/修正是否完整记录。
- 隐去组名的成果能否实际交付；事实/范围/品牌/内容质量是否满足冻结规则。
- 真实操作时间、支持次数、下一次任务机会与采用行为。
- 脱敏后哪些证据允许对外，以及应该描述成收益、限制还是尚待验证。

程序看到“human_decision=approved”只能检查记录存在，不能证明真的是用户作出的决定。A3抽查原始确认消息/签字记录，Agent不得自填。

## 15. runner 退出码与缺失数据契约（由A2实现）

对 smoke/live-extract/reuse/handoff 等执行阶段，采用：0=该阶段已执行且所要求的程序断言通过；10=已执行失败；20=环境/配置/授权阻断；30=等待人类确认；64=参数/清单错误。阶段0退出不自动让V2“人工净收益”通过，价值状态单列。

report/prepare阶段的0只说明产物生成成功。辅助 `audit_evidence.py` 的0只说明账本结构与证据文件完整，失败/受阻记录本身也可以完整。禁止上层把这些0统一翻译成“Worket有用”。

若只完成一部分，输出已执行部分及其证据、失败与未执行列表；不要因一个分支缺权限抹掉其他部分，也不要把未执行的项从报告移除。
