# Worket 价值验证协议 v1

编制日期：2026-09-17  
建议执行窗口：2026-09-18—2026-10-01  
状态：实验设计与记录模板；尚未执行，不含任何实测结果。  
用途：验证当前记录、工作要求提炼、复用与接续价值；为邀请制试用和投资沟通建立可复查证据。不验证完整企业治理平台或产品市场匹配。

## 1. 本轮需要回答的核心问题

在明确的一类工作里，Worket 能否让用户以不降低交付质量的方式，减少再次说明、确认、纠正、交接和维护的**总人工投入**？这种收益能否离开创始人的亲自操作，出现在别人的真实工作中？

把三个不同结论分开：

- 信息能够被提炼并保存，是功能与机制证据。
- 信息用于新任务或交接后，带来净收益，是使用价值证据。
- 用户主动再用、协作者采用、付费，是采用和商业证据。

前一种不能替代后一种。接续同一 WorkInstance 不能替代复用 Definition 创建新实例；导出成功也不能替代跨执行环境工作成功。

所有数字门槛都是本项目**建议预注册的内部决策线**，不是行业标准、统计显著性门槛或已实现指标。可在正式运行前依据任务规模调整；冻结后不得为通过测试而降低标准。

## 2. 范围与角色

### 2.1 第一类工作

优先选择：从新素材制作可交给视频制作执行者的内容方案／视频 brief。只选当前执行环境能够完成的交付物，不默认已经接入全部视频工具。

选择理由是与你已有的实际问题相连：风格、参考、修改意见、禁止事项和验收判断在执行中逐渐形成。这里是场景选择，不是“该人群已验证有需求”的结论。

筛选条件：任务真实、可授权；两周内有多次同类工作机会；有可说明的质量标准；能够与现行做法比较。不要挑本来十秒就能重写的任务，也不要只挑人为设计得特别适合 Worket 的任务。纳入一个低复用价值或不适合套用旧定义的边界案例。

同一轮先选一个任务家族。另一个任务家族应独立汇报，不能混在一起形成一个漂亮平均值。

### 2.2 角色

| 角色 | 工作 | 约束 |
|---|---|---|
| 实验负责人 | 冻结问题、任务、阈值、版本、顺序与分母 | 可以是创始人，但不得独自挑选所有成功案例并独自评分 |
| 原作者／任务拥有者 | 授权历史资料，确认真实要求，准备基线 | 隐藏的、从未表达过的要求不能算模型本应提取的内容 |
| 执行者 | 使用固定环境完成任务 | 不私下拿到其他组答案；全部补充说明留痕 |
| 评价者 | 按事先标准检查结果与来源 | 尽可能不知道使用的是哪一组；不读系统宣传文案 |
| 工程负责人 | 记录版本、运行日志与故障 | 不在正式实验中无记录地修代码、改数据库或补结果 |

“非创始人”“同公司同事”“独立外部用户”分别标记。同事不自动等于外部客户。只有一位评分者时如实说明，不声称独立双盲。

## 3. 统一实验规则

### 3.1 三个主对照

| 组 | 做法 | 公平条件 |
|---|---|---|
| A：现行最佳办法 | 用户已有的 Skill、模板、项目规则、原生历史、工作文档或实际组合 | 真实已有的好办法必须保留；不能故意退化成一句空白提示词 |
| B：普通但认真制作的总结 | 从同一历史资料整理目标、稳定要求、例外、进度和来源 | 允许用户核对、修改；记录成本；不使用刻意弱化的“概括一下” |
| C：Worket | 从同一资料提炼候选内容，经用户确认，选择版本，用于新实例／交接 | 自动提炼、人工新增、人工纠正分别留痕；全部产品操作成本计入 |

在揭示 C 的结果前，让用户准备 A，防止把 Worket 的结果无偿送给基线。不要禁止基线使用它实际拥有的良好功能。已有 Skill 的过去成本是沉没成本，不为了让 Worket 好看而重新计费；本次为比较而新增的整理工作则记录。

各组都能取得相同的授权历史源、新输入、必要文件与执行工具。各自如何组织和调用资料，是实验变量。不要强行截断基线历史，也不要人为要求完全相同的输入 token 数；设相同的合理资源上限并报告实际使用量。原生上下文超过限制时，使用用户正常的处理方式并记录，不静默裁掉关键内容。

### 3.2 先固定第二层，再改变第三层

本轮核心归因位于交互／工作层：先固定模型、Agent/harness、工具、权限与任务输入，只改变是否使用 Worket 组织的工作信息。这样测的是 Worket 的增量，而不是更换更强模型的增量。

V4 才单独改变执行环境。在每个迁移方向内仍固定目标环境，比较普通交接与 Worket 交接。不能拿 A→B 的 Worket 结果和 A→C 的普通交接结果比较。

### 3.3 防止泄漏与顺序效应

先封存用于生成定义的历史材料，再封存新任务。验证新输入及其答案不得用于定义优化。若查看失败结果后修改提示词／定义，该案例进入开发回归集，新版本需补未见过的测试。

机器试验可以用完全相同的新输入，但每次需重置会话、文件状态及可控缓存，禁止上一轮答案通过文件或历史泄漏。保留原生对照所需的既有历史，但排除本轮新任务答案；控制不了隐藏状态时注明限制。

真人不能反复做同一道题再把熟悉效应算给 Worket：给相似难度的不同新任务，随机分配 A/C 并交叉顺序，评分者尽量隐藏组名。小样本不能保证任务完全等价，个体差异和排序限制应进入报告。

### 3.4 评分与失败

先由任务拥有者写出约 8—12 条可观察验收条件，并标注哪些是硬约束。可采用 100 分软评分，但严重事实错误、错误对象／旧客户数据、未授权行为、关键要求违背具有否决效力。

只检查历史资料或本次任务中可获知的要求。隐含在作者脑中、从未表达的品味不能作为事后扣分依据；作者后来补充应记录为新增信息，不算自动提炼成功。

机器检查适合核对文件存在、版本、字段、链接、明确禁止内容；人工判断适合核对含义、适用范围与可交付性。LLM 可辅助预评分，但必须对照人工样本校准，不能让同一模型自称“输出很好”就通过。

正式试验统一重复次数，默认每个机器条件 2 次；资源允许时全部条件升至 3 次，不只重跑输掉的一组。保留所有开始的运行，包括报错、超时、放弃和救场。重试作为新 trial，记录前一次失败。

### 3.5 结果状态

- **通过**：按冻结条件达到该项门槛。
- **未通过**：有足够的该项观察，未达到门槛或触发阻断项。
- **证据不足**：没有真实任务机会、样本太少、关键记录缺失或功能尚未实现。

“证据不足”不是通过；也不自动证明产品没价值。方法人工可行不等于产品自动实现，人工代做必须标记为 assisted／concierge。

## 4. 核心成本与收益口径

对方案 p 的 n 次新工作：

`T_p(n) = S_p + Σ(选择与准备 + 补充说明 + 人工执行 + 纠正返工 + 结果复核 + 本次维护)_p,j`

S 包含本次新增的安装／接入、初次整理、定义审阅修订与必要学习成本。原工作本来就要发生且各组完全共享的交付成本可以排除，但必须明确；为了 Worket 特意补的记录不能排除。不得把研究访谈、实验评分这类纯研究成本误算成用户日常成本。

分别记录：用户主动投入分钟数、等待时间、墙钟交付时间、模型调用费用与币种、创始人／开发者支持时间。不同人的人工时间求和；等待与人工可能重叠，不能简单相加。没有数据写 null／未测，不写 0。

`观察期净节省 = T_A(n) - T_C(n)`

只有质量门槛不劣且净节省大于零时，才可称该观察期省了人工投入。不能因为失败后提前退出导致时间少，就记为“提效”。报告全部分配任务的完成率和失败；仅对成功案例计算的时间必须标注为条件结果。

初次投入未回收时，可以报告后续单次改善，但不能称“全流程净收益已证实”。

**纯算术例子，非 Worket 数据：**额外整理花 12 分钟，每次后续少花 6 分钟，第 2 次打平，第 3 次才净省 6 分钟。现实中规则更新、任务难度、用户熟悉度会变化；预计回本次数不是已观察回本。

本轮不按单条 requirement 或模型 trial 冒充独立用户样本。分别报告工作家族数、历史实例数、新任务数、用户数、机器运行数。小样本以逐例结果、中位数、范围和失败解释为主，不声称普遍增益或统计显著。

## 5. V1｜可信提炼：留下的是知识，还是噪声？

### 假设

Worket 能从真实协作中提炼有来源、有适用范围的工作要求，并把稳定要求与一次性信息、进度、被否定提案区分开。

### 材料

先准备 6 份真实历史记录：2 份调试，4 份封存评估。尽量来自至少 2 位作者；只有一个作者时标记单作者。另建合成边界片段，用于覆盖历史样本未包含的危险错误，不能合并宣传为真实用户样本。

评价者先于 Worket 输出标记每条原子信息：稳定要求、实例参数、当前状态／检查点、临时例外、已否定／已替代意见、尚未确认的推测。每条标注来源位置、有效时间、适用范围及关键程度，去除重复表达。

### 执行

对封存记录生成候选定义，保存未经修改的版本；按参考标注评分；用户审阅并确认，保存差异与主动用时；再次评分确认版本。

用户新写出的要求标记 `user_added` 并附确认时间。它可以是有效知识，但不是“自动从原文提炼”的命中。

### 指标与建议门槛

| 指标 | 算法／判断 | 建议决策线 |
|---|---|---|
| 原始候选可信率 | 有证据且含义、状态、范围均正确的去重候选 / 全部去重候选 | ≥95%，同时报告分子／分母 |
| 关键覆盖率 | 正确提炼的关键稳定要求 / 人工标注关键稳定要求 | ≥90%；空输出不能凭高可信率过关 |
| 确认版安全 | 关键错引、无根据的已确认约束、旧实例事实泄漏 | 0 个严重问题，否则不能发布该定义 |
| 修订负担 | 审阅分钟数、新增／删除／修订数量、查来源次数 | 全计入 V2，不用修完后的准确率掩盖成本 |

没有确定参考的项单列为 unknown，不用模型自报 confidence 代替判断。评价者有分歧时保留分歧与裁定；评分规则变更后须对全部组重评分。

### 失败意味着什么

覆盖少但正确：提炼不够；内容多但真假混杂：精度或状态／范围建模有问题；必须大幅重写才可靠：可能只是把写说明变成改说明。V1 通过仍不证明下一次交付更好。

### 留存证据

授权原文快照、参考标注、原始候选、确认版、修改差异、逐条来源、人工用时和版本。

## 6. V2｜新实例复用：下一次是否真的更省事？【主实验】

### 假设

固定模型与执行环境后，Worket 在未见过的新输入上，相比用户现行最佳方法，可以在质量不劣的条件下降低总人工投入。

### 机器阶段：测信息是否改善交付

从同一个任务家族准备 6 个新输入，包含常规变化和适用范围变化。相同输入分别使用 A/B/C，各运行 2 次，共 36 次机器运行。生成与确认定义所用材料不得包含这 6 个输入的答案。

先检查第一轮无需人工纠正的成果；随后有必要时按预定停止条件继续。第一轮通过率与修正后通过率分开。机器阶段可测遗漏、旧事实污染、token、等待与输出质量，不能替代真人计时宣称人工提效。

必须包括：同类新素材；同类但不同对象；新 brief 明确覆写旧默认；本来就不应套用此定义的边界输入。正确选择“不适用／需要澄清”应在边界案例中算正确行为，而不是强制所有任务自动完成。

### 真人阶段：测真实总成本

建议 3 位非创始人，各做一对相似难度的新任务：一个用 A，一个用 C，随机任务分配并交叉顺序，共 6 次真实工作。用户先制作／确认 A，避免看过 C 后复制其内容。不同人的定义与任务按本人场景绑定，不假定品牌约束能跨所有用户共享。

这是最低方向性样本，不是充分统计样本。外部试用的自然回访另在 V6 记录；被安排的这 6 次实验不能冒充主动再次使用。

条件允许，再观察到该定义的第 2／3 次实际复用以测量成本回收。没有观察到，不应把外推结果写成事实。

### 建议门槛

C 的最终硬约束通过率不低于 A；盲评质量中位差不低于 A 5 分以上（100 分制，首轮前冻结）；没有新增严重旧数据污染或未授权行为。

在完整观察周期、计入新增整理确认与维护成本之后，C 的总人工投入相对 A 下降至少 20%，且至少 2/3 参与者呈同向净收益。报告逐人值，不能让一个大收益掩盖其他人反而更费事。对很小的时间差保留计时误差，不机械宣布通过。

与 B 的比较同样完整公开：如果普通总结质量与成本已经相当或更好，不能说结构化 Work Definition 的增量已经被证明，需要结合 V3 检查是否仅有产品操作层收益。

### 失败意味着什么

只有机器输出提高，用户总时间未下降：可能是质量工具而非省事工具；只在原任务有效：可能记住答案，没有提炼通用要求；靠后期补写大量规则才成功：要审查新信息贡献，不算自动沉淀的功劳。

## 7. V3｜拿掉 Worket：是不是一份好 Skill 就够了？

### 假设

Worket 的采集、确认、检索、版本管理和调用流程，比人工维护一份同等内容的 Skill／Markdown 更低负担，而不只是多包了一层界面。

### 消融对照

C：完整 Worket 路径。
D：把同一份确认后的定义完整导出为 Skill／Markdown，允许用户使用自己的文件管理、原生项目规则和正常编辑办法。

两组信息内容相同，不能为了突出 Worket 故意删减 D 的来源、关键要求或说明。D 的格式需要目标环境正常可用；首次必要转换与维护时间计入。若不能导出，只能做人工复制内容的方法测试，并将“产品导出未实现”单独列明。

### 三步生命周期

先创建一次新工作；然后给予同一条真实的新要求，让两组更新自己的保存方式；第三次交给未参与维护的人，查找并使用正确的新版本。

最小先做一组完整三步序列，争取 3 组配对序列。与 V5 可以复用授权材料，但同一观察不能重复当成独立样本。

### 指标与建议门槛

比较从定位资料、确认适用范围、更新、绑定本次参数，到交付与归档的全部主动用时；另记错版本次数、找错源文件次数、手工复制错误、使用者理解成本。

在质量不劣和无新增版本错误的情况下，若完整生命周期主动时间下降 ≥20%，可形成产品操作增量的初步证据。只观察一次首次生成时，不宣称生命周期收益成立。

首次输出持平不是失败：信息相同，本就可能执行得一样。关键在“形成、维护、查找、用对”的成本。

### 失败后的正确决策

同等说明足以解决全部问题且维护更便宜：不要声称独立运行层已被证明。可以收敛为生成、维护、导出高质量工作说明的工具；重新检验这个更小产品能否独立收费。Worket 有用与 Worket 已有壁垒，是两件事。

## 8. V4｜跨执行者接力：保留状态是否减少重启成本？

### 假设

同一项工作在支持的两个执行环境之间接力，Worket 比最佳人工交接更少丢失关键状态、重复劳动和重新说明。

### 材料与配置

只用两边工具／权限都确实能完成的工作。在同一工作封存 3 类检查点：要求已确认但未执行；已有部分产物；发生阻塞并等待资料或决策。

每个检查点保存输入、已确认要求、产物实际路径与版本、当前状态、尚待完成事项及授权范围。先核验目标环境能力，不把目标本来不具备的工具算成语义迁移失败。

### 对照执行

H：用户最佳手工交接包＋必要文件。
W：Worket 交接包＋相同文件和访问条件。

固定同一迁移方向与目标环境。每个检查点、每组运行 2 次，最小 12 次机器运行。双方从相同快照起步。人工交接准备与 Worket 准备／确认成本都算入。

不要求原作者完全不能回答问题，但不能私下补救；内容性补充标记并计时。先要求接手者说明“已完成／未完成／当前有效要求／下一步／缺失依赖”，再实际继续工作。

### 建议门槛

全部关键状态正确接续；非关键状态正确率 ≥90%；无旧决定复活、重复覆盖已确认产物或假报完成。准备交接＋恢复工作＋纠正返工的总主动投入相对 H 降低 ≥30%，才可说这些案例有明显接力收益。

产物不可访问、权限撤销、工具缺失另设负向测试。明确指出阻塞并提出所需条件算安全处理通过，不算“完成接力后的交付”。

保持同一个 WorkInstance ID 是工程条件，但不是用户收益；不能仅因 ID 未变就宣布该试验成功。A→B 成功也不代表支持所有 Agent、所有权限或隐藏运行态。

## 9. V5｜原作者不在：工作积累能否被别人使用？

### 假设

已经确认的工作要求能够脱离原作者记忆，由具备相应执行能力但不了解该工作历史的人使用。

### 执行

选择 3 位未参与原始工作的合格执行者。给他们新输入、正常所需工具和授权材料。对照用户正常交接资料与 Worket 保存的工作资料；真人使用不同但相近的新任务并交换顺序，避免先学会答案再测试另一组。

先让接手者用自己的话说明目标、边界、验收与不确定项，再实际交付。不应一上来讲解整个产品理念。原作者退出执行；如确需介入，记录介入理由与内容。必要的新业务决策不应被惩罚成“多问一次”，更不能鼓励 Agent 编答案。

加入一条新约束或旧约束撤销，观察接手者能否使用当前版本，而不是沿用作者上次的私人习惯或旧结论。

### 建议门槛

至少 2/3 接手者能在无需原作者内容性救场的情况下完成合格交付；质量不差于正常交接；交接双方合计主动时间有下降。错误沿用旧范围、旧客户事实或临时授权属于严重失败。

如果正常交接一样容易，不能把别人完成任务全归功于 Worket。要展示相对减少的准备／询问／返工，或确实减少的关键遗漏。

### 证据边界

通过后只能说这些工作要求开始可跨人复用；不能说复制了专家全部经验，更不能推出企业会为组织治理付费。

## 10. V6｜自然再次使用：用户会不会主动回来？

### 假设

Worket 在真实重复工作中有足够价值，使用户在出现下一次合适任务时再次选择它，而不只是在配合创始人做测试。

### 招募与第一天

目标先完成 5 次问题访谈，邀请 3—5 位适配当前环境且有重复工作的人试用。优先找能展示最近真实案例的人，询问旧办法、重复频率、实际投入与下次机会，而不是“你会不会用一个这样的产品”。

在一次正常上手之后记录已激活用户：成功将一份确认后的资料用于真实新工作并达到交付节点。安装、打开、生成一份未被使用的定义不算完成价值闭环。

### 观察与分类

在试用可用窗口内记录其下一次真实任务机会、是否采用 Worket、是否完成、是否需要帮助。实验强制任务、创始人提醒、应用正常提醒、主动无提醒使用分别标记。

研究补偿不得与好评或重复使用次数绑定。不要关闭用户原有工具或扣住他们的资料来制造依赖。

复用率分母为“已有一次真实激活，且在观察期出现下一次适配任务机会的用户”。没有机会与失访分别列出，不能从分母静默剔除让数字好看。额外报告全部招募／安装／激活人数。

### 建议门槛

当至少 3 名激活者有下一次适配任务机会时，争取至少 2 人不靠创始人提醒，主动使用 Worket 处理不同日期的新实例并产生实际成果。这是方向信号，不是长期留存或 PMF。

不足 3 人有机会时记证据不足，不声称留存率可靠。用户只打开旧记录、没有完成新工作，另记为浏览行为。

### 更强但非本轮必须的信号

主动带入新任务家族、邀请协作者、要求维护共享定义；具备真实责任人、任务和开始日期的试点安排；真实付款。试点不等于付款，礼貌报价认可不等于购买。涉及收费测试时先明确真实条款和产品边界，不能虚构稀缺或可交付能力。

## 11. V7｜信任与失败边界：能否放心记录、用错时能否及时停？

本项是试用发布门槛，不是差异化收益证据。当前产品实际行为应在固定版本上核验，不能依据旧说明文件推测已经通过。

使用脱敏／虚构测试资料，在可控环境检查：

| 测试 | 通过条件 |
|---|---|
| 未选择的会话 | 不被采集；不能串到另一项工作 |
| 停止记录 | 后续事件不继续进入该绑定；提示与实际一致 |
| 采集、提炼、改进样本的用途开关 | 各用途真实数据流与已告知授权一致；关闭改进不被误说成所有云功能都关闭 |
| 导出与离开 | 可导出内容、引用、版本及不可导出的部分清楚；不声称导出了隐藏运行态 |
| 删除与保留 | 实际删除范围、云端／备份保留限制与说明相符；没做完不得显示已全部删除 |
| 重启与恢复 | 已确认保存的定义／状态不丢失；不会混淆历史版与当前版 |
| 失效链接／无权限附件 | 明确不可用，不虚构已读内容或假报交付完成 |
| 提炼超时／执行失败 | 可见失败、保留原始工作；不生成伪造完成状态或证据 |

至少固定场景连续完成 3 次端到端运行，记录版本和全部失败。连续 3 次通过只说明该固定场景通过，不代表生产级零故障。

未授权记录／外发、跨工作敏感数据污染、虚构来源、破坏原文件等严重问题必须阻断相关功能的外部试用。安全负向测试通过不计为一项成功交付。

## 12. 最小执行规模与优先级

| 项目 | 建议最小规模 | 属性 |
|---|---|---|
| V1 | 6 份真实历史：2 调试＋4 封存；合成边界另记 | 核心 |
| V2 机器阶段 | 6 新输入 × 3 组 × 2 次 = 36 次 | 核心；36 次不是 36 个用户 |
| V2 真人阶段 | 3 人 × 2 个不同匹配任务 = 6 次真实执行 | 核心；被安排实验不计自然留存 |
| V3 | 1 组完整三步生命周期，争取 3 组配对 | 差异化，优先于扩功能 |
| V4 | 3 检查点 × 2 组 × 2 次 = 12 次 | 计划宣传接力时必须做 |
| V5 | 3 位合格非原作者 | 计划宣传跨人复用时必须做 |
| V6 | 5 次访谈；3—5 人试用；至少 3 人有复用机会时判门槛 | 核心；时间不可强行制造 |
| V7 | 8 类边界＋3 次固定闭环 | 发布阻断项 |

这些规模用于方向验证，不是统计功效计算。任务多样性和外部用户的重要性不能由更多机器重跑替代。

时间不足时先保 V1/V2/V6/V7。V3 至少做一次可信消融；V4/V5 未测就不对外声称已验证。不要为了“七项全绿”选简单题、漏掉失败或缩小分母。

## 15. 每项案例应保存的证据包

每个 case 下至少保留：任务卡、授权与数据范围、冻结 source/input 快照或受控引用、定义版本与确认差异、基线材料、执行环境清单、全部试验日志、初稿和最终成果、评分与分歧、分阶段人工时间、失败与救场说明。

唯一 ID 区分：`case_id`（任务）、`run_id`（一次尝试）、`participant_id`（人）、`definition_id/version`（定义）、`instance_id`（本次工作）。同一事实可以用于不同分析，但不要重复算独立样本。

有敏感数据的完整证据包不要直接发投资人。对外用脱敏版本并取得授权；保留受控原始证据用于核查。
