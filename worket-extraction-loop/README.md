# Worket 提取审计与优化循环 v3

日期：2026-09-18。用途：在最终价值验证之前，先确认并改善实际提取链路。不是已完成的产品升级，也不是最终验收通过报告。

## 先读什么

1. `00_CURRENT_IMPLEMENTATION_AUDIT.md`：本次核对到的代码、已执行反例、证据边界。
2. `01_OPTIMIZATION_LOOP.md`：交给本地 Codex 的主执行协议；四角色、分阶段、有限迭代、验收与停止规则。
3. `02_CODEX_START.md`：可以直接粘贴给 Codex 的启动指令。
4. `03_HUMAN_ACTIONS.md`：你要提供的材料、必须人工确认的事项。

`reference/` 保留上一版最终价值验证协议与执行计划。v3 增加前置优化循环，不降低 v1/v2 的质量、授权、人工确认或证据要求。进入最终阶段前重新核对本地实际平台、源码与脚本，不固定在旧 Mac 路径。

## 本包已经做了什么

通过 GitHub 连接器重新读取 main 与实验分支，查看提取、校验、定义发布和新实例代码。容器无法完整 git clone；在 Linux 中只对三个按 Git blob SHA 核对的原始模块做了 12 项隔离诊断：3 项控制通过、8 项行为/防线缺口复现、1 项明确容量限制。详见 `results/module-probes.json`。

全部诊断采用合成输入及 mock provider。真实模型调用数为 0；未运行完整仓库测试、真实 Electron UI、数据库端到端或外部用户试验。没有更改 GitHub、用户本地代码、生产服务、账号或数据。

## 包内代码的性质

- `audit-snapshot/` 是三个已审计公开源码文件及一个编译输出，不是完整 Worket 仓库，不是待优化的目标。
- `probes/audit-probes.mjs` 是本次诊断复现器，刻意检验“旧代码会接受哪些错误”。其退出码 0 **不表示产品质量通过**。
- `templates/` 是待填配置、迭代记录、缺陷任务和冻结清单。不存在一个已经完成的新自动优化 CLI；Codex 必须复用/扩展实际仓库测试与执行器。
- `reference/` 只是执行依据；其历史状态不能替代本轮实际测试。

将整个 `worket-extraction-loop/` 放在 Worket 仓库根目录后，读取 `02_CODEX_START.md`。不要覆盖项目的 AGENTS.md、全局配置或未提交更改。真实记录、gold、费用与审批放在仓库外私有目录，不默认提交到公开仓库。
