# 粘贴给本地 Codex

先把本包 `worket-extraction-loop/` 放进 Worket 仓库根目录。以下任务开始后，你只对接总控；总控负责其他Agent的分工。

```text
执行 worket-extraction-loop/01_OPTIMIZATION_LOOP.md。

先读根AGENTS.md、CONTEXT.md，再读00_CURRENT_IMPLEMENTATION_AUDIT.md。
参考reference/中的v2最终验证计划，但现在先做v3前置优化循环，
不要直接消耗封存final语料。

你是A0总控。组织A1算法/工程、A2测试/评估、A3独立审计，
加你4个长期角色；没有子Agent能力时按角色契约串行并注明。
先核验实际本地HEAD、GitHub分支和dirty状态，不重置或覆盖我的工作。

先建立当前版本基线。把报告G01–G08转成针对真实工作树的回归，
区分确定性结构校验、语义人工判断和本地WorkState分类。
本包audit-snapshot是历史审计快照，不能修改它来冒充修复产品。
诊断脚本退出0表示反例复现完成，不表示产品合格。

在隔离分支中，先写会失败的期望行为测试，再做最小修复。
优先：中间结果校验、替代链合法性、原文依据、
最终条目与有效可复用要求的映射、历史输入默认值污染。
不要重写Work对象体系；不要把LLMWiki架构当成已批准Worket设计。

每轮只改一个主要失败族，跑旧回归+dev语义对照+必要的开发复用，
由A3审查。默认最多3轮，连续2轮无增益或达到预算就停止汇报。
不要无限修到绿色；不要删失败、改gold或降低验收门槛。

真实资料读取/外发、模型费用、定义发布、人评、桌面操作、
schema迁移和最终解封按H0–H5取得实际人的决定。
没有授权/材料则标BLOCKED，其他离线工作继续。
人工新增要求、真实操作时间和自然再使用不能由Agent伪造。

先交付environment.json、baseline、gap-matrix和HUMAN_INBOX.md。
候选达到FINAL_VALIDATION_READY后，给我一页就绪卡确认，
再开启未见过的final。看过并用于修复的final必须退役并换新，
不能反复调同一批题后说已经通过独立验证。
```

## 你的第一次输入不必复杂

提供一项你拥有且能授权的真实工作及其完整对话、关键附件/最终产物，以及现行最好复用办法。允许的服务/用途/费用单独写清楚。不需要你写JSON或组织Agent；总控整理后请你确认。

如果你暂时没有准备真实资料，仍可执行仓库盘点、离线回归和合成边界。没有live结果时不得说算法质量已验证。
