# 产品定义：工作记录、接力与沉淀复用

v0.1.5 已正式发布，生产后台已同步，自动工作状态准备接口已启用。公网健康与认证能力检查通过，见 [发布验收](releases/v0.1.5-verification.md)。

## 沉淀输入过滤（2026-09-24，本地实现）

沉淀保留完整原始记录，在发送前固定一份分析输入：用户消息、Agent 回复、验收与所选资料保留；明确的实现代码读取与写入正文省略，受支持的成功测试输出可保留原文结果段。同一次工具调用的重复输出可以合并，不同调用即使输出相同仍保留。用户提及的文件、规范文档、失败记录及未知工具内容保守保留。

长消息按原文位置分块，汇总接收提取候选和经过核验的原文片段，避免再次带回全部历史。过滤不等于全文已分析；原始范围与实际分析范围分别计数。旧失败任务重试产生独立快照，旧任务和原文不被覆盖；生成的候选仍需用户审阅。

本轮本地失败快照重放已通过输入及分块检查；真实模型重测仍等待上传授权，尚未更新生产后台或已安装客户端。详见 [验证记录](acceptance/distillation-input-filtering.md)。

## 面板信息精简（2026-09-23）

最近活动移除常驻记录说明，历史聊天入口使用带悬停提示的 history 图标。工作详情把执行者放在“返回列表”同一行右侧，次级操作入口使用三个点；未准备时不再显示“交接时自动准备工作状态”，实际处理进度与状态缺口仍可见。

右上角应用菜单使用三道横线，与工作详情的三点操作菜单区分。“Worket 服务”和“改进数据”使用左上角返回箭头，按“改进数据 → Worket 服务 → 原工作面板”逐级返回；Esc 同样返回上一级。用户确认后，本批已统一更新并重启本机应用，见 [安装验收](acceptance/panel-navigation.md)。

## 点击即开始沉淀（2026-09-23）

点击工作详情的“沉淀”或列表的“沉淀所选”后，立即固定所选记录的当前快照并开始后台处理，不再进入“确认沉淀范围”页面。界面直接显示后台进度；同一快照仍在处理时重复点击复用该任务。生成完成后仍需审阅候选，再保存为可复用定义。

默认仅包含记录与附件信息。需要额外分析附件正文时，从工作详情“更多 → 含附件沉淀”单独选择文件及用途。参与改进沿用“Worket 服务 → 改进数据”的持久设置；模型处理说明移至服务设置，不在每次沉淀前重复确认。该变更已随用户确认后的面板导航批次安装。

## 后台工作理解与统一状态（2026-09-23）

记录立即开始，并在后台准备整体目标、阶段、有效要求、替代关系、成果依据和下一步。后续可见记录变化在安静 30 秒后合批更新；交接只需选择执行者，系统等待已有任务并检查最新性，有效结果直接复用。界面不提供独立“整理”按钮或“先整理”复选框。首次记录或交接说明模型处理范围：所选工作的已有及后续可见记录、状态线索和材料版本，不额外读取附件正文。升级不会自动开启历史记录的模型处理；已有记录可在继续记录或交接时开启。

界面、工作包导出和 MCP 共用同一份通过出处校验的接续状态。新来源、人工编辑或材料版本变化后使旧状态失效；记录中自动准备，交接前再次核对。尚未准备、失败或超限时保留可核对的来源线索，不能把旧待办顺序或 Agent 完成声明当成已核实进度。普通本地提取不再截断第 8 条之后的要求；明确否定完成的语句不进入完成声明。

整理保持当前 workId，不发布定义；沉淀仍负责人工确认后的未来复用。用户在 Worket 内进行的逐项验收作为带交付物 ID 与 hash 的事件进入共同证据。模型判断仍可能出错，结构与引用校验不等于语义准确率。单次上限为 80,000 JSON 字符，超出时明确显示范围缺口，不自动上传更多内容。服务失败不反复轮询调用模型；交接时可重试并保留带缺口说明的原始证据。验收见 [工作接续](acceptance/work-continuity.md) 与 [自动准备](acceptance/automatic-work-preparation.md)。

## 统一交接启动内容（2026-09-23）

Codex、WorkBuddy、ZCode、Antigravity 使用同一份应用层生成的交接指令，请求 v3 当前阶段上下文；适配器只处理链接或剪贴板传输。打开应用仍保持待确认，收到目标会话与本次读取证据后才确认接手。

## 规范修订的审阅范围（2026-09-23）

更新规范文件中的一条要求时，无关输入和其他已确认事项继续保留；修改的条款及其依赖关系仍需复核，减少重复确认。见 [规格](specs/document-revision-review.md) 与 [验收](acceptance/document-revision-review.md)。

## 规范文件的部分采纳（2026-09-23）

已用真实模型与桌面回放验证：文件选作规范后，聊天明确限定的条款采纳范围仍生效；未采纳相邻条款和本次例外不会进入新实例通用规则。既有技能的一次绑定与规范重复绑定分别处理。见 [验收](acceptance/document-adoption.md)。

## 组合技能的固定目录（2026-09-23）

同一约定中明确选择的多个技能，现在保留原目录名放入共同目录，支持彼此的相对路径引用。升级依赖后新实例使用新版本，旧实例保持原版本；同名不同内容须解决后才能保存。不自动收集其他技能或安装工具。见 [规格](specs/combined-skills.md) 与 [验收](acceptance/combined-skills.md)。

## 整体采纳中的局部边界（2026-09-23）

整体赞同和后续纠正按用户明确限定的范围提炼；新增两例真实模型试验验证保留长期安全区/来源、排除临时配色/尺寸。现有实现已通过，不因检查器误报改动产品逻辑。见 [验收](acceptance/bounded-adoption.md)。

## 草稿资料与修订恢复（2026-09-23）

暂存成功后结束当前未保存编辑的撤销记录，避免撤销方法时意外重新读取原件。失败时保留撤销；成功后仍可继续编辑和明确更换资料。

编辑约定时，删除同名方法不再清空已经选择的资料或技能；不同栏位独立处理。

用户选择的固定资料和技能在暂存时固定版本，关闭或重启继续恢复；原件变化不影响发布。手动修订继续打开同一基准版本的未发布草稿，避免重复选择和修订内容丢失。见 [规格](specs/draft-materials.md) 与 [验收](acceptance/draft-materials.md)。

## 范围提升与冗余关系（2026-09-23）

重复次数不自动产生长期授权。本轮补充重试转述、多个本次特例、明确提升为通用要求的真实试验；发现模型用两个字段重复同一关系使正确候选无法审阅，现由后台入口合并完全一致的关系表达。 证据见 [验收](acceptance/repetition-evolution.md)。

## 候选来源变化审阅（2026-09-23）

候选审阅对照提交时的聊天原文与本地最新记录；修订、待复核或缺失时须明确决定是否仍采用当前候选，发布前再次核对。提交快照和已发布实例保持；新增未选消息不增加确认。 详见 [规格](specs/source-review.md) 与 [验收](acceptance/source-review.md)。

## 2026-09-23：取消强制、禁止与本次豁免

增量比较明确区分“以后可选”“以后禁止”“仅本次豁免”。已用新合成真实模型链路验证：取消强制后新实例不再要求原义务，禁止产生相反的执行规则，本次豁免不改变通用版本；旧实例和原验收版本保持。

修复了模型把“所有以后工作”误写成额外适用条件导致替代校验失败的问题。真正限定平台等条件仍保留，范围校验没有放宽。来源、失败、测试误报和收费调用均见 [验收](acceptance/obligation-evolution.md)；不能据此宣称普遍语义准确或实际视频已交付。

## 2026-09-23：恢复原版本的固定资料

已沉淀定义可“检查与恢复固定资料”，工作详情的“更多 → 修复固定资料”覆盖约定资料、技能、本次已固定输入和参考。选择文件/技能目录后核对原版本完整 hash；错误版本拒绝，正确版本可恢复缺失或损坏副本。恢复不会发布新约定、改变实例输入或复制来源授权；同 hash 共享资料恢复后，依赖它的历史实例也可继续校验使用。

“本次文件”仍用于主动更换输入，重新选择相同原文件也可修复损坏。无历史 hash 的旧输入仍须走明确重选，不能猜测原版本。不会自动读取原路径、安装依赖或上传所选正文。见 [恢复验收](acceptance/material-recovery.md)。

## 2026-09-23：无新消息时停止重复扫描

已授权的改进记录在没有新来源时，不再重复加载完整工作档案或逐条尝试排队。已保存检查点跨重启生效，归档、停止记录、删除与授权到期仍检查；新修订、来源缺失及恢复继续同步。局部合成量测和真实桌面链路见 [验收](acceptance/recording-idle.md)，不能据此推算整个应用耗时或真实用户节时。

## 2026-09-23：每次工作的文件版本

从约定创建工作时，本次 FILE 输入和主动选择的参考案例保存为实例独立副本，保留文件名及 hash。原路径覆盖、移动或删除不会改变已创建工作；副本不可用时停止导出和 MCP 接手，不回退到原件。

进行中工作可通过“更多 → 本次文件”重新选择输入或移除参考；只修改本次工作，旧交接包和旧副本继续保留。修改后 Agent 必须重新读取当前工作包，界面才确认接手。旧版仅保存原路径的实例须明确重新选择文件，不能把今天的文件当成历史原件；参考可按原 hash 确认固定，已变化的参考需移除。永久删除实例清除它自己的副本。

连续实例的版本选择、特殊要求和文件隔离已通过真实桌面/MCP 合成验收；未新增外部 Agent 业务交付证据。详见 [实例文件验收](acceptance/instance-files.md)。

## 2026-09-23：识别具体采纳与背景来源

用户只采纳 Agent 提议的一部分时，约定保留被采纳要求；原建议作为背景引用，具体采纳语句作为直接依据，两者在审阅中区分显示。只有背景或泛泛的“好”不等于正式采纳；未决定项仍待审。同一问题的具体说明替代程序兜底提示，避免重复提问。来源身份、摘录和完整覆盖校验保持。已用新合成输入的真实模型链路及桌面回放验证平台条件、单次特批、跨实例冲突和部分采纳，失败及范围见 [语义验收](acceptance/contract-semantic-trials.md)。

## 2026-09-23：从后续交互更新约定

最新约定新增“从后续工作更新”：用户选择同一约定系列下的工作并确认范围，比较尚未确认过的新交互。未变的规则、输入角色和固定资料由程序保留；模型提出明确差异。审阅默认只看变化，可展开完整约定和重复/单次要求依据。

重复只增加可追溯依据，不增加相同版本；确认有效变化后新版本用于下一次实例。旧实例保留旧规则，过期基准不能覆盖新版本，来源删除仍脱敏。已通过一次两轮真实模型合成场景和桌面回放，未证明业务节时或普遍语义准确。现支持每份约定明确开启的持续比较：只处理开启后的已记录可见交互，稳定两分钟后合批、每 24 小时最多三次、有待审时暂停，确认后才生效。默认关闭，可随时停止；详见 [持续比较](specs/continuous-contract-evolution.md)。详见 [增量比较](specs/contract-incremental-evolution.md)。

2026-09-23 已启动 [持续优化计划](specs/worket-improvement-loop.md)。首轮固定可复现桌面回放与失败样本；回放通过证明已记录结果可走完产品链路，不代表新模型的语义质量或实际业务交付已经通过。

## 2026-09-22：工作约定的规则协调与规范引用

本轮实现 [working contract 通用机制](specs/working-contract-evolution-v2.md) 的首条完整链路：选择已授权交互与规范文本、审阅协调结果、保存定义、新建实例、导出有效工作包及逐项验收。验收证据与范围见 [本轮验收记录](acceptance/working-contract-v2.md)。

同义要求在执行包中只保留一个有效条目，多个来源仍可追溯。长期修正可以替代同组任一重复条目，整组旧要求退出执行；旧证据不会被当成新数值或新义务的依据。补充、长期替代、单次覆盖和未解冲突分别表达；范围不明或未采纳的建议不直接成为以后工作的要求。规则被去重后，验收仍引用保留下来的规则；无需为了验收再维护一份同义文字。

附件默认是参考。用户可将选中的文本设为规范或本次输入；只有实际读取且明确设为规范的条款可以成为文件规则。定义引用条款的固定内容版本，Worket 保存不可变快照；交付给 Agent 时展开选定条款，原件移动或删除不会让本地路径变成失效要求。非文本资料仍需另行传递。

手工修改规则和更新规范条款都会让受影响的直接及间接关系重新待审；旧确认不会沿用到改变后的要求。审阅页在保存时显示新增待定项，确认前不发布。

“修订”内可检查/采用规范的新版本，选择明确的条款范围；依赖该条款的关系转为待确认。确认后的新版本用于新实例，历史实例保持旧版本。新建实例时可输入“仅本次”的规则覆盖，长期定义保持不变。

范围：规范版本更新由用户主动选择，支持 UTF-8 Markdown/文本；没有自动文件监视或源文件写回。持续学习支持主动增量比较及明确开启范围内的自动触发；默认关闭，不自动发布。系统链路测试不等于新视频已制作完成，也不证明长期节时或泛化准确率。

## Production

### 用户是谁

在 Codex、WorkBuddy 等桌面 AI 应用中持续完成真实工作的个人用户。他们的工作散落在多轮 Prompt、Agent 回复、文件和操作中，并且不希望工作上下文被某个 Agent、应用、Skill 或会话锁定。

### 核心价值

用户在桌宠头顶展开的便利贴上点击“记录”后，系统识别前台 Codex 或 WorkBuddy 的工作上下文，把松散的 AI 协作过程记录并抽象为独立的 WorkInstance 和 WorkRecord。记录能够持续跨越不同 Executor 与 ExecutionEnvironment，并在需要时生成可直接接力的 Handoff Package。

产品核心是 Work Object：工作定义独立于执行者。事先定义工作的成本较高，因此从用户已有的真实工作记录进入。记录一方面支持继续同一项工作、交换 Agent，另一方面在用户主动选择“沉淀”后生成可复用的 WorkDefinition，用新输入开展下一次同类工作。未来传递给同事是独立的交接路径；并非所有工作都需要沉淀。

本次不新增 WorkPattern 实体；固定要求与参考方法先在工作定义中明确区分。术语见 [CONTEXT.md](../CONTEXT.md)。

### 产品原则

- 工作属于用户，不属于 Agent、应用、Skill 或会话；
- 用户主动触发后才记录；前台识别只读取应用身份和窗口标题，不读取或保存窗口内容；
- WorkInstance ID 是工作身份，对话 ID 只是来源引用；
- 原始档案与结构化 Work State 分离；
- 每条结构化信息必须可追溯到来源；
- 当前 Work State 的自动提取结果是可追溯的只读投影；用户回到来源对话修正事实后，由后台自动更新工作状态。下一阶段的 DefinitionDraft 可编辑，候选编辑不修改原工作状态和记录；
- 前台检测到的原始窗口标题不落盘；仅把来源接口返回的会话标题作为可追溯来源保存；
- 工作记录与定义本地为主。记录和交接动作确定该工作的后台模型处理范围；沉淀的来源选择与可选改进采集分别处理；
- 完整记录不等于把完整聊天塞进目标 Agent；
- WorkDefinition、WorkInstance、WorkRecord、Executor 和 ExecutionEpisode 必须分离；
- 用户可以取消记录：撤销该项工作的记录授权、停止后续同步，并清除 Worket 保存的本地副本。Worket 不提供删除外部应用原对话的权限或接口。

### 不做什么

- 不创建替用户自主执行工作的 Agent；下一阶段后台仅提供固定的模型分析流程；
- 不读取或推断 Agent 隐藏思维；
- 不持续记录所有桌面活动；
- 不自动判断并切分工作；
- MVP 不支持 Claude、ChatGPT 等其他 Adapter；
- MVP 不实现 WorkPattern 自动提炼与应用；
- 不做完整 Dashboard、工作库云同步、多人协作或全文件历史版本；托管后台只提供匿名用户身份、模型处理、额度和明确授权的改进上传，正式工作库及定义仍以本地为权威；
- 不把 Codex、WorkBuddy 专属字段放入核心 Work State。

### 用户体验路径

1. 用户在任一已接入执行者中开展工作，点击桌宠便利贴“记录”，或从面板“最近活动 / 记录沉睡工作”选择聊天。
2. 能明确识别会话时直接导入；无法定位当前聊天时打开该执行者的会话选择。无标题聊天可以手动选择，不把首次 Prompt 冒充应用标题。
3. 选中会话后立即导入已有可见历史，后续独立同步。Codex 和 WorkBuddy 都支持多项记录；发现聊天不自动保存内容。
4. 查看只读工作状态，按需刷新、从消息新建工作、完成、归档或取消记录。
5. 点击“交接”，选择可用执行者。系统准备工作包并打开目标应用；Codex 打开预填草稿，需要用户在 Codex 确认发送，WorkBuddy 使用新任务 Deep Link。
6. 真实提交带回本次交付标记后绑定目标会话，后续协作写回同一个 WorkRecord，每次切换建立独立执行片段。
7. 未确认交付可以取消并恢复原来源；取消不会关闭目标应用里的草稿，也不会终止已运行的外部任务。确认窗口同时解释好处与风险。
8. 完成或归档后停止同步；继续原工作恢复最后一个真实来源，也可以再次选择执行者交接。

最近活动合并各执行者的最新聊天；历史列表按执行者切换、搜索已加载的标题或项目并加载更早聊天。Codex 所选对话的正文按完整页读取，摘要页补齐后才记录；中途失败保留既有记录，不把部分历史作为成功导入。已有记录显示“打开记录”，重复选择不新建或自动恢复已完成工作。后台每轮同步结束五秒后继续同步所有 OPEN 的真实活动绑定；单个来源失败不影响其他来源，接口读取设置超时。面板刷新保留当前 Tab。正在生成的 Codex 回复待回合结束再记录；已保存来源的同 ID 内容修订追加留痕，当前状态与提炼使用有效版本，旧定义和历史交接包保留。详见 [来源修订](specs/source-revisions.md)。完整来源连续两次确认缺失后，停止自动采用该原文；第一次发现变化先待复核，暂停本记录交接与提炼。已确认约定保持不变，恢复原文可继续使用；从消息新建的起点缺失须重新选择范围。见 [来源缺失与恢复](specs/source-presence.md)。

### 设计原则如何回应以上要求

- **一致的品牌形象**：桌宠始终使用与 Dock 图标一致的圆土豆、右上便利贴和微笑表情；空闲时闭眼，其他状态睁眼，同时保留呼吸、搬运、提醒动画及对应体色和状态点，但任何状态都不改变笑嘴；
- **可发现的运行入口**：MVP 保留与桌宠一致的圆土豆加便利贴 Dock 图标；开发中固定使用 `scripts/run-latest.command` 启动当前源码；再次双击应用会把已有桌宠和侧边面板带回前台；
- **单次授权，不逐条打扰**：悬浮桌宠后点击便利贴即授权记录当前工作，不预览全部历史，也不要求逐项确认 Work State；
- **当前来源可见**：只在确认支持的前台聊天后显示窄气泡，标题直接使用来源应用生成的会话标题；
- **提取结果只读**：面板展示来源数量与提取结果，但不提供就地编辑或删除，避免投影与来源事实分叉；
- **执行者可以替换**：接入配置随 Worket 启动安装或更新，交接目标由可用执行者列表提供；
- **小而完整**：采用桌宠加轻量侧边面板，不建立复杂管理后台；
- **隐私可撤销**：完成和归档保留已有记录；取消记录撤销授权并清除本地副本；
- **来源清楚**：Work State 内容可以定位回原始消息，Codex 与 WorkBuddy 内容按 ExecutionEpisode 区分。

## 用户主动沉淀与复用（开发实现，真实验收待完成）

2026-09-08 决策替代此前“归档为工作副本”的暂定方向：将可复用工作保存的能力命名为“沉淀”，并作为下一阶段核心功能。归档是独立生命周期操作，后续再设计，入口应置于次级区域；历史 ARCHIVED 记录不能自动变成已沉淀定义。

用户可以选择一条或多条已记录工作，点击“开始沉淀”后才触发抽象。系统检查多条记录是否同类，提取输入、交付、约束、验收标准与参考方法，保留来源并提出待确认问题。用户修改、确认后保存定义版本，在“已沉淀”中查看和使用；原记录不自动完成、归档或删除。

复用时，用户提供本次输入，创建新 WorkInstance，交给受支持执行者。旧客户、结论、完成状态与临时授权不默认继承。首次定义的完整价值必须通过第二次真实执行验证；生成候选文本不能单独算作完成。

抽象默认走 Worket 后台提供的模型 API，使用 Worket 的服务端凭据与额度管理，不使用用户的 Codex 订阅额度或 Codex App Server 发起模型任务。现有采集层读取 Codex 聊天的 App Server 不在本次替换范围内。

所选材料会经过 Worket 后台及模型供应商处理，产品不能宣传“全程离线”或“内容不经过 Worket 服务器”。未另行授权时仅暂时处理内容，运行/费用元数据与正文分开；2026-09-09 已实现单次范围授权的产品改进样本与反馈采集，保存 90 天，具体边界见 Spec。用户无需配置模型供应商 API Key；服务登录与用量方案在公开发布前落定。

状态整理、工作定义抽象是两种能力：交换 Agent 和未来传递给同事不触发沉淀。沉淀服务失败不妨碍已有记录、定义和交接材料的本地使用。

### 本次沉淀开发交付

用户在记录上点击“沉淀”或多选来源后点击“沉淀所选”，直接开始后台处理。额外附件正文通过“更多 → 含附件沉淀”单独选择。候选按目的、输入、交付、约束、验收、方法和固定资料编辑，用户保存为不可覆盖的版本。固定资料存本地副本；复用时重新提供本次输入，默认不带旧成果。

约定支持独立的技能依赖：提取候选声明技能名称，审阅时由用户选择含 SKILL.md 的目录及其全部配套文件；发布固定目录版本，新实例只填新输入。缺失或损坏会阻断工作包生成，更新技能不改历史实例。技能外部的插件和运行环境仍需执行者核验。详见 [技能依赖](specs/skill-dependencies.md)。

MCP 读取当前工作时重新生成工作包，纳入后续状态与已记录产物，同时校验固定资料和本次文件输入。资料缺失或校验失败不会记为成功读取；历史交接包保持原样。具体执行者读取与最终业务交付仍须独立验收。

新工作先保存，显示“尚未交给执行者”；复制或导出不表示接手。目标执行者收到真实 Hook session 与本次交付标记后建立绑定，每次交接独立的 MCP 读取回执决定完整接手状态；仅查看不确认，新交接不会继承旧读取。详见 [交接回执](specs/delivery-receipts.md)。本次成果由用户关联，并逐项选择通过或需要修改；只有全部通过才完成。服务故障不影响已有定义的本地使用。

v0.1.4 的正式版内置 Worket 托管地址。首次使用云端能力时自动创建匿名用户与本设备身份，普通使用者无需接触供应商 Key 或管理员令牌。恢复码可在另一设备恢复同一匿名用户；它不能证明真实姓名、邮箱或企业成员身份。管理员仍可查看用户下的设备、撤销单台设备并控制每用户和全局额度。真实复用验收与商业账号、订阅及组织租户仍未完成。

### 模型服务后台

后台通过浏览器打开，首次设置至少 6 位的管理员密码（本机使用支持简单数字密码），再填写 API 基地址、模型与 Key。“测试连接”只发送固定检测文本，成功后需明确保存；更换配置不需要重启服务。已有密钥不回显，更换供应商地址需重新填写密钥。

模型供应商和调用额度卡片均有“保存并启用”入口，提交同一份配置。修改额度后显示“尚未保存”，提交后在额度卡片内显示成功或失败结果；保存与连接测试进行时，两个保存入口和测试入口统一禁用。

“Worket 接入”生成有期限、可撤销的接入凭据，用户复制到桌面 Worket；“运行记录”显示请求状态和调用次数，不展示工作正文。模型未配置时也能打开后台，发起沉淀会得到明确错误。当前后台只监听本机，远程使用需要单独部署 HTTPS；本机桌面接入使用开发模式。

## 本版本的数据积累目标：改进 Worket

2026-09-09 用户明确：当前版本采集数据的用途是改进 Worket。围绕主动沉淀与复用，积累所选工作材料、模型候选、人工修订和确认、复用及验收反馈，支持功能诊断、质量评测以及提示词、处理流程和模型版本比较。价值来自能复现问题、解释人工修正并验证后续改进的样本链。

**实现状态：**后台“改进样本”支持查看来源、候选原稿、用户修改、确认、复用验收，保存评审备注与删除；可暂停或恢复接收。桌面沉淀范围确认与创建复用工作页面直接展示 `worket-improvement-v1` 采集选项，默认勾选，授权起保存 90 天。2026-09-10 按用户要求改为持久偏好：取消后跨页面和重启保持关闭，并停止全部已有样本的后续采集；重新开启只适用于此后提交的范围，已停止样本不恢复。该桌面变更随 v0.1.3 打包发布；后台服务仍需单独部署和升级。自动同步仅覆盖已授权的范围，不调用额外模型。复用首版只采集定义、非文件输入及逐项验收，交付物仅记录所选 ID，不读取文件正文。

记录样本现在同时提供截至同步点的有效原文视图：修订、来源缺失和恢复与历史原文分开展示，分片/关系不齐或待复核时不提供当前要求。内部消息关系随样本上传，不包含来源原始元数据；旧后台需升级后才同步新版记录样本。见 [记录样本视图](specs/recording-sample-view.md)。后续同步只传来源状态的变化，重启可恢复；记录样本以 10,000 事件与 20 MiB 双预算限制，超限明确停止，原始本地工作保留。见 [长记录同步](specs/recording-sample-scale.md)。

本地记录不等待服务器：离线、后台暂停或暂未升级时保留待同步数据，恢复原服务后重试；取消记录、完成、归档或关闭参与改进会停止对应后续上传并丢弃待同步正文，已发送样本仍可单独删除。上传本身不调用模型。复用创建动作仍只采集定义和验收，未主动选择记录的新工作对话不自动纳入。v0.1.3 已包含桌面端改动；改进采集新增协议仍需要兼容的后台版本才能接收。

“更多 → Worket 服务 → 改进数据”能查看同步状态、停止单个或全部样本的后续采集、删除后台样本。停止会丢弃待同步正文；已经发出的请求可能仍到达后台，彻底移除须使用删除。离线删除显示待确认，恢复原服务连接后完成。网络重试和应用重启不重复计数；服务或凭据变化时暂停上传；异步连接完成、请求实际发出前会重新核验停止状态、有效期和原服务身份，删除也只发送到原服务。停止后重新开启不会恢复旧队列或待定授权。见 [发送边界](specs/improvement-send-boundary.md)。新范围沿用参与改进偏好，并在提交前展示实际采集内容；沉淀重试默认不加入改进采集。

## 后台沉淀与桌宠反馈（2026-09-18）
