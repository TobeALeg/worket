## 需要谨慎处理的状态与遗漏风险

- `real-active-window/r11` 与 `r17/q2`：较早获确认的降级流程，随后遭到用户体验层面的质疑，再出现替代交付选择。不能机械标为永久有效，也不能仅凭助手后续解释就视为用户撤回目标。应保留时间关系和本轮范围；这里不把其唯一正确状态武断指定为 `SUPERSEDED`。
- `real-active-window/q1`：原始用户授权没有完全说明外部处理范围，提出问题具有依据，**不判为无意义提问**。但应将其阻塞范围限定在需要该授权的处理分支；当前整体状态不能说明哪些独立工作仍可继续。
- `real-multiwork/r8`、`r9`、`r10`，依据 `m654`、`m661`：助手建议仍标 `AGENT_PROPOSED`，没有冒充用户确认。用户未来方向也保留了延期条件；因此不直接判成当前强行实施。不过 `r9` 的 `ACTIVE` 与自然语言中的延期条件可能被仅筛选状态的消费者误读，宜将“用户已表达”和“当前执行范围”分字段表达。`r8` 也不应仅因 `UNRESOLVED` 就触发追问。
- `real-multiwork/r6`，依据 `m358`、`m361`、`m368`：修复提示的要求已覆盖，但其表达较宽泛，未显式保留用户应知道的等待原因和下一步动作。可加强确认指代解析并链接 `m361`；不能要求逐字照搬助手给出的 UI 文案。此项为细节召回建议，不计作确定遗漏。
- `real-multiwork/q1`：最初要求是泛化的并行能力，助手交付报告保留来源差异。问清覆盖范围有信息价值，标 `OPTIONAL` 合理；也不能把助手报告中的局限默认当作用户批准的范围缩减。

两例用户明示的主要目标、回归修复、入口调整、并行与历史工作、分阶段布局和延期记录方向均有对应条目；未发现明显的大项意图遗漏。`real-active-window/r15/r16` 与 `real-multiwork/r8` 正确保留为助手提案，说明来源区分已有作用。该结论不代表每个细节都已达到人工金标准，也不代表可复用 WorkDefinition 已验收。

`real-active-window` 的范围问题不会因为增加一次模型审核就自动消失；目前来源闸门更适合视为风险筛选，不能宣称全部 ACTIVE 内容均已可靠证明。确认页内容遗漏仍存在，未由分类式闸门补回，这符合闸门不能扩写要求的职责边界，也说明还需单独检查召回。

### 闸门是否误降级

已落盘的更新与识别例把混合高层句整条降级，属于**保守的信息损失**：句中确有与最终边界不完全一致的部分，因此不能简单判为无依据降级；但正确子命题也随之失去 ACTIVE 身份。不能用“误要求减少”单项指标证明全面变好。

识别例删除了默认提炼范围问题，闸门理由部分依赖助手后来的实现说明。这不能当作用户已经确认具体外发安排的证据。最终相关安排仍在 `r12` 中保留 AGENT_PROPOSED UNRESOLVED，未被直接提升为云端外发许可，所以当前风险是问题必要性判断与解释可靠性，而非已授权外发。

多工作例的主要要求未见明显误降级；更新例最终半自动路线、数据保留、文档、发布要求均仍 ACTIVE。配色例保留用户方向与探索动作；视频例保留精简稿替代关系，没有恢复已废弃的逐字稿要求。视频中的具体脚本名称来自上下文解释而非所引初始用户句，属于引用精细度不足，未改变已批准稿文或形成额外制作约束。

### 沉淀例最终复核

`real-distillation` 最终为 28 条要求、3 个 OPTIONAL 问题。核心产品思想、手动触发、路径分离、输入与固定资料、版本、首版外部执行、规格交付以及第二次复用验收更完整。之前只引晚期助手复述而漏接确认的验收目标，现由 `r21` 关联 `m82/m89`；执行者无关的信息边界和现有领域对象也得到了单列。这是可审阅性上的实际改进，不以条目数量本身判断质量。

**SA-206 / 中，仍漏检：`real-distillation/r20` 继续将旧额度等待前提设为 USER_CONFIRMED ACTIVE。** 来源 `m194/m201` 中用户认可的交接独立性仍成立，但同条用户评论随后因此选择自有模型 API；最终 `r18` 已表达新路径，`r19` 也拒绝旧路径。闸门仅用交接不依赖旧调用的确认来支持整句，遗漏了句内另一项已经失去方案前提的等待条款。该错误没有被 v0.11 的最终分类闸门截住，不能声称已清除旧依赖。

`r18` 的 applicability 已限定 AI 整理与抽象调用，不据此误判为要求删除现有会话采集接口。`r12` 由用户修改过的建议点整体降为未决；其部分安全约束未必真的被撤回，但也没有足够明确的独立确认链证明所有子句继续有效，故不列为确定误降级。代价是一些可能有价值的条款只能供审阅，不能直接执行。

本例顶层仍 `NEEDS_CLARIFICATION`，三个问题却全为 OPTIONAL；运行配置、隐私披露和执行者范围涉及后续实现/上线，不能据此阻塞当前规格草案交付。部分问题可由实施判断与产品规则解决，不应把它们全都转成用户必须立即回答的事项。
