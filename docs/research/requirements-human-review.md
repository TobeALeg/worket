# 工作要求真人审阅：本地研究流程

日期：2026-09-11。状态：审阅工具已实现并通过工程验收；工作发起人的真实标注尚未完成。这是独立研究页面，不是桌面产品发布。

## 验证目标

由原工作发起人判断：草案是否准确表达原对话发生时的要求、状态和适用范围，哪些应接受、修改、拒绝，以及哪些内容遗漏。将真人判断与模型自动评分分离。新的决定单列，不用今天的改变回填昨日的正确答案。

本步骤验证单次要求提炼的可认可性和修订负担；不直接证明跨实例适用性、执行者迁移或下一次交付收益。对历史条目的“接受”表示认可其被替换/否定等分类，不表示重新启用旧要求。对可复用候选的认可也不发布 WorkDefinition。

## 使用

双击 `scripts/run-requirements-review.command`，或在研究工作树根目录运行：

```sh
node experiments/conversation-requirements/review/server.mjs
```

打开 `http://127.0.0.1:4318`。Node.js 22+，本轮实际使用 24.15.0，无新增运行依赖，不需要模型 Key。

预装此前冻结的 v0.11 audited 产物：6 项真实工作、81 条要求、5 个待澄清问题。原文件仍在 `output/requirements-private/`。从视频、品牌、更新等较短案例进入；顺序只为降低初次使用负担，不作为随机实验。

1. 选工作，进入一条要求及其原文依据。当前有效性、范围和模型归因同时显示；模型 gold、分数、独立复核结论不进入页面。
2. **接受 / 修改 / 拒绝**：接受与拒绝直接保存后进入下一条，修改在原位进行。修改可以区分回顾修正和今天的新决定，并调整状态、范围、适用条件。对已修改的条目，重新接受模型版本的按钮明确标为“接受原稿”。
3. **暂放与撤销**：暂放不计为已判定；最后集中回看。撤销恢复原评价及条目位置，保留操作日志。
4. **查原文**：点击引文查看对应消息和前后文，引用按原始偏移高亮；可展开完整可见对话。原文按纯文本渲染，不执行 HTML、链接或其中的指令。
5. **补遗漏**：区分“当时说过但提炼遗漏”“当时有意图但没说出”“今天新增的决定”，可关联用户消息。输入和编辑都自动暂存；回到本工作、刷新或重启后可继续。
6. 所有条目完成评价、暂存编辑已处理、用户检查遗漏后，允许提交。结果页显示计数，支持 JSON 导出及重新打开修改。任何未审阅/暂放项都不会被默认为接受。

快捷键：A 接受、E 修改、R 拒绝、S 暂放、Z 撤销，左右方向键切换；编辑区使用 ⌘/Ctrl + Enter 保存。输入框内不触发单字母快捷键。弹出的原文窗口支持 Escape 关闭与焦点返回。尊重系统减少动态效果设置。

## 持久化与可追溯性

```text
冻结 WorkRecord + WorkRequirementsDraft
  → 导入时校验工作身份、来源哈希、原文偏移
  → 本机页面：逐项评价、编辑暂存、补充遗漏
  → HumanRequirementsReview：当前状态 + 只追加的操作日志
  → 显式提交 / 导出
```

`HumanRequirementsReview` 关联 WorkInstance、WorkRecord、AnalysisRun、Draft ID 及草案哈希。原稿不修改。反馈默认位于 `output/requirements-private/human-reviews/<case>.json`，通过同目录临时文件后 rename 原子保存，文件权限 0600。整个目录被 Git 忽略。

保存按 revision 串行校验，防止多个页面互相覆盖；operationId 让保存重试幂等。网络失败保留本页内容，明确显示未保存并提供重试。服务重启后可刷新会话令牌重试。版本冲突要求重新载入，拒绝静默覆盖另一个页面的结果。

只监听 127.0.0.1；Host、Origin、请求令牌及 CSP 约束本地访问。页面没有远程字体、统计 SDK、模型请求、训练或上传功能。可以用 `WORKET_REVIEW_PORT`、`WORKET_REVIEW_PRIVATE_ROOT`、`WORKET_REVIEW_OUTPUT_DIR` 配置运行位置。此版本是一名本机工作发起人的研究入口，不提供多人身份认证。

## 结果怎么解释

- 要求与待澄清问题分别统计。要求报告直接接受、修改、拒绝、暂放和未评；问题评价的是“当时是否确实需要问”，不要求重新作业务决定。
- 历史要求的直接接受数以已判定的历史要求为分母；同时保留全部要求数与未评数，避免以部分样本冒充完成。修改项与新决定单列，不能把“修改后可用”称为原文提炼正确。
- 补充只表示工作发起人发现的遗漏或新增内容；未建立穷尽金标准前，不能据此计算严格召回率。
- engagedMs 是前台交互间隔的粗略估计，忽略大于 60 秒的空闲间隔；单次命令上限 5 分钟。包含撤销前的投入，不代表精确工时，也不包含所有离线阅读成本。
- 单用户、已见样本、回顾式评价，仍受记忆和自选择影响。未显示自动评分可减少直接提示，但用户已参与此前讨论，因此不是严格盲测。
