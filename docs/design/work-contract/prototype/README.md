# 单页工作契约原型

2026-10-09，独立只读设计预览，尚未接入客户端。用户在比较摘要、折叠和封面后，明确希望单页尽量多展示信息，减少翻页和跳转；要求缩小标题、去掉短描述、提高正文密度，接受接近 A4 的比例。本轮按该方向重新排版，视觉结果仍待用户评审。

## 当前布局

- 小标题与总条数取代大标题、短描述和全文按钮。
- 左栏为输入、约束，右栏为交付、验收、资料；底部通栏放方法。
- 短条目紧凑连排，约束和验收保留逐条编号。六类的 27 条原文默认可见，不用打开弹窗。
- 重复的必填、选填、模型推断、参考方法状态改用行内标记与统一图例，原状态仍保留在辅助文本及悬停提示中。
- 原始目的可在纸页底部原位展开；顶部短描述不显示。底部继续显示草稿、待确认及提炼时间。
- A4 为目标比例，内容需要更多高度时自然延伸，不裁切、不用固定高度覆盖确认区。

旧三方案保存在提交 `1f320ea`，当前页面已移除切换栏和详情弹窗；旧 `?variant=` 参数不再切换布局。

## 本机启动

从仓库根目录运行，使用 Python 标准库：

```sh
python3 docs/design/work-contract/prototype/serve.py output/design/work-contract-real/compact-data.json
```

打开 `http://127.0.0.1:8771/`。右上角可选择 520px / 420px / 320px，窄窗口会自动收窄。若本机服务已运行，无需重复启动；可用 `--port` 指定其他端口。

服务仅绑定 loopback，使用临时资源目录；不连接数据库，不提供写入 API。私有候选和截图留在被忽略的 `output/` 中，不提交。

## 输入与状态边界

输入 JSON 包含 `title`、`purpose`、`id`、`revision`、`createdAt` 与 `sections`。每类包含 `key`、`label` 和 `items`；条目包含 `key`、`text` 与可选 `meta`。本轮直接使用已有候选快照，没有再生成或改写条款。

支持的分区 key 为 `inputs / deliverables / constraints / acceptanceCriteria / methods / materialRoles`。`meta` 的“必填 / 选填 / 模型推断 / 参考方法”对应“必 / 选 / † / 参”，图例明确 † 仍待审阅。该原型的数据状态固定为候选，不提供确认、发布或复用动作；不扩展标准组件的 `ContractView`。

## 浏览器核对

标准 520px 卡片的内纸页约 502×735px，宽高比约 1:1.46，接近 A4 的 1:1.414；标题约 23px，正文约 12.5px。27 条原文、条目身份及原状态逐项与本机快照核对一致。完整目的原位展开，确认区随之下移，不覆盖正文。

420px 与 320px 卡片也检查了正文、编号、日期的横向溢出和确认区位置，均无溢出或内容重叠。

这只验证本样本的排版和内容保留，不等于用户已认可，也不证明阅读效率或复用质量。窄版优先保留可读字号与全部内容，因此可能比 A4 更长；不以缩小到不可读或裁去条款来保持比例。
