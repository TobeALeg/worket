# 契约紧凑展示原型

2026-10-09，throwaway UI prototype。问题：真实候选的 27 条原文让纸页超过 2000px，如何保留纸张凭证的完整形态，同时让全文随时可查？

| 方案 | 默认内容 | 阅读方式 | 420px 卡片内纸页高度 |
| --- | --- | --- | --- |
| A 双列概览 | 目的摘要、六类摘要与条数 | 点类别查看原文，也可查看全文 | 约 456px |
| B 分类折叠 | 目的摘要、六类标题与条数 | 同页互斥展开一类 | 约 555px，展开后增长 |
| C 极简封面 | 名称、目的摘要、总条数 | 全文在独立详情中阅读 | 约 327px |

原全文同宽纸页约 2015px；A 缩短约 77%。这只是该样本的布局尺寸，不是阅读效率证据。助手推荐 A，用户选型仍待确认。保留三种方案供比较，未合入标准组件或客户端。

## 本机启动

从仓库根目录运行（Python 标准库，无需安装依赖）：

```sh
python3 docs/design/work-contract/prototype/serve.py output/design/work-contract-real/compact-data.json
```

打开 `http://127.0.0.1:8771/?variant=A`。B/C 通过 URL 参数或底部左右按钮切换，键盘左右键也可切换；输入控件和详情弹窗中不劫持方向键。右上角可以选择 420px / 320px。该端口若已运行上一轮预览，无需重复启动。

服务仅绑定 loopback，使用临时资源目录；不连接数据库，不提供写入 API，不持久化选择。端口可用 `--port` 更换。真实候选 JSON 和截图继续留在被忽略的 `output/` 中，不提交到仓库。

## 数据边界

必须显式提供本机 JSON 文件；其结构如下。示例为合成数据，可保存到忽略目录运行：

```json
{
  "title": "示例工作",
  "purpose": "完整目的原文",
  "purposeSummary": "用于浏览的简短目的",
  "id": "example-draft",
  "revision": 1,
  "createdAt": "2026-10-09T00:00:00Z",
  "sections": [{
    "key": "inputs",
    "label": "输入",
    "summary": "输入摘要",
    "items": [{"key": "input-1", "text": "完整原文", "meta": "必填 · 模型推断 · 待审阅"}]
  }]
}
```

分区 key 可为 `inputs / deliverables / constraints / acceptanceCriteria / methods / materialRoles`。摘要为独立展示字段，不写回原定义、不替换规则、不参与确认。原文和状态标记使用 `textContent`。本原型只展示候选，固定显示“草稿 / 待确认 / 提炼于”，不调用 `createWorkContract` 的已确认版本渲染接口，也没有确认、发起工作或发布动作。

## 已核对与待验证

已在 Chromium 核对 A 的分类详情、全文 27 条与目的逐字一致、Escape 关闭；B 展开第二类时收起第一类；三方案切换及 320px 换行。478×671 窗口下 A 的纸页和阅读按钮可见，正文无横向溢出。纸页两侧的齿孔装饰允许超出边框。

仍需用户选择展示方式，以及决定摘要的生产来源和编辑方式。该原型中的摘要是为单一样本手工编写的，不代表已实现自动摘要或已验证语义完整性。确认后的蜡封状态仍由原标准组件负责。
