# 单页工作契约原型

2026-10-09，独立只读设计预览，尚未接入客户端。用户认可当前其余设计，并要求去掉方法。输入和输出必须全部展示，交付物更重要、逐条换行；验收内容并入约束，约束与资料可以折叠。标题缩小、无短描述及纸张样式沿用。底部符号说明与来源标识已移除，保留必填星号和工作目的入口。接入位置与用户路径见 [流程提案](../journey.md)。

## 当前布局

- 小标题保留，移除卡内重复总数，短描述和全文按钮继续移除。
- 输入在前，双列完整排列；交付物在后并加强字重，每项独占一行，两类原文全部直接可见。两区标题字号、左边界及条数格式一致，没有仅用于强调的侧边竖线。
- 约束、资料默认折叠；验收原文追加在约束列表内，统一计数，不另设分组或入口。方法不在卡片显示。使用原生 `details` 在当前纸页展开，可同时展开多类，不跳转也不打开弹窗。整行可点，右侧使用“展开 / 收起”及方向箭头，键盘焦点可见。
- 必填只用 `*`，选填无专属标记；按最新批注移除条目后的“模型推断”“参考方法”等来源标识。来源状态仅保留在原始数据与 `data-meta`，不生成标签或对应悬停提示。
- 原始目的沿用同一折叠交互，放在约束与资料之后；顶部短描述不显示。底部继续显示待确认、提炼时间，并为编号和草稿版本补足文字标签。
- A4 为目标比例，内容需要更多高度时自然延伸，不裁切、不用固定高度覆盖确认区。

旧三方案保存在提交 `1f320ea`，当前页面已移除切换栏和详情弹窗；旧 `?variant=` 参数不再切换布局。

## 可用性依据

2026-10-09 用户指出交付物的额外竖线缺少必要性，并要求参考 Steve Krug 的《Don’t Make Me Think》。核实依据为 [原书预览及章节目录](https://www.oreilly.com/library/view/dont-make-me/0789723107/ch02.html)：清晰视觉层级、惯例、明确分区、明显的可点击区域，以及减少视觉噪声。以下是针对本页面的设计应用，不是书中的逐字规范：

| 阅读问题 | 本次处理 |
| --- | --- |
| 输入与交付物为何像两种组件？ | 统一分区结构，用交付物字重表达重要性，去掉无语义竖线。 |
| 哪些能点，点后会发生什么？ | 静态列表不做按钮外观；折叠行统一显示展开/收起、方向箭头、悬停和键盘焦点。 |
| 数字与符号是什么意思？ | `08` 改为 `8 项`，底部编号和版本有名称；按最新批注仅保留必填星号，不显示来源标识或符号图例。 |
| 为了核对条款是否需要离开当前页面？ | 输入输出完整常驻，其他条款可同时原位展开，保留原始文字与候选状态。 |

纸纹、纸边和层次感继续沿用。目标是使内容与操作更容易辨识；尚未进行用户可用性测试，不能宣称阅读速度已经提高。

## 本机启动

从仓库根目录运行，使用 Python 标准库：

```sh
python3 docs/design/work-contract/prototype/serve.py output/design/work-contract-real/compact-data.json
```

打开 `http://127.0.0.1:8771/`。右上角可选择 520px / 420px / 320px，窄窗口会自动收窄。若本机服务已运行，无需重复启动；可用 `--port` 指定其他端口。

服务仅绑定 loopback，使用临时资源目录；不连接数据库，不提供写入 API。私有候选和截图留在被忽略的 `output/` 中，不提交。

## 输入与状态边界

输入 JSON 包含 `title`、`purpose`、`id`、`revision`、`createdAt` 与 `sections`。每类包含 `key`、`label` 和 `items`；条目包含 `key`、`text` 与可选 `meta`。本轮直接使用已有候选快照，没有再生成或改写条款。默认可见输入 8 条、交付物 4 条；全部展开后展示 25 条，原始快照中的 2 条方法不展示，预览计数同步排除方法。

输入支持的分区 key 为 `inputs / deliverables / constraints / acceptanceCriteria / methods / materialRoles`，展示时忽略 `methods`。`meta` 的“必填”对应 `*`，其他元信息不渲染为标签；原始 `meta` 不改写。该原型的数据状态固定为候选，不提供确认、发布或复用动作；不扩展标准组件的 `ContractView`。

展示层将 `constraints` 与 `acceptanceCriteria` 合并为一个约束列表，条目仍保留原 `key`、正文、`meta` 和 `data-source-section`。本机样本为 5 条原约束加 5 条验收，共 10 项。未做语义去重或条款改写，也不迁移正式领域字段。

## 浏览器核对

纸页继续以 A4 为目标比例；展开条款后自然增长，原文、条目身份及原状态不变。合并后少一个折叠入口，约束内容仍可完整展开。

已核对默认完整显示 8 条输入及 4 条交付物、交付物各占一行、约束和资料默认收起；同时展开后 25 条原文及原状态与本机快照的非方法条目逐项一致。约束包含原约束和验收共 10 项，没有独立验收或方法入口。必填均使用 `*`，选填不生成“选”或星号。全部展开后确认区仍位于正文下方。

此前 420px 与 320px 卡片全部展开检查中，正文、编号、日期均未超出纸页，确认区位于正文下方。本次仅移除方法，沿用既有布局和原生开合交互；当前约束、资料、工作目的三个折叠入口均至少 40px 高。装饰缺口伸出纸边不作为正文溢出。

这只验证本样本的排版和所需内容保留；用户对当前其余设计的认可不等于阅读效率或复用质量已经验证。窄版优先保留可读字号与所需内容，因此可能比 A4 更长；不以缩小到不可读或裁去条款来保持比例。
