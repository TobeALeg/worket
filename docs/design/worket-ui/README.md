- [页面与状态清单](inventory.md)：页面边界、复用组件、迁移前必须覆盖的状态。

## 应保留的设计语言

1. 奶油白背景、灰绿表面、深绿色主要操作，保持安静、紧凑的信息呈现。
2. 普通管理界面使用系统无衬线字；已确认契约保留纸张、衬线标题、分类页签、蜡封。契约材质不扩散为所有列表或按钮的装饰。
3. 全局反馈、菜单与收起窗口保持稳定位置。子页用返回表达层级；关闭窗口与返回不能互换。
4. 工作、已确认契约和一次流程运行各有身份；用标题、版本、文字状态与内容层级区分，不仅依赖颜色。
5. 主要动作与用户当前目标对应。耗时操作有真实状态，只有完成保存后才显示成功反馈。

## 页面结构规则

2026-10-28 用户确定后续 UI 规划先做信息审核，再讨论视觉方案。审核顺序和本轮已沉淀/工作流逐项结论见 [信息审核](information-audit.md)；已沉淀具体内容最多三行，运行时尚未修改。

| 结构 | 适用页面 | 规则 |
| --- | --- | --- |
| 主列表 | 最近活动、进行中、已完成、已沉淀 | 共享顶栏和主导航；工具栏用于当前列表的搜索、筛选或批量动作；列表正文独立表达空、加载、错误 |
| 内容详情 | 一次工作、来源详情、已确认契约 | 标题及身份先于内容；次要资料与管理操作按需展开；长内容可读且可返回原列表 |
| 表单子页 | 服务设置、本次输入、沉淀准备 | 字段标签始终可见；字段错误就地显示；主要动作放在稳定操作区，不随正文长度漂移 |
| 紧凑审阅 | 候选定义审阅 | 保留分区和逐条确认/删除；展开编辑与来源核对不丢失上下文；发布失败保留编辑 |
| 轻量弹层 | 执行者选择、危险操作确认、截图预览 | 完成单一短任务；可取消；返回焦点到触发入口；与全页子页区分 |

这是从现有行为归纳的目标规则，不表示所有页面已经完整满足。当前工作详情仍在主面板内渲染；不要为了匹配模板立即将其改成新路由或新弹窗。工作流将使用什么结构留待重新设计。

## 交互与状态约定

- **返回 / 收起 / 取消**：返回上一级；收起窗口；取消当前短任务。分别命名，不混用。编辑离开前的暂存必须成功，失败时留在原页并展示错误。
- **按钮**：同一区域一个最突出主动作；普通、轻量文字和危险动作区分。忙碌只锁定相关动作，避免重复提交；错误后可重试并保留输入。
- **表单**：必填标记与实际校验一致；输入类型决定控件；取消不得被必填校验阻挡。已有导入先预览再确认的边界保留。
- **列表**：空列表、筛选无结果、读取失败分别表达；失败不能显示成“没有内容”。来源筛选和加载范围要与实际数据一致。
- **状态**：未开始、处理中、成功、失败、待确认用文字明确表达；不要用一个通用“完成”覆盖保存、发送、接手、验收等不同事实。
- **图标**：已有执行者品牌素材和 Tabler 审阅图标继续复用；新增通用图标先选同一成熟图标库并保留来源。可见图形尺寸与点击区域分别定义。
- **键盘与长内容**：焦点可见、按钮有可访问名称、弹层退出后恢复焦点；长中文标题、长路径、空值和多行错误不遮挡操作。
- **动效**：沿用已实现的审阅状态变化与成功保存后契约显现。再次打开契约保持静态；减少动态效果偏好有效。新动效先讨论方案。

## 如何转成代码与 Figma 的共同规范

首期不更换前端框架，不引入通用组件库来覆盖现有视觉。先抽取已有重复部分；单次业务布局保留在业务模块。

| 内容 | 正式维护位置（建议） | 对应 Figma 资产 |
| --- | --- | --- |
| 颜色、字体、间距和尺寸 | 仓库内一份可版本化 token 数据；实施后生成 CSS | Variables 与 Text / Effect Styles |
| 按钮、字段、列表行、页面壳等 | 共享样式与必要的 DOM 构造函数；已有接口优先保留 | 主组件与真实需要的属性/状态 |
| 页面组织与关键状态 | 审核通过的设计稿 + 页面清单 | Auto Layout 页面与组件实例 |
| 业务状态、权限和数据调用 | 现有业务模块与类型定义 | 说明及样例，不在 Figma 维护另一套运行状态机 |
| 对应关系 | 稳定组件名、源码路径、Figma 节点 ID、规范版本 | 相同组件名与代码引用 |

Figma 可以试验新样式，但批准后的 token 回到同一数据源；第一版显式同步，不实现双向自动覆盖。组件映射先使用名称和路径，Code Connect 是可选增强。不要把源码模块名直接当成组件名：例如 `distillation.ts` 承载多种业务页面，并非一个设计组件。

建议 Figma 初期只使用一个 Design 文件，按 Foundations、Components、Pages 分组；页数受实际账户能力约束时使用同页 Sections。页面用组件实例组装，颜色与尺寸绑定变量；截图只作对照，不作为可编辑设计交付。字体、纸纹、遮罩和蜡封应验证还原效果，不能以新生成的整图替换。

## 验收边界

本次整理的完成标准：有可追溯的页面/状态清单；有现有 token 到语义 token 的映射；有组件职责与例外；工作流明确排除；现状、建议与尚未验证的内容分别标注。

下一阶段实施的完成标准：设计和代码组件对应；基础值可追溯至同一来源；实际原生尺寸、长内容与关键状态通过视觉核对；产品文档与实现一致。规范文档合入不代表组件已抽取、Figma 已迁移或客户端已改版。
