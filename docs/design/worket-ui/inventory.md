## 工作流：重新设计，现有 UI 排除

用户于 2026-10-21 明确表示当前工作流 UI 不可接受。`workflows.css`、`workflows.ts`、`workflow-builder.ts`、`workflow-ui.ts` 的布局与呈现不可提取为标准组件，也不作为 Figma 页面复刻目标。

后续设计应从以下用户任务及真实状态出发。它们来自 [产品定义](../../product.md) 与 [领域术语](../../../CONTEXT.md)，不是已批准的新导航或页面方案：

| 用户任务 | 必须能辨别的事实 | 不得误导的表达 |
| --- | --- | --- |
| 组织一套可复用流程 | 流程定义、固定契约版本、输入来源、最终交付 | 把定义与一次运行的状态混在一起 |
| 为本次客户/批次开展 | 本次输入、独立运行身份和工作目录 | 默认继承另一运行的客户材料 |
| 判断下一步做什么 | 节点就绪条件、阻塞原因、执行者、可执行动作 | 所有节点都用同一种“进行中” |
| 跟进执行 | 请求启动、待接手、已接手、交付结果 | 打开外部应用即表示已经执行成功 |
| 核对与验收成果 | 提交版本、实际成果、验收项、放行条件 | 上传成果即表示验收通过 |
| 重做或采用新版成果 | 旧轮/新轮、后续影响范围、采用版本 | 静默覆盖已开始的下游输入 |
| 暂停与恢复 | 是否允许新的准备/交付、外部任务真实状态 | 宣称暂停流程会终止外部 Agent |

开始重设计前，围绕“用户最常打开工作流是为了搭建，还是跟进执行”讨论信息优先级，并对运行详情的主要决策路径给出方案。节点图、侧栏、列表和画布都只是候选表达方式，不预先锁定。
