# 明确开启范围内的持续比较

2026-09-23。沿用增量协调协议，新增本地触发队列；不新增后台定时任务、模型提示或自动发布权限。

## 用户行为

每份约定的“持续比较”默认关闭。用户确认后，比较此系列现有及未来实例中**开启后新记录**的用户消息、Agent 回复和本次输入，与该系列最新已确认约定合并审阅。开启前的事件版本不自动补传，其他系列不进入队列。关闭再开启视为新的未来范围；主动“从后续工作更新”仍可选择历史范围。

输入角色和固定规范来自已确认约定；已固定的规范条款仍由本机验证后提供有效文字。新附件只带无路径的类型/hash 元数据，不读取正文；工具输出、推理摘要不自动发送。持续比较不启动或扩大本地记录，也不自动加入“参与改进”样本。

新交互稳定两分钟后提交，Worket 必须打开。每份约定任意 24 小时最多三次自动尝试，关闭重开不重置额度。每次最多选协议允许的实例数量，整个实例的新交互不截断；超限保留记录并提示主动选择较小范围。已有增量任务运行或等待审阅时暂停，避免堆积草稿。一次失败或取消的相同批次不会自动重试；有新交互可形成新批次，受同一上限约束。用户可以从任务入口主动重试。

新增/替代/冲突仍由现有差异审阅确认；重复只补充依据。只有确认后更新比较游标及约定版本，旧实例不变。关闭阻止下一次发送；已经发送的任务仍可查看，必要时单独取消。

## 数据与状态

`continuous_evolution` 是本机 SQLite 中的操作订阅，不是新领域实体。每个 definitionKey 记录授权 generation、服务身份 hash、开启前事件 ID/hash、稳定批次指纹和时间、尝试过的批次 hash、滚动调用时间及最近任务 ID。它不保存额外对话正文或令牌。

`DistillationService.tick → ContinuousEvolution.tick → prepare(内部事件白名单) → start(automatic 授权) → 原 submit/receive/draft/publish`。模型请求协议、后台服务和增量合并规则均复用。先持久化尝试，再发起异步提交；重启不重复提交不确定请求。PREPARED 自动任务可以恢复，SUBMITTED 且没有 requestId 的不确定请求仍进入 INTERRUPTED。

授权绑定服务身份；开启期间身份变化需重新确认，旧任务不能改投新服务。能力查询后、连接恢复后、真正 POST 前重查授权、来源是否仍存在、基准是否最新、任务是否取消。状态查询、确认接收和取消也绑定原服务身份。显式重试保留原目的地，但不要求持续开关仍开启。正在确认开启时发生停止或服务切换，旧异步回调不能重新开启。

删除来源沿用快照及审阅引用脱敏，发送前检查会拒绝已删除来源；删掉整个定义系列后，下一轮清理其订阅。已确认/本次忽略的来源仅在用户确认草稿后进入既有 EVOLUTION_CONFIRMED 游标。

## 验收边界

`npm run qa:contract:continuous` 在隔离 Electron/SQLite/HTTP 服务中走开启、真实计时器合批、待审阻塞、差异审阅、确认和停止。QA 只将本地稳定观察时间提前两分钟来避免空等，产品本身没有快进接口。旧基线回放冻结的真实模型响应，新增持续阶段使用明确标记的受控协议响应，实际供应商调用为零；不作为新的语义准确率或业务收益证据。

`test/distillation/continuous.test.ts` 覆盖未来范围、隐藏/工具内容排除、附件正文排除、只输入不触发、并发 tick、确认游标、失败与额度跨重启、开关/服务/来源/基准在提交途中变化，以及 HTTP 连接恢复后的目的地守卫。
