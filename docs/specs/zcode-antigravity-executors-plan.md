# ZCode 与 Antigravity 执行者接入计划

日期：2026-09-16。状态：本地适配器、记录、手动交付与回执处理已实现；打包界面已验证，真实模型接力待验收。实际覆盖范围见 [验收记录](../acceptance/zcode-antigravity-executors.md)。以下保留原始实施计划，不把计划目标自动视为验收通过。

## 目标

让用户在 ZCode、Antigravity 中开展的工作，能够通过 Worket 主动记录、持续同步和跨执行者交接；换执行者保留同一 WorkInstance，复用定义创建新实例。完成标准是两个应用都走通真实记录和交接闭环，而不是仅出现在选择列表。

本轮只制定计划、检查本地安装元数据与现有架构；未读取聊天正文、修改执行者配置或触发模型执行。

## 已核实的基础

| 执行者 | 本机版本 | 应用与标识 | 已知接入线索 |
| --- | --- | --- | --- |
| ZCode | 3.11.2 | `/Applications/ZCode.app`；`dev.zcode.app` | 注册 `zcode` URL scheme；存在 `~/.zcode` 和应用支持目录 |
| Antigravity | 2.14.0 | `/Applications/Antigravity.app`；`com.google.antigravity` | 注册 `antigravity` URL scheme；存在 `~/.gemini/antigravity`，含 conversations 目录与 conversation_summaries.db |

以上来自本机 Info.plist 与目录检查。URL scheme 不证明支持预填提示词或创建会话；数据目录存在不证明正文可解析、可稳定定位或可增量读取。两者均未在当前 shell PATH 中找到同名命令，不据此判断应用是否提供其他 CLI。

Worket 已具备 `ExecutorAdapter`、`ConversationSource` 和 `ExecutorRegistry`，默认装配目前只有 Codex、WorkBuddy。执行环境类型为字符串，无需为新增应用重建领域模型。安装器已隔离单方安装失败；交接选择器已使用 available/canDeliver。优先沿用这些接口，仅在实测发现共性缺口时最小扩展。

## 实施顺序

### 1. 先确认两者的接入协议

分别检查当前安装包提供的文档、命令、扩展接口与官方资料，记录支持版本和证据。优先选择受支持的本地接口；必要时评估只读存储解析或最小权限扩展，明确内部协议的兼容风险。

每个执行者都要回答并实际验证：

- 能否分页列出已有会话，取得稳定 ID、真实标题、项目路径和更新时间。
- 能否读取静止会话的可见历史，区分用户消息、回复、可见工具事件和隐藏推理；能否识别消息追加、修改和删除。
- 能否精确定位前台会话；不能时使用用户明确选择，不用最近更新的聊天猜测当前聊天。
- 能否创建或打开接收工作的新会话、传入启动信息、接入 Worket MCP，并将真实目标会话与 deliveryId 关联。
- 是否提供 Hook 或事件通知；没有时，是否可通过现有轮询可靠同步。

交付能力矩阵、只读验证结果和推荐路线。摘要库只能作为发现线索，不能代替完整记录。无法可靠读取或绑定时，明确阻塞点；不把仅能启动应用的路线标为完整接入。两者可采用不同底层协议。

### 2. 按执行者完成记录能力

先完成 ZCode，再完成 Antigravity；若协议验证表明后者显著更确定，可调整顺序。每次完成一个可验收功能点后统一测试并单独提交。

预计新增 `src/adapters/zcode/`、`src/adapters/antigravity/`，分别负责应用发现、会话读取、事件规范化、当前会话解析与兼容性检查；在 `src/executors/defaults.ts` 注册。实际文件划分按协议复杂度决定，不复制整套现有适配器。

接通桌宠、最近活动、历史选择、导入、持续同步、重启恢复和从消息新建工作。来源必须包含执行者与会话身份，跨应用同名或相同会话 ID 不冲突。沿用主动记录、参与改进偏好及取消记录边界，不新增后台全量聊天采集。

### 3. 接通交接与定义复用

实现各自的配置安装与 deliver；合并并保留用户已有 MCP/Hook 配置，重复安装不重复写入。启动包沿用 workId、deliveryId 和 START/CONTINUE，完整工作包通过实际验证的接入路线取得。

打开目标应用只表示交付已发起；取得可核验的目标会话关联后，才确认接手并开始对应执行片段。缺少自动发送能力时，可以预填草稿或提供明确的手动步骤，但必须保留待确认状态，不伪造已接手。若只能记录，交接入口应准确显示不可用，并列为尚未完成的范围。

覆盖失败重试、取消、超时、重复点击和迟到回调；不能把旧来源消息写入新执行片段。继续工作保持原实例；复用定义建立新实例，不继承旧会话绑定。

### 4. 完成真实验收与文档

在完整功能点实现后运行有意义的适配器与应用层测试，最终执行 `npm test`、macOS 打包和真实桌面验收。配置测试使用临时目录，会话样本脱敏，不将本机真实聊天提交入库。

真实模型验收使用明确指定的测试工作，包含向目标执行者交付数据与调用模型的范围；当前的“写计划”不授权执行这些操作。记录实际应用版本、Worket 提交、打包版本、成功证据与剩余限制。更新 product.md、architecture.md、执行者验收记录及 BP 条目状态。打包验证与对外发布分别记录。

## 最终验收标准

1. 两者已有静止会话均能主动选择并立即导入，无需补发消息；可见内容保留，隐藏推理不进入记录。
2. 前台会话识别准确；无法确认时进入选择流程，同标题、多窗口情况下不误绑。
3. 四个执行者各至少两条记录同时同步；重复读取、重启、应用退出和单方故障不重复写入，也不阻塞其他来源。
4. 完成、归档、取消记录后停止采集；取消记录不删除外部聊天。
5. 实际走通 Codex → ZCode → Antigravity → Codex，以及 WorkBuddy 与新增执行者之间的交接；工作 ID 保持一致，目标会话、执行片段、工作包读取和新增回复可追溯。
6. 复用定义分别交给 ZCode、Antigravity，创建新实例；重复交付不会重复创建或确认执行。
7. 打包后的 Worket 完成上述入口操作；源码测试通过不代替真实接手成功。

## 工作量与决策点

主要不确定性是两款应用的会话读取协议和交付回执，而非 Worket 列表 UI。第一阶段结束后再据实际协议评估工期。若需要未公开内部接口，先报告具体维护成本及可选路线；不预先承诺官方集成稳定性，也不为两个执行者引入通用插件平台。
