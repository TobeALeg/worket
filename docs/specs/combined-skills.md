# 多个已选技能的共同目录

2026-09-23，第 26 轮。先以两个明确选择的合成技能固定验收：report-builder 的入口和脚本读取 ../format-kit（脚本内 ../../format-kit）的参考文件/模块。它们作为两个 SKILL 资料角色被用户选择、暂存并发布。删除原件后，新实例通过认证 MCP 取得工作包，按包中的入口执行受控脚本，应读取固定 v1 依赖；修订依赖为 v2 后新实例读 v2，旧实例仍 v1。

当前实现把每个技能放进独立 hash 目录，虽然各自完整，兄弟目录的名字和相对位置丢失。先用旧解压包复现，不改写技能正文或安装依赖。

已实现：保留现有明确选择多个技能的流程，工作包把同一已发布约定里的技能放到共同的固定目录下，保留用户所选目录名。依据已验证的固定副本生成这个目录，不访问原件；同名不同版本不能覆盖，提示解决命名冲突。单技能行为保持。共享目录随定义版本固定，可重建但必须与固定清单一致；删除无实例引用的定义时清理。不自动探测/收集目录外技能，不执行用户脚本。

验收必须覆盖原件删除、跨目录读取/模块执行、更新依赖后的新旧实例隔离、MCP 路径一致、同名冲突、缓存篡改/缺失和删除清理。这里处理多个明确选择的技能在本机的目录关系；插件服务、系统工具和网络环境的可用性仍不由文件完整性证明。合成执行与外部 Agent 的真实视频交付分别记录。

共同目录由 skill-environment.ts 根据 definitionId 生成于 definition-materials/skill-environments 下，保持每个原目录 basename，内容不重写。各技能 canonical 副本先校验；派生目录缺失、篡改或增加文件时从这些已验证版本重建，不读取原路径。canonical 缺失时仍拒绝，不反向采用派生缓存为证据。目录通过暂存和 rename 切换，替换为符号链接的目标拒绝；不宣称断电完全原子。删除定义后回收其派生目录，其他定义和共享固定副本保留。崩溃留下的 .assemble 临时目录不会在并发读取时被直接清理。
