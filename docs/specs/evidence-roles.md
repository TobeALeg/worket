# 直接依据与背景引用

2026-09-23。动机来自新的真实模型合成验收：用户明确采纳 Agent 建议中的字幕，尚未决定 Logo 和音乐。模型引用原建议及具体采纳语句是合理的来源链，但旧协议将混合发言全部标为错误归因，产生一次多余的审阅要求。

## 行为与边界

SourceRef 新增可选 `role:"CONTEXT"`；省略表示直接依据。SOURCE 必须至少有一个直接引用。USER_STATED 的所有直接依据必须来自 user.prompt 或 work.*；Agent 原提议可以作为背景引用，但不能代替明确的用户采纳语句。所有引用仍核对请求内的来源 ID、事件 ID 和逐字摘录。只有背景、未知来源、伪造引文均不通过；未标明角色的非用户发言仍降为推断并要求审阅。

模型负责判断用户具体采纳了哪一项；泛泛的“好”“继续”和执行成功不能当作采纳全部提议。程序验证发言身份与引用角色，用户仍审阅确认最终约定。没有新增自动发布权限，也不能证明模型总能判断正确。

审阅依据展开后明确显示“直接依据”和“背景引用（不作为直接依据）”；映射本机引用时保存角色，已确认版本和补充依据保留同样区分。修改条目沿用已有 USER_AUTHORED 编辑证据；来源删除沿用脱敏。

## 兼容

新版客户端请求显式声明 `evidenceSchemaVersion:1`；服务能力声明 `evidenceSchemaVersions:[1]`。只有声明支持的请求才加入背景引用提示，未声明的请求若收到 CONTEXT 结果则拒绝，避免把新角色送给旧客户端。新客户端能接收不带角色的旧结果；连接旧后台时仍沿用其较严格的混合来源审阅方式。

新版协调提示版本为 `work-definition-v2.2`，增量为 `work-definition-evolution-v1.2`。不声明来源角色能力的协调请求为 v2.1/v1.1，旧无规则协议请求维持 v1.4；仅启用来源角色的旧结构请求标记 v1.5。

同时明确覆盖含义：无新增通用要求的事件仍是已处理输入，coverage.exclusions 必须为空；实例值不是重新声明输入角色，不能只因填了新脚本就增加一条输入角色的重复依据。原严格完整覆盖校验保持。

## 验收

`test/distillation/workflow.test.ts` 验证版本声明、直接用户锚点、背景引用、未知来源/引文拒绝和旧请求边界；`evolution.test.ts` 验证从 wire 映射到本机、审阅与不可变发布后的角色保留。`npm run qa:contract:semantics` 回放固定原始响应，包含部分采纳、条件与单次例外、跨实例冲突裁决到新实例。

真实模型与开发失败保留于 [语义验收](../acceptance/contract-semantic-trials.md)。回放不修改原响应，不将旧失败归为语义通过；后续审阅中的冲突选择是明确标注的合成用户操作，不是模型自行确认。
