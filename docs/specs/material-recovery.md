# 固定资料的精确版本恢复

2026-09-23，第 18 轮。

已复现：实例副本内容损坏后，用户重新选择内容正确的原文件，旧 freeze 只因目标路径已存在就复用，仍在 verify 失败。真实“本次文件”界面保留“固定资料副本缺失或校验不符”，不能完成恢复。

普通输入重选同内容须可恢复；此外给定义及实例提供“修复固定资料”，按已保存 manifest 找目标，选择正确原版恢复文件/完整技能目录。错误版本先拒绝，不改变当前副本；不得用今天的不同原文件冒充历史版本。没有原 hash 的 legacy 输入只能明确重选，不能自动恢复。

定义页处理普通固定资料、规范文件及技能；工作页另处理本次输入和已选择参考。恢复不变更 contract/instance IDs、hash、输入绑定、版本、已保存交接快照或执行授权。共享 hash 的旧实例可共同恢复。

文件暂存并核验后 rename；技能完整暂存校验，再备份/替换，普通异常回滚。受管目录不跟随替换链接，所选目录内部链接仍拒绝。操作只读取显式选择，不运行脚本、不安装依赖、不自动监视或上传正文。

验收优先真实界面：旧客户端失败 → 新输入重选恢复 → 定义页选错/选对文件和技能 → 工作页恢复输入/参考 → 原版本和另一实例保持 → HTTP MCP 重新校验成功。补齐缺失、不可读、权限/多余文件、链接边界及替换异常回滚。目录双 rename 的断电间隙不宣称无缝原子恢复。
