# 记录稳定内容与来源修订

目标：用户与 Agent 的交互必须可正确进入工作状态和 working contract 的提炼范围。原始观察用于追溯，当前要求不能永久停留在第一次捕获的半句话。

## 观察与当前内容

Codex 正在 inProgress 的回合只记录已经提交的用户输入，其他内容待回合结束后入档。completed、failed、interrupted 的可见内容仍可记录；这不把中断或失败认作工作完成。缺少状态的旧生产者保持兼容。协议取值于本机 codex-cli 0.155.0-alpha.9.2 生成的 TurnStatus/Turn 类型核实，日期 2026-09-23。

来源增量以适配器、实际会话和原始 externalId 识别逻辑事件。相同 ID 的内容、事件类型、执行者或元数据改变时追加观察，以 metadata.worketSource.previousEventId 指向本地旧事件，旧记录不覆盖。相同内容的重复同步不增加事件；A→B→A 仍是新的修订。不同会话相同 ID 不碰撞。时间戳、顺序和 Worket 自身记录元数据不作为内容变化。

currentSourceEvents 提供有效内容，修订保留逻辑消息的原位置，因此编辑早期用户消息不会把它移到后续 Agent 回复之后。档案 sequence 保持观察顺序与增量游标；提炼快照重新连续编号，ID/hash 仍指向具体不可变观察。没有发生修订的重复消息不会因文字相同被合并。

## 消费与恢复

当前 WorkState 隐去引用已被替代观察的自动派生项，保留 USER_EDITED 项。来源修订后按有效内容重算状态；若提炼失败，过时派生项也不会重新进入当前工作包，重启后继续补算。人工修改和同文本删除决定沿逻辑来源保持效力。

首次提炼、主动增量、持续比较与发送前来源检查都使用有效事件。旧准备范围遇到来源修订会拒绝按未变来源提交。已确认定义、旧实例的定义版本和旧交接包不自动修改；新变化仍需差异审阅确认。

MCP get_work_archive 保留完整事件，并提供 currentEventIds 与修订说明；读取历史不能把每条旧观察都当成当前要求。从消息新建只展示当前用户消息，映射回外部应用的原始 ID；过时选择拒绝。

## 边界

本轮不依据一次列表缺失推断消息删除、分支回退或撤回，不自动移除历史文件引用。资料版本仍走既有固定副本规则。长期改进样本的旧上传消息不删除，现行 MESSAGE 协议尚未传递修订关系，须另行演进并验收；不得将该远端样本当作已经重建的当前对话。

本轮为受控来源和真实桌面/HTTP 验收，无真实外部 Agent 执行或新增模型语义成绩。详见 [验收](../acceptance/source-revisions.md)。
