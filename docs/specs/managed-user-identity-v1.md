# Worket 托管用户身份 v1

日期：2026-09-18。

## 目标

正式版 Worket 默认连接统一托管服务。首次使用无需配置模型或复制令牌；服务能稳定区分用户与设备，将额度和明确授权的上传内容归属到用户，并允许使用恢复码在另一设备恢复同一用户。

## 领域对象

- `UserIdentity`：匿名稳定用户。服务仅保存高熵恢复码的 SHA-256，不保存恢复码原文。
- `DeviceIdentity`：某个用户的一次 Worket 安装。每个设备有独立安装秘密、令牌和撤销状态。
- `UserUpload`：用户明确授权上传的改进样本。正文关联 `userId`、客户端样本 ID、授权版本、创建与到期时间及删除状态。

用户身份不等于真实姓名、邮箱或法律身份。恢复码持有者可恢复该匿名用户，因此恢复码按密码处理。首版不提供邮箱找回、组织成员关系、订阅计费或管理员冒充用户。

## 接口与不变量

桌面首次初始化生成两个互不复用的随机秘密：设备安装秘密和用户恢复码。生产版内置 `https://worket.dandi.site`，首次需要云端能力时将两个秘密通过 HTTPS 提交到 `/v1/installations`。

服务以安装秘密哈希查找设备，以恢复码哈希查找用户。新恢复码创建用户；已有恢复码为同一用户添加设备。响应只包含 `userId`、`deviceId`、有期限的 RS256 令牌及到期时间。令牌的 `sub` 是设备，`uid` 是用户；认证先验证设备有效，再以用户作为模型额度、幂等和上传隔离主体。

恢复时客户端生成新的设备安装秘密，不复用原设备身份。撤销只使目标设备的令牌失效；为防止已撤销设备的在途请求继续处理，首版会取消该用户当时运行中的模型请求，不撤销其他设备。

恢复码原文只保存在 macOS 系统安全存储中。服务配置、管理视图、日志和 Git 不得返回或记录安装秘密、恢复码、供应商 Key 或完整访问令牌。

## 上传与留存

模型处理和正文留存是两种授权。普通沉淀材料只用于当次处理，不因存在用户身份而自动留存。只有 `worket-improvement-v1` 或 `worket-recording-v1` 等明确授权范围进入 `improvement.sqlite`，默认保存 90 天。

同一用户的不同设备共享上传归属和删除权限；不同用户即使使用相同客户端样本 ID 也必须隔离。停止采集阻止后续正文，删除移除正文并保留无正文 tombstone，防止迟到重传恢复。

## 迁移与限制

后台设置从 schema v1 原子迁移到 v2。既有手工凭据各自迁为一个不可恢复的用户，不生成或猜测恢复码。既有桌面自定义服务配置继续优先于内置地址。

服务限制每小时注册/续期请求、用户数、设备数、单用户调用和全局调用。匿名身份仍可能被滥用；公开试点必须保留全局每日预算、日志审计和设备撤销。正式账号、套餐和企业租户以后通过身份 Adapter 接入，不改变上传与模型调用使用的 `userId`。

## 验收

1. 两个不同恢复码得到不同 `userId`，上传和额度相互隔离。
2. 同一恢复码在第二设备得到相同 `userId`、不同 `deviceId`，可删除同一用户的上传。
3. 撤销一个设备后该设备失败，另一个设备仍可使用。
4. 服务磁盘与管理响应不包含安装秘密或恢复码原文。
5. 生产包首次启动出现内置 HTTPS 地址；手工配置不被覆盖。
6. 未授权的模型处理正文不进入持久样本库；授权上传保留期限和删除行为不变。
