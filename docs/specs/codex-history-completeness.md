# Codex 历史完整读取

目标：后续 working contract 提炼不能建立在被当成完整历史的摘要页或半份来源上。

## 读取方式

先 thread/read(includeTurns:false) 取得并核验所选会话身份，再按升序 thread/turns/list(itemsView:full)，直到明确 nextCursor:null。返回 summary/notLoaded 的回合通过 thread/items/list 补齐全部消息，核验 turnId 后再归一化。全部读取完成前不向记录层返回任何事件。

仅第一次分页请求明确返回 JSON-RPC -32601 时使用旧 thread/read(includeTurns:true)；旧接口显式声明摘要或未加载内容仍拒绝。网络、鉴权、参数错误、中途失败和格式异常不触发静默回退。stdio 保留结构化错误码，避免靠错误文字猜测能力。

同 ID 同内容的跨页重叠去重，冲突内容拒绝并提示重试。重复游标、有下一页却无内容、缺少结束标志、陌生完整性状态、错回合消息均不算成功。单次上限 512 页/64 MiB，超限整次失败而非截断。现有采集在 readThread 成功后才追加，失败不落第一页面的变化。正常下次同步可重试。

## 证据及边界

本机 codex-cli 0.155.0-alpha.9.2 生成协议说明全历史加载已不推荐于分页线程。用户引用任务当前的旧全量接口仍可完整工作：实际 16 轮、1,225 个条目，不能宣称这份真实任务之前已经漏页。将同一任务分成 8 页读取后，774 个规范化事件与旧方式 hash 完全一致。

受控摘要页对照证实旧客户端不检查完整性，会漏掉未展开的末页要求；新版可补齐。真实协议兼容与合成边界分别记录，见 [验收](../acceptance/codex-history-completeness.md)。

分页不构成原子快照：并发删除或分支回退仍需独立的来源生命周期机制，不能凭列表缺失自动撤回旧证据。没有新增模型调用或自动执行任务；仍沿用用户主动选择记录的范围。
