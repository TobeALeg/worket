# 面向继续执行的交接上下文：方案草稿

日期：2026-09-23。状态：供讨论，未批准实现；本轮不修改运行逻辑、不清理用户记录、不调用模型或发起真实交接。

## 目标与取舍

用户需要在一项工作尚未完成时更换 Agent。接手者应对齐交付目标，使用已有成果，从当前断点继续，避免重新解释、重复执行和重复踩坑。

用户接受适度冗余：假设必要信息占原上下文 12%，简单筛选后携带 20%–30% 也可接受。比例是取舍示例，不是样本实测结果或截断配额。先保证继续工作所需信息，再观察传输成本。

验收问题：下一位能否说明要交付什么、哪些要求仍有效、哪些成果可以接着用、哪些尚未验证，以及现在应采取什么行动。能复述摘要不等于已经正确执行。

## 从接手方式比较

| 方式 | 接手者拿到什么 | 适用条件与缺口 |
| --- | --- | --- |
| 重述要求，从头执行 | 目标与输入 | 已做工作少、重新执行便宜时可用；会丢失进展及过程中的有效决定 |
| 全量阅读后继续 | 历史与全部引用文件 | 可作为对照，但读取量大；信息齐全也不能保证正确区分旧要求、建议与当前状态 |
| 按计划接续 | 整体 plan、已做、待做 | 能定位阶段；仍可能缺少实际产物、验证范围和失败教训 |
| 从可用成果及断点接续 | 目标、当前成果、验证状态、剩余工作、关键原因 | 直接回答哪些工作不用重做；依赖成果版本明确和证据可查 |
| 缺口驱动读取 | 上述主包，加按项读取证据的入口 | 对具体疑问补读，减少默认全文读取；入口必须可定位、可访问 |
| 向上一位短暂询问 | 主包之外的一次定向补充 | 上一位仍可用时有帮助；额度耗尽、会话不可用时失效，不能作为基本依赖 |

建议组合第四、第五种；第三种的整体计划保留为简短阶段脉络。原 Agent 的补充是可选来源，不要求每次交接进行双 Agent 会谈。Worket 继续保持工作交接工具的定位。

## 主包必须回答的五个问题

### 1. 最终要完成什么

保留交付物、完成标准、范围和仍有效的用户约束。计划只表达主要阶段及当前位置；已经完成或无关的计划细节由引用承载。

明确区分用户要求、已采纳决定和 Agent 建议。明确替代才替代；未解决冲突并列显示，不靠最后一句话覆盖。下一步建议标明建议，不能扩展授权。即使与眼前一步无关，最终交付标准仍须保留。

### 2. 现在停在哪里

描述一个当前断点：已走到哪一阶段，哪一部分做了一半，哪些剩余工作仍在范围内，有无等待事项或正在运行的操作。

旧计划不能被机械当成事实。若没有可靠的当前 plan，保留已知阶段和未确定项，不编造完整路线。远期细节可以引用，但不能只留下紧邻的一步而丢掉剩余范围。

### 3. 哪些成果能继续使用

每项主要成果包含：结果或当前内容摘要、所在位置、对应版本、验证范围、尚缺验证。只有文件路径不足以告诉接手者它为什么有用。

区分“Agent 说已做”“产物存在”“检查通过”“用户验收”；没有证据时保留相应不确定性。对代码工作，分支/提交以及必要的未提交修改属于当前工作状态；对文档或数据工作，草稿版本和输入范围同样重要。不能把未提交、未保存的工作藏在旧会话里。

### 4. 有哪些继续执行所需的经验或条件

只前置会影响当前或后续行动的已知条件，以及关键决定的简短理由、仍适用的失败教训。比如“输入缺少币种列，已尝试自动换算但无法可靠完成”；不需要重放每条命令。

失败是否已解决，必须能对应同一操作、同一对象及适用版本。后来另一个命令成功不等于之前的问题解除。判断不了时保留短错误及证据，避免误报成功。推测与观察分开，不加入隐藏推理内容。

### 5. 从什么动作开始，遇到疑问查哪里

给出首个可执行动作、它依赖的输入/资料和预期检查结果。必要资料明确为什么要读、读哪一部分；其余证据供出现具体疑问时读取。

本来就必须完整处理的输入（例如待分析的数据集）仍需完整读取，不为了达成压缩比例省略。目标不明确且不同解释会实质改变行动时，再向用户提出一个具体问题；普通接手不增加固定的确认环节。

## 两层内容

**主包：**上面五个问题的简短答案与必要证据引用。可以较宽松地保留事实，不规定恰好五个固定 UI 区域，也不强迫每项工作填写空白栏目。

**证据：**对应原始事件、计划或规范的特定段落、成果版本和检查输出。引用携带用途、可定位标识与版本信息。需要时读取，默认不附全部历史、完整执行片段或内部绑定记录。

同一内容只携带一份，多个结论可以引用同一证据。文件可访问且版本匹配时用引用替代重复正文；无法保证可回查时保留必要片段或明确资料缺失。跨机器的本地路径不能冒充可用附件。原始档案与历史交接快照保留。

接手提示建议简短说明当前理解和准备采取的首个动作，随后继续执行；不新增必需的“理解确认”状态或用户审批步骤。MCP 读取回执只说明读取发生，不证明理解准确或工作完成。

## 借鉴本机 handoff skill

该文件很短，主要要求总结当前会话、根据下次重点定制、引用既有产物避免重复、移除敏感内容，并提供 suggested skills。它未规定固定的大篇幅模板。不能据此确认用户之前遇到的长文具体由什么造成；可能需要另看实际产物。

借鉴：按接续目的组织、复用已有计划和成果、引用代替复制。收紧：主包围绕五个接手问题；只有确实影响本次执行的技能才纳入依赖，不自动罗列技能目录；原 skill 的临时文件位置是手工交接方式，Worket 仍沿用本地工作与交接快照。

## 如何生成：把去噪与理解分开

1. **冻结本次读取范围。** 延续现有同步、来源复核、资料校验，记录有效事件与材料版本。本次包的每个结论能追溯到这份范围。
2. **规则先去掉明确噪音。** 合并相同正文并保留来源、次数和必要时间信息；有可靠类型时将读取全文/差异转为引用，将可解析检查输出转为有范围的结果。无法分类的输出保守保留或列作必读证据，不能静默丢弃。
3. **组织接手答案。** 优先复用已确认定义、用户明确要求、已有计划/验收记录与成果索引；现有 WorkState 是候选输入，尤其 objective 和 pendingActions 不能仅因在字段首位就视为当前真相。
4. **缺少语义总结时另处理。** 规则无法从任意历史可靠推导目标、决定原因及完成状态。若有当前 Agent 写出的短交接说明，作为待核对的摘要来源；不可依赖旧 Agent 始终可用。没有时，后续可在已授权范围内用一次受约束的整理生成五问候选，保留证据和不确定性，不逐条给全部事实打重要性分。不额外建立评分/审核 Agent 链。没有模型条件时输出已知信息与缺口，不能把规则拼装宣传为已可靠理解整体工作。
5. **确定性校验。** 检查引用可定位、版本匹配、要求和结论未被截断、完成表述与证据级别一致。冲突或缺口无法解决时保留原文/未知，不能补造结论。第一次验收用人工核过的小样包，不把模型整理当作正确性的证明。

第一版先实现可解释规则和统一主包结构；是否需要补充语义整理，以小样验证暴露的缺口决定。本方案不预先承诺纯规则能达到 20%–30%，也不默认将全部历史发送给新的模型。

## 表达示例（虚构周报任务，非真实用户数据）

> 目标：完成本周客户周报，交付 PDF；本期金额使用美元。该要求仅限本期。
>
> 位置：收入部分已完成，目前停在退款核对；后面还需更新结论、导出并检查 PDF。
>
> 可用成果：周报草稿 v3 已有收入章节，收入数字已与本周输入表核对；退款章节仍为草稿，PDF 尚未生成。草稿、输入表及核对记录各有版本引用。
>
> 继续所需条件：退款表缺少币种列，此前自动换算尝试未解决这一缺口。当前不能假定原金额都是美元。
>
> 首个动作：读取本期退款说明中币种段落和退款表；确认换算依据后修改草稿。若说明中也没有币种，再向用户确认。核查收入计算时才读取原核对记录。

与“收入已做、退款待做”相比，补充的是可用成果、证据级别、必要条件和明确断点；无需附上历史每次文件读取与计算输出。

## 落到现有代码的边界

采用 `codebase-design` 的小接口原则，交接整理集中在一个纯投影模块中，接收当前工作快照与已解析材料，输出主包和证据索引。不让四个执行者适配器各自生成不同摘要。

- 保留 WorkInstance、WorkRecord、WorkState 的领域意义；本方案首先改变交接投影，不增加新的工作生命周期或偷偷重写已确认定义。
- `createHandoffPackage` 与 `buildWorkPackage` 共用投影，避免 `handoff.state`、嵌套 `workPackage.state` 和外层包重复发送同一内容。历史快照不改写。
- `get_work_context` 通过明确版本/请求选项支持新主包；更新后的启动指令选择新版本。旧调用保留兼容出口，新版响应不能一边给摘要一边仍附完整 state 和全部绑定历史。
- 对证据提供按事件 ID/范围读取和有限页大小；文件引用仍复用现有资料解析与校验。不能把“需要时读原文”实现成每次默认返回全部 archive。旧全量读取行为在兼容出口中保留，不在新启动指令中引导无条件调用。
- 交付 ID、会话绑定、每次读取回执和启动失败恢复规则保持；它们负责工作连续性，不承担摘要语义判断。

## 最小验证

先选同一项授权工作中的一个真实中断点，冻结原输入、已有成果版本、用户要求和未完成范围。由人核对一份短答案，标明关键要求、真实完成范围及合理首个动作；不要把旧 Agent 的摘要当作答案。

比较四种输入：重述要求、全量上下文及引用文件、plan＋已做＋待做、本文主包＋必要资料＋按需证据。接手者使用同一模型/设置、独立会话和同一初始工作副本，避免前一次试验修改文件影响后一次。旧 Agent 可写说明的情形作为后续补充，不是首轮依赖。

观察三件事：

1. **接续是否正确：**目标/约束是否对齐，首个动作是否合理，有无重做已完成内容、误当已验收、重复已知无效尝试或漏掉剩余范围。
2. **真实成本：**主包＋初始必读文件＋后续检索的总输入；整理本身的模型调用/人工时间；继续执行的时间、调用和用户纠正次数。单独缩小 facts 字段不算总成本下降。
3. **压缩在哪里失效：**若主包很小却迫使接手者全读原文，记录为延后成本；必要数据本身很大时报告可压缩与不可压缩部分，不硬凑比例。

首轮只判断该断点是否值得继续；不从一个样本宣称稳定节省比例或业务收益。达到有用的精简且未暴露关键遗漏即可停止继续压缩。后续再用缺资料、未提交修改、冲突要求与失败后重试的断点检查脆弱处。
