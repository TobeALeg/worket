# 无变化记录的后台扫描

2026-09-23，第 17 轮。先测量 RecordingCollection.collect：3 项各 2,000 条消息、30 次闲置检查，旧实现读取 90 个完整快照，重复尝试入队 180,000 条消息，中位每次 232.97 ms。

目标：无变化时仅核验生命周期、授权及本地追加位置；检查点跨重启保存。处理位置必须用本地 row_id，不能使用来源 sequence，因为来源可迟到或重用序号。新事件仍从档案投影当前关系，不削弱修订/缺失核验；已有 view 证明其消息分片已经排队，避免重复尝试。

数据流：sourceCheckpoint → 是否仍 OPEN/活动绑定/授权有效 → 比较 recording_checkpoints → 有变化时读取档案及旧 view → 排入新增消息分片 → 计算变化关系 → 同事务保存 outbox/view/checkpoint。只有无消息关系变化的工具事件时，单独推进检查点。远端 view 序号递增并覆盖消息序号；不把来源序号作为扫描游标。

验收：真实 Electron 和 HTTP 后台中无变化的 40 次同步不读取完整快照/不尝试重复入队/不新增上传；之后修订、消失、恢复仍正确。检查长消息部分排队、事务中断、重启、旧格式升级、迟到序号、停止/到期/删除。性能报告限于采集函数，不能表述为整体应用或模型节省。
