# 改进记录样本的有效原文视图

2026-09-23。原始消息长期留存用于追溯，不能因此把每次观察都视为独立、当前有效的要求。

## 协议和范围

RECORDING 范围的新上传使用 schemaVersion:2。用户消息、Agent 回复仍以 MESSAGE 分片保存，新增 RECORDING_VIEW 表达截至某个本地序号的全量有效性：每条已允许上传的消息只有内部 sourceEventId、CURRENT/SUPERSEDED/PENDING/ABSENT 状态及必要的 supersededBy。它不传原应用 ID、会话 ID、路径、工具输出、推理摘要或原始 metadata，也不读取额外正文。用途、90 天期限、显式记录触发和用户退出方式不变，仍使用既有记录授权。

后台能力 improvement.recordingViewSchemaVersions:[1] 表示支持此视图。客户端整份 RECORDING 队列发送前检查能力；不支持则保留队列、显示 COLLECTION_UPDATE_REQUIRED，不降级成语义残缺的消息上传。v2 请求本身也会被旧后台拒绝。后台兼容旧 v1 消息，但没有视图的样本标明有效性未知，不冒充当前原文。升级前已排队或已收到的 v1 消息可以与后续 v2 视图关联，无需改写原始事件。

## 投影规则

本地记录按不可变档案生成视图，同 ID 修订形成链接，缺失检查映射至可上传消息；工具/隐藏内容的链路完全排除。相同截止序号只排队一次，重复同步幂等。发送 MESSAGE 后排队完整视图，中间故障不会凭部分分片生成当前正文。

后台按 sourceEventId 合并分片。只有全部分片一致、视图覆盖全部已收到消息、引用目标存在且按递增观察序号修订、无待复核状态时，ready 才为 true，current 才有内容。乱序读取取最高截止序号；同序号冲突或额外未覆盖消息使视图待定。消息修订保留原会话位置，避免把早期用户要求排到较早的 Agent 回复后面。历史原文和原始上传事件不删除。

管理员先看当前有效原文，历史/缺失状态及原始上传证据按需展开。ready 仅证明已接收样本截至该同步点的结构完整，不能证明用户语义意图、上游实时状态或已确认 contract 被撤销。已停止的样本保留最后同步视图，并不继续追踪来源。

初版 1,000 事件限额及逐次完整视图的成本已在下一轮实测并优化：记录样本现在支持 v3 增量视图，并以 10,000 事件/20 MiB 双预算限制，90 天不变。详见 [长记录同步](recording-sample-scale.md)。
