# 未确认交接的恢复验收（2026-10-13）

用户批准修复：打开请求不能冒充草稿准备成功；等待接手时直接显示取消和重新打开。此轮不安装日常 App，不 push、merge 或 deploy。

## 行为与持久化

- Codex 适配器仅返回 `OPEN_REQUESTED`。打开请求返回后提示用户检查草稿、确认发送；不据此确认草稿出现、发送、绑定或读取。
- 未确认交付直接显示“重新打开”“取消未确认交接”，隐藏会产生第二次交付的“交接”主按钮。后台仍拦截重复调用。
- 新交付将最终 DeliveryRequest 保存在本地 `connector_reopen_requests`，按原提示 SHA256 校验。重新打开复用原 delivery ID、prompt、title、purpose，不新建工作包、执行片段或绑定，不自动发送。弹窗提示可能出现重复草稿，只发送一次。
- 请求持久化支持重启；完成绑定、取消或初次打开失败时清理重开内容；永久删除工作通过外键级联清理。既有摘要账本继续仅存 hash。旧版本交付没有原提示时不重建，明确提示确认未接手后取消再交接。
- 取消保留工作、消息和历史片段，恢复原来源；已取消标记不能绑定重试。重新打开失败保留原待确认状态。真实来源先确认、打开请求后报错时，不回滚已确认绑定。
- 详情区分等待用户发送与来源确认、已绑定但尚无读取回执、已绑定且工作包已读取。读取仍由本次 delivery 的 MCP 回执决定。
