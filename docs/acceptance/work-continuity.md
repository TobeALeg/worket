# 工作整理与接续验收（2026-09-23）

后续更新：用户已将整理确定为后台步骤，当前入口、265 项回归与本机更新状态见 [自动准备验收](automatic-work-preparation.md)。以下保留初次实现的实验与部署历史。

用户授权实施 [工作对象审视](../reviews/2026-09-23-work-object-audit.md) 的四步方案。本轮接通统一交付、托管整理、共享证据/状态出口，并比较固定断点的接手判断。未实现跨机器材料传输、同事/SaaS 接手或通用 Agent 调度。

## 实现

- AppService 生成最终 v3 启动指令；Codex、WorkBuddy、ZCode、Antigravity 适配器仅传输它。打开应用仍待真实会话绑定与对应读取回执。
- 进行中工作可“整理”，交接可选先整理。当前记录、状态线索及材料版本经已有 WorketAIClient/托管服务；不附带文件正文或事件元数据，不自动上传后续对话，不借用沉淀授权。
- workEvidence 统一来源修订、排除内部推理与本系统读取审计；外部消息 ID 映射到档案 ID。覆盖/摘录/用户来源校验共用。Worket 内逐项验收同事务写入带文件 ID/hash 的 work.acceptance 事件。
- ContinuationSnapshot 保存来源、状态和全部固定材料依据；来源、人工编辑、定义/技能/输入/参考/成果版本变化使快照失效。界面、工作包与 MCP 读取同一状态投影，原关键词线索保留为降级材料。详情目标和当前阶段也取自该快照。
- 去掉本地要求列表第 8 条截断，明确否定完成的表达不再成为完成声明。供应商 Key 环境变量不再触发桌面自动分析。

整理仍是一次最多 80,000 JSON 字符的调用；超限明确 PARTIAL，不自动分块扩大范围。结果结构/出处合法不等于语义正确，也不自动改变定义、发布版本或验收工作。

## 工程验证

完整测试 259/259；服务端独立构建通过。新增托管链路测试覆盖显式授权、归档期间禁止发送、界面/导出/MCP 一致、来源变化失效、被动读取无模型调用、读取审计不污染沉淀证据、服务器只保存操作元数据。既有 MCP 已为异步接口，修正两份旧测试缺少 await 的调用。

四个默认适配器通过实际 AppService 集成测试，操作系统打开/剪贴板使用替身。阶段回归 12 项通过，涉及范围替代、自报不升级验收、依赖环拒绝、超限、无权限、基础变化失效和历史快照保留；使用确定性适配器，无云端调用。

macOS arm64 打包应用使用独立临时数据库、合成记录和 mock keychain，实际点击整理、经过 HTTP 服务与认证 MCP。三个真实候选回放通过，448px 窗口无横向溢出、无 pageerror；本次 80 words 在当前阶段中直接显示。不覆盖用户已安装应用，不代表实际 Codex/WorkBuddy 业务交付通过。

## 真实模型与固定断点对照

使用后台当前配置的 deepseek-flash；供应商 Key 留在服务器。三个合成场景分别先通过真实桌面整理，再用相同接手提示词比较全聊天、未整理 v2 和整理后 v3。v2 是当前程序的未整理线索包基线，包含新增降级提示，不是整个旧版二进制。未调用外部 Agent 执行业务或访问用户真实工作。

| 场景 | 未整理 v2 接手判断 | 整理后 v3 接手判断 | 全聊天对照 |
| --- | --- | --- | --- |
| CSV 改 PDF，人民币保持 | CSV/PDF 并列，要求确认是否同时交付 | 交付 PDF，保留人民币，不再要求 CSV | 正确识别替代 |
| 清洗/图表检查通过，继续写报告 | 旧待办与完成声明冲突，先额外核验阶段 | 沿用 clean.csv/chart.svg 写报告，用户仍未验收 | 同样识别下一阶段 |
| 默认 50 words，本期 80，下期 50 | 本期限制未知，只保留 50 默认，要求确认 | 本期 80，未来 50，例外不推广 | 同样区分本次/未来 |

人工在本轮阅读这些固定响应进行上述定性判断；不是独立盲评、统计准确率或真实用户验收。阶段样本只有工具文本，没有真实输出文件 ID/hash；v3 正确保留了该缺口，不能把合成文本检查当成真实文件验收。

该成功运行共 12 次真实调用（3 次整理，9 次接手判断），供应商返回 53,428 tokens。短样本的 v3 输入为 6,248 / 8,862 / 5,134 字符，全聊天为 133 / 246 / 160 字符，不能主张压缩或总成本优势；v3 的价值在于显式状态及可追溯依据，本轮未测补读、人工纠正和真实交付耗时。

冻结输入、原始响应和报告在 [证据目录](work-continuity/)，主报告为 [report.json](work-continuity/report.json)。打包回放不新增模型调用。

## 保留的失败与修复

1. 第一轮验收脚本误读请求时间列 created_at（实际为 created），启动一次模型调用后中止；用量未知，不计为通过。
2. 初始提示词用字符串 “Claim” 代表对象，真实模型在多处返回字符串；来源校验拒绝。改成完整嵌套对象示例，没有降级为无来源摘要。
3. 后续候选在旧要求端放替代证据，在新要求端明确 supersedes 关系；原校验只接受新端证据，拒绝了有依据的关系。现接受关系任一端的有效引用，仍要求明确旧→新连接和逐字来源，回归覆盖旧端证据。

以上 [失败原件](work-continuity/failures/) 均保留。两次有完整响应的失败用量 4,094 与 4,523 tokens；全轮已知合计 62,045 tokens，另有第一次中断调用用量未知。没有暗中重试或把这些失败从试验记录中删除；金额未取得，tokens 不等于账单。

## 复现

```sh
npm test
npm run build:server
node scripts/qa-handoff-stages.mjs
npm run package:mac
WORKET_CONTINUITY_REPLAY=docs/acceptance/work-continuity \
WORKPET_EXECUTABLE_PATH="$PWD/release/Worket-darwin-arm64/Worket.app/Contents/MacOS/Worket" \
```

不设置 REPLAY 将进行最多 12 次合成真实模型调用，需要配置好的 jp-server；每次新运行保存独立目录，失败不自动重试。
