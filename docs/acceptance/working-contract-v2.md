# Working Contract 规则协调：实现与端到端验收

日期：2026-09-22。用户要求优先端到端验收。范围是 [方案](../specs/working-contract-evolution-v2.md) 中第一条通用链路，未启动自动增量学习、未修改正式 Gold。

## 已实现

模型声明重复时必须指向保留规则；程序检查关系、作用域、条件、循环及有效目标。执行包与已保存约定页面只展示有效规则，单次要求、未采纳建议与被替代要求留作候选/来源追溯。补充保持独立，实例覆盖单独保存，不改长期定义。验收通过引用保留规则实现，不需要重复维护正文。

FRAME.md 等已采用规范使用固定 hash 与条款行区间，底层保存不可变正文快照；执行包展开所选条款，不依赖接收 Agent 访问用户本机路径。参考文件、本次输入和未读取正文不能充当规范。文件改名不改变版本；用户主动采用新条款后形成新定义版本，关联关系须重新确认，旧实例保持原版。源文件不会被隐式修改。

## 端到端方法与结果

`scripts/qa-contract-e2e.mjs` 启动真实 Electron、独立 HTTP 服务与 SQLite 测试库，通过页面选择文件角色、提交、审阅、发布、新建实例与更新文件。真实模型使用服务器现有 `deepseek-flash` 配置；凭据留在服务器，只发送合成输入。每次运行最多两次模型调用，没有隐藏重试。这里只替换原生文件选择器的返回值，后续读文件、IPC、保存与导出都走产品代码。

| 场景 | 真实模型运行 | 最终客户端验证 | 结果 |
| --- | --- | --- | --- |
| 视频 | `2026-09-22T11-39-19-669Z`，2 次调用 | 同次完整桌面链路 | 通过 |
| 调研报告 | `2026-09-22T11-31-17-293Z`，2 次调用 | `2026-09-22T11-39-27-364Z` 回放原响应，补验最终 UI 和验收入口 | 通过 |
| 代码改动 | `2026-09-22T11-35-11-383Z`，2 次调用 | `2026-09-22T11-39-23-593Z` 回放原响应，核验最终 UI 和输入 | 通过 |

回放只复用完整原始模型响应，不修改结果；仍经过 HTTP、验证、持久化和桌面操作。它不算新的模型成功试验。报告和代码的真实运行早于最后一处“补充只表达新增信息”的提示修订，不能冒称三组均使用最终提示进行独立抽样。

| 标准 | 实际检查 |
| --- | --- |
| 跨对话/文件重复不堆入有效 contract | 有效规则与保存页只出现一次数值限制；复制到剪贴板的执行包仍只出现一次 |
| 新增要求不因去重丢失 | 保留视频口播同步、报告来源要求、代码回归测试要求 |
| 特殊要求不污染下一次 | 48 秒/页/行的单次要求不在有效规则及新实例执行包中 |
| 新工作只提供新的内容 | 三组均只有一个指定的必填输入，无旧值默认；创建全新实例 |
| 单次覆盖不改默认 | 本次 80 替代默认 50；此前默认实例仍为 50 |
| 改名、更新、删除的行为可预测 | 原件改名后版本相同；采用 30 后新实例使用 30、旧实例仍为 50；删除原件后仍可导出 |
| 依赖不可用不得假成功 | 删除固定快照后，实际复制入口返回 MATERIAL_MISSING；恢复测试快照后继续 |
| 去重不取消验收 | 合成附件 + NEEDS_REVISION 保持 OPEN；逐项 PASS 后变为 COMPLETED |

原始请求、响应、草稿、工作包、截图和失败 DOM 保存在本地 `output/contract-e2e/<run>/`。可提交的 [运行账本](working-contract-v2-results.json) 保留全部运行，不包含供应商密钥或真实用户对话。

## 发现并处理的问题

- 初始脚本把异步等待过早视为完成、另一次未等到 panel 窗口；已修正等待方式。这些是测试脚本失败，不能计为模型失败或忽略。
- 规则提示最初没有进入实际请求，真实端到端返回旧结构；已修复提示装配并增加回归检查。
- 去重后 acceptanceCriteria 为空触发旧发布门槛；已改为对有效规则的引用式验收，同时保持旧定义兼容。
- 代码场景返回了嵌在 basis 中的 document，系统拒绝该无效引用；同时暴露遗漏未来输入角色，已补强通用结构与输入语义提示。
- 视频复测把“英文”作为补充，但同时重述字数限制；已要求补充只保留新增信息。该次失败保留在账本。
- 为避免旧客户端把 INSTANCE 候选当通用要求，新协议显式协商；旧请求保持旧提示，新客户端在旧后台上提交前即失败并提示升级。

## 回归与可复现性

全项目测试 **149/149** 通过，原抽取评测测试 **34/34** 通过。新回归覆盖跨字段合并、独立补充、替代、范围不一致、循环/悬空目标、无正文或未采用文件、版本变更与过期预览、手改文本解除文件绑定、损坏快照、去重后的验收及新旧协议兼容。

运行：先 `npm run build`，再 `node --experimental-strip-types scripts/qa-contract-e2e.mjs`。`WORKET_E2E_SCENARIO` 可选 `video`、`report`、`code`；设置 `WORKET_E2E_REPLAY=output/contract-e2e/<真实运行>` 可仅回放。真实运行要求本机有现有 `jp-server` SSH 配置和读取容器配置的权限，不需要把模型 Key 配到客户端。

## 未证明的部分

这三组是为了检查机制而编写的合成输入，已用于调试，不是盲测集。没有以旧 S 轨道 Gold 宣称可复用定义准确率，也没有 A/B 测得重复率下降、审阅节时或返工收益。程序能保证模型声明的关系被正确执行，不能保证模型总能识别所有同义、范围和采纳变化；合并多个义务的长句、跨字段语义重复仍可能需要人工修改。

验收附件明确是 QA 假数据；自动点击确认只验证产品状态流转，不冒充用户验收。尚未用 contract + HyperFrames + 新脚本制作并由用户验收真实成片。规范更新仍是主动选择和审阅；不自动监视、语义吸收文件全部变化或写回原件。二进制资料仍须另行传递。现有跨版本候选编辑可用，但连续新交互自动形成增量提案未启用。
